5.What happens when you enter a URL into a browser?
When you enter a URL such as https://www.example.com into a browser, several steps happen before the webpage appears.

1. URL is parsed

The browser identifies components such as:

https://www.example.com/products?id=10
  │        │             │
scheme   hostname       path/query

Here:

https → protocol/scheme
www.example.com → hostname
/products → path
id=10 → query parameter
2. DNS resolution

The browser needs the server's IP address.

It checks available DNS information/caches first. If necessary, a DNS query resolves:

www.example.com
       ↓
   DNS lookup
       ↓
IP address

For example, conceptually:

example.com → 93.x.x.x

The actual IP depends on the domain and DNS configuration.

3. Connection is established

For HTTPS, the browser establishes a secure connection to the server.

Depending on the protocol:

HTTP/1.1 or HTTP/2: typically TCP connection → TLS handshake
HTTP/3: uses QUIC over UDP, with TLS integrated into the QUIC connection setup

For traditional HTTPS:

Browser
   ↓
TCP connection
   ↓
TLS handshake
   ↓
Encrypted connection

The TLS handshake establishes encryption and verifies the server's certificate.

4. HTTP request is sent

The browser sends an HTTP request, for example:

GET /products?id=10 HTTP/1.1
Host: www.example.com

The request travels through the network using the appropriate transport and Internet protocols.

5. Server processes the request

The request reaches the web server/application.

The server may:

Authenticate the user
Read cookies
Query a database
Call other services
Generate HTML
Return cached content

For example:

Browser
   ↓
Load Balancer
   ↓
Web/Application Server
   ↓
Database / Cache
6. Server sends an HTTP response

The server returns something such as:

HTTP/1.1 200 OK
Content-Type: text/html

along with the response body.

The response could contain:

HTML
CSS
JavaScript
Images
Fonts
Other resources
7. Browser parses and renders the page

The browser processes the HTML and builds the DOM (Document Object Model).

It then processes CSS and builds the CSSOM, combines them to determine what should be displayed, performs layout, and paints the page.

JavaScript can also execute and modify the DOM/CSSOM or make additional network requests.

HTML → DOM
CSS  → CSSOM
          ↓
    Render information
          ↓
       Layout
          ↓
        Paint
          ↓
      Display page
8. Additional resources are requested

The HTML may reference:

CSS
JavaScript
Images
Fonts
APIs

The browser makes additional requests for these resources, potentially using existing connections.

Overall flow
Enter URL
    ↓
Parse URL
    ↓
DNS resolution
    ↓
Establish connection
    ↓
TLS handshake (HTTPS)
    ↓
Send HTTP request
    ↓
Server processes request
    ↓
HTTP response
    ↓
Browser parses HTML/CSS/JS
    ↓
Layout + Paint
    ↓
Webpage displayed
Important interview nuance

A common simplified answer is:

URL → DNS → TCP → TLS → HTTP → Server → Response → Rendering

That's useful for an interview, but modern browsers can also use HTTP/3 over QUIC, so TCP is not mandatory for every HTTPS request.

Interview Takeaway

Entering a URL triggers a chain of operations: URL parsing → DNS resolution → connection establishment → TLS for HTTPS → HTTP request → server processing → HTTP response → browser parsing and rendering. Understanding this flow connects concepts from DNS, TCP/UDP, TLS, HTTP, operating systems, and browser architecture.
