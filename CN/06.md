6.What is TCP?
TCP (Transmission Control Protocol) is a connection-oriented transport-layer protocol that provides reliable, ordered, and error-checked delivery of data between applications over an IP network.

It is part of the TCP/IP protocol suite.

Why do we need TCP?

IP provides packet delivery between hosts, but IP itself does not guarantee that packets will:

Arrive
Arrive in order
Arrive only once
Be retransmitted if lost

TCP provides mechanisms to handle these concerns.

How TCP works

A simplified TCP communication looks like:

Client                          Server
  │                               │
  │──── SYN ─────────────────────→│
  │←─── SYN + ACK ────────────────│
  │──── ACK ─────────────────────→│
  │                               │
  │──── Data ────────────────────→│
  │←─── ACK ──────────────────────│
  │                               │

The first three messages establish the connection. This is called the TCP three-way handshake.

Important TCP features
1. Connection-oriented

TCP establishes a logical connection before transferring application data.

2. Reliable delivery

TCP uses sequence numbers, acknowledgments, retransmissions, and timers to recover from packet loss.

For example:

Sender:
Packet 1 → 2 → 3 → 4

Receiver:
ACK 1 → ACK 2 → ACK 4
                  ↑
             Packet 3 missing

TCP can detect the missing data and retransmit it.

3. Ordered delivery

Even if packets arrive out of order, TCP uses sequence numbers to reconstruct the original byte stream.

4. Flow control

TCP prevents a fast sender from overwhelming a slower receiver using a receive window.

5. Congestion control

TCP adjusts its sending behavior based on network congestion to avoid overwhelming the network.

TCP is a byte-stream protocol

An important interview point:

TCP provides a reliable ordered byte stream, not individual message boundaries.

If an application sends two separate writes, the receiver does not necessarily receive them as two corresponding messages. Applications that need message boundaries must implement them at a higher layer.

TCP vs UDP
Feature	TCP	UDP
Connection	Connection-oriented	Connectionless
Reliability	Built-in	No built-in reliability
Ordering	Yes	No guarantee
Retransmission	Yes	No built-in retransmission
Flow control	Yes	No
Congestion control	Yes	No TCP-style mechanism
Data model	Byte stream	Datagrams
Typical uses	HTTP/1.1, HTTP/2, SSH, databases	DNS, streaming/real-time applications, QUIC
Where TCP fits
Application
    ↓
TCP / UDP        ← Transport layer
    ↓
IP               ← Internet layer
    ↓
Ethernet/Wi-Fi   ← Link layer

For example, HTTP/1.1 and HTTP/2 commonly run over TCP, while HTTP/3 runs over QUIC, which uses UDP as its underlying transport.

Interview Takeaway

TCP is a connection-oriented transport protocol that provides reliable, ordered byte-stream delivery using mechanisms such as sequence numbers, acknowledgments, retransmission, flow control, and congestion control.
