7.What is UDP?
UDP (User Datagram Protocol) is a connectionless transport-layer protocol that sends independent datagrams between applications with minimal protocol overhead.

Unlike TCP, UDP does not inherently guarantee that data will be delivered, delivered in order, or retransmitted if lost.

How UDP works

A simplified flow is:

Application
    ↓
UDP datagram
    ↓
IP packet
    ↓
Network
    ↓
UDP
    ↓
Receiving application

There is no TCP-style three-way handshake before sending data.

Important features
1. Connectionless

UDP doesn't establish a connection before transmitting each datagram.

2. Low overhead

UDP has a small, simple header and does not provide TCP's connection management, acknowledgments, or retransmission mechanisms.

3. No guaranteed delivery

A datagram can be:

Lost
Duplicated
Delayed
Delivered out of order

UDP itself does not correct these problems.

4. Preserves message boundaries

Unlike TCP's byte stream, UDP sends datagrams. One send corresponds to one datagram at the UDP layer, subject to normal IP/network constraints.

5. Uses port numbers

UDP uses source and destination ports to deliver datagrams to the appropriate application.

Example

Suppose an application sends:

Datagram 1
Datagram 2
Datagram 3

The receiver could potentially receive:

Datagram 1
Datagram 3

with Datagram 2 lost. UDP itself does not automatically retransmit Datagram 2.

If an application requires reliability, ordering, or retransmission, it can implement those mechanisms at a higher layer—or use a protocol such as QUIC.

Where is UDP useful?

UDP is useful when low overhead, low latency, or application-controlled reliability is important.

Examples include:

DNS queries in common configurations
Real-time audio/video applications
Online gaming
Network discovery
QUIC, which is the transport foundation for HTTP/3

For real-time applications, waiting for retransmission of an old packet may sometimes be less useful than continuing with newer data.

UDP vs TCP
Feature	TCP	UDP
Connection	Connection-oriented	Connectionless
Reliability	Built-in	Not built-in
Ordering	Guaranteed	Not guaranteed
Retransmission	Built-in	Not built-in
Flow control	Yes	No TCP-style flow control
Congestion control	Yes	No TCP-style congestion control
Data model	Byte stream	Datagrams
Overhead	Higher	Lower
Typical use	HTTP/1.1, HTTP/2, SSH	DNS, real-time applications, QUIC
Important interview point

Don't say “UDP is always faster than TCP.” UDP has less protocol machinery, but actual application performance depends on the protocol, network conditions, implementation, and workload.

Interview Takeaway

UDP is a connectionless transport protocol that provides lightweight datagram delivery without built-in guarantees of reliability, ordering, or retransmission. It is useful when low overhead or application-controlled delivery behavior is important.
