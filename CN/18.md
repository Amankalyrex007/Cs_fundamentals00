# Q18. What Is an IP Address?

An **IP (Internet Protocol) address** is a logical address associated with a **network interface or network-layer endpoint** so that it can be identified and reached for communication over an IP network.

In simple terms:

> **An IP address helps identify where an IP packet is supposed to go and allows routers to forward that packet toward its destination.**

Think of an IP address like a **network address** rather than a permanent identity of a physical device.

For example:

```text
Client
  |
  | IP Packet
  | Source:      192.168.1.10
  | Destination: 142.250.183.14
  v
Router
  |
  v
Internet
  |
  v
Destination
```

---

# 1. Example of an IP Address

There are two major versions of IP used today.

### IPv4

```text
192.168.1.10
```

IPv4 addresses contain **32 bits**.

They are normally written as four decimal numbers separated by dots:

```text
192 . 168 . 1 . 10
```

Each part is called an **octet** and represents 8 bits.

```text
8 bits + 8 bits + 8 bits + 8 bits
      = 32 bits
```

---

### IPv6

Example:

```text
2001:db8:85a3::8a2e:370:7334
```

IPv6 addresses contain **128 bits**.

They are normally represented using hexadecimal notation separated by colons.

For example:

```text
2001:db8:85a3::8a2e:370:7334
```

The `::` is a shorthand notation for one or more groups of consecutive zeroes.

---

# 2. Why Is an IP Address Needed?

When one device communicates with another over an IP network, packets need addressing information so that routers can determine where to forward them.

For example:

```text
Client
  |
  | Network
  v
Router
  |
  | Internet
  v
Server
```

A packet might contain:

```text
Source IP:
192.168.1.10

Destination IP:
142.250.183.14
```

The **destination IP address** helps routers determine which next hop or interface should be used to move the packet toward the destination network.

---

# 3. IP Address in a Packet

A simplified IP packet can be visualized as:

```text
+--------------------------------------+
|              IP Header               |
|                                      |
| Source IP      → 192.168.1.10        |
| Destination IP → 142.250.183.14      |
| Other IP fields                      |
+--------------------------------------+
|              Payload                 |
|        TCP / UDP segment             |
+--------------------------------------+
```

The IP header contains addressing and control information needed for network-layer delivery.

The payload can contain:

```text
TCP segment
```

or:

```text
UDP datagram
```

depending on the transport protocol.

---

# 4. IP Address and Routing

Routers primarily make forwarding decisions using **IP-layer information**.

For example:

```text
Network A
192.168.1.0/24
       |
       v
    Router 1
       |
       v
    Router 2
       |
       v
Network B
142.250.183.0/24
```

A packet might start with:

```text
Source:
192.168.1.10

Destination:
142.250.183.14
```

The routers examine the destination IP and use their forwarding information to choose the next hop.

### Important distinction

**Routing** is about determining paths or maintaining routing information.

**Forwarding** is the actual per-packet action of sending a packet toward the selected next hop/interface.

---

# 5. IPv4 vs IPv6

There are two major versions of the Internet Protocol:

* **IPv4**
* **IPv6**

| Feature               | IPv4                            | IPv6                                    |
| --------------------- | ------------------------------- | --------------------------------------- |
| Address size          | **32 bits**                     | **128 bits**                            |
| Example               | `192.168.1.10`                  | `2001:db8::1`                           |
| Address space         | ~4.3 billion possible addresses | Extremely large address space           |
| Representation        | Decimal, dotted notation        | Hexadecimal, colon-separated            |
| Base header           | Variable length                 | Fixed 40-byte base header               |
| Broadcast             | Supported                       | No broadcast; multicast is used instead |
| Address configuration | DHCP, manual, etc.              | SLAAC, DHCPv6, manual, etc.             |

---

# 6. Why Was IPv6 Introduced?

IPv4 provides:

```text
2^32
```

possible address values.

That is approximately:

```text
4.29 billion
```

addresses.

Although techniques such as **NAT, private addressing, and address allocation strategies** helped extend the usable life of IPv4, the IPv4 address space is limited.

IPv6 uses:

```text
2^128
```

possible address values.

This provides an enormously larger address space.

Conceptually:

```text
IPv4
32 bits
   ↓
~4.3 billion addresses


IPv6
128 bits
   ↓
~3.4 × 10^38 addresses
```

So one major motivation for IPv6 was the need for a much larger address space.

---

# 7. IPv4 Address Structure

An IPv4 address contains 32 bits.

For example:

```text
192.168.1.10
```

can be represented as:

```text
11000000.10101000.00000001.00001010
```

That's:

```text
8 + 8 + 8 + 8 = 32 bits
```

The address is interpreted according to its **network prefix and host/interface portion**, as determined by subnetting/prefix length.

For example:

```text
192.168.1.10/24
```

means:

```text
Network prefix → first 24 bits
Host/interface portion → remaining 8 bits
```

The exact usable address range and special addresses depend on the subnet and context.

---

# 8. IPv6 Address Structure

IPv6 uses 128 bits.

A full IPv6 address contains eight groups of 16-bit hexadecimal values.

Example:

```text
2001:0db8:0000:0000:0000:8a2e:0370:7334
```

It can be shortened to:

```text
2001:db8::8a2e:370:7334
```

The `::` notation compresses consecutive zero groups.

### Important point

IPv6's colon-separated hexadecimal representation is simply a human-readable representation of its 128-bit address.

---

# 9. Public vs Private IP Addresses

IP addresses can also be discussed in terms of whether they are intended for use inside private networks or are globally routable.

---

## Private IP Address

A **private IPv4 address** is intended for use inside private networks such as:

* Home networks
* Office networks
* Enterprise LANs
* Internal cloud networks

The commonly used private IPv4 ranges are:

```text
10.0.0.0/8
```

```text
172.16.0.0/12
```

```text
192.168.0.0/16
```

For example:

```text
Laptop → 192.168.1.10
Phone  → 192.168.1.11
Router → 192.168.1.1
```

These addresses are **not globally routable across the public Internet**.

---

# 10. Example of a Home Network

A typical home network might look like:

```text
                    Internet
                       |
                       |
                Public IP
                       |
                  Home Router
                 192.168.1.1
                  /    |    \
                 /     |     \
                /      |      \
           Laptop    Phone    TV
        192.168.1.10  .11    .12
```

The devices use private IP addresses internally.

The router typically has a public-facing address on its Internet connection.

When an internal device accesses the Internet, the router may perform **NAT (Network Address Translation)**.

Conceptually:

```text
Private network
192.168.1.10
      |
      | NAT
      v
Public Internet
      |
Public IP of router
```

### Important point

Private IP addresses are not "fake" addresses.

They are valid IP addresses designed for private network use.

---

# 11. Public IP Address

A **public IP address** is an address that can be globally routed within the public Internet, subject to routing policy and other network controls.

It may be associated with:

* A router's Internet-facing interface
* A publicly reachable server
* A cloud service
* Another Internet-connected network interface

For example:

```text
Home Network
      |
      v
Router
      |
Public IP
      |
      v
Internet
```

A public IP does not automatically mean that a service is reachable from the Internet. Firewalls, NAT, routing, security groups, and application configuration can still prevent inbound access.

---

# 12. Static vs Dynamic IP

Another important distinction is whether an IP address is expected to remain stable.

---

## Static IP

A **static IP** is intended to remain unchanged for a particular assignment or configuration.

Useful when a service needs a stable address, such as:

* Servers
* Network infrastructure
* Some VPN endpoints
* Certain enterprise services

Example:

```text
Server
   |
   +── 203.0.113.10
```

Clients can consistently reach the service using the same address, assuming routing and service configuration remain valid.

---

## Dynamic IP

A **dynamic IP** can change over time.

In IPv4 networks, addresses are commonly assigned dynamically using **DHCP**.

For example:

```text
Laptop
   |
   | DHCP
   v
DHCP Server
   |
   | 192.168.1.10
   v
Laptop
```

Later, the laptop may receive a different address depending on the network's address-allocation policy.

---

# 13. DHCP and IP Address Assignment

A common misconception is that every IP address must be manually configured.

In many networks, IPv4 addresses are assigned automatically using **DHCP**.

A simplified DHCP process is often remembered as:

```text
DORA

Discover
   ↓
Offer
   ↓
Request
   ↓
ACK
```

Conceptually:

```text
Client
  |
  | DHCP Discover
  v
DHCP Server
  |
  | DHCP Offer
  v
Client
  |
  | DHCP Request
  v
DHCP Server
  |
  | DHCP ACK
  v
Client receives configuration
```

The configuration can include:

* IP address
* Subnet mask/prefix information
* Default gateway
* DNS server information

# 14. IP Address vs MAC Address

This is one of the most common Computer Networks interview questions.

| Feature          | IP Address                        | MAC Address                                                     |
| ---------------- | --------------------------------- | --------------------------------------------------------------- |
| Layer            | Network layer                     | Link layer                                                      |
| Main purpose     | Logical addressing and routing    | Local-link delivery                                             |
| Scope            | Can work across multiple networks | Primarily local network/link                                    |
| Example IPv4     | `192.168.1.10`                    | `00:1A:2B:3C:4D:5E`                                             |
| IPv4 size        | 32 bits                           | Common Ethernet MAC = 48 bits                                   |
| IPv6 size        | 128 bits                          | Common Ethernet MAC = 48 bits                                   |
| Can change?      | Yes                               | Interface MAC can also be changed/spoofed                       |
| Used by routers? | Yes, for IP forwarding decisions  | Router does not route using an Ethernet MAC across the Internet |
| Address type     | Logical/network-layer             | Link-layer/interface identifier                                 |

---

# 15. IP vs MAC — Simple Example

Suppose:

```text
Laptop
IP: 192.168.1.10
MAC: AA:BB:CC:DD:EE:01
```

and:

```text
Router
IP: 192.168.1.1
MAC: AA:BB:CC:DD:EE:02
```

The laptop wants to send traffic outside its local network.

The IP packet may look conceptually like:

```text
IP Packet
+--------------------------------+
| Source IP:      192.168.1.10   |
| Destination IP: 142.250.183.14 |
+--------------------------------+
```

But on the local Ethernet/Wi-Fi link, the packet is carried inside a frame:

```text
Ethernet/Wi-Fi Frame
+--------------------------------+
| Source MAC:      Laptop MAC    |
| Destination MAC: Router MAC    |
+--------------------------------+
| IP Packet                      |
+--------------------------------+
```

So:

```text
IP address
→ Helps with network-layer routing

MAC address
→ Helps with local-link delivery
```

# 16. What Happens at a Router?

This is an important practical distinction.

Suppose:

```text
Laptop
192.168.1.10
    |
    v
Router
    |
    v
Internet
    |
    v
Server
142.250.183.14
```

The laptop sends an IP packet:

```text
Source IP:
192.168.1.10

Destination IP:
142.250.183.14
```

The local Ethernet/Wi-Fi frame has a destination MAC corresponding to the **next hop**, often the local router.

When the router forwards the packet onto another link, the outgoing link-layer frame normally uses different link-layer addresses.

Conceptually:

```text
Laptop → Router

Frame:
Laptop MAC → Router MAC
        |
        v
    IP Packet
    192.168.1.10
        ↓
    142.250.183.14
```

Then:

```text
Router → Next Hop

Frame:
Router's outgoing MAC → Next-hop MAC
        |
        v
    Same IP destination
```

The exact IP fields can also be modified by mechanisms such as NAT, but the key point is:

> **Link-layer addressing is hop-local, while IP addressing provides end-to-end network-layer addressing semantics.**

---

# 17. An IP Address Does Not Permanently Identify a Physical Device

This is a very important distinction.

An IP address identifies a **network-layer address/interface assignment**, not necessarily a permanent physical device.

For example:

```text
Home Wi-Fi

Laptop
   ↓
192.168.1.10
```

The same laptop connects to another network:

```text
College Wi-Fi

Laptop
   ↓
10.20.5.37
```

The physical laptop is the same, but its IP address changed.

Similarly, one physical device can have:

* Multiple network interfaces
* Multiple IP addresses
* IPv4 and IPv6 addresses simultaneously

For example:

```text
Laptop
   |
   +── Wi-Fi interface
   |      ├── IPv4
   |      └── IPv6
   |
   +── Ethernet interface
          ├── IPv4
          └── IPv6
```

Therefore, saying:

> "An IP address is the permanent address of a device"

is inaccurate.

---

# 18. Network Interface vs Device

A more precise way to think about IP addressing is:

```text
Physical Device
       |
       +── Network Interface
       |       |
       |       +── IP address
       |
       +── Another Network Interface
               |
               +── IP address
```

For example, a laptop could have:

```text
Wi-Fi interface
    ↓
192.168.1.10

Ethernet interface
    ↓
192.168.1.20
```

The IP addresses are associated with interfaces/configurations rather than being an immutable identity of the laptop itself.

# 19. IP Address in the Protocol Stack

A simplified network stack looks like:

```text
Application
    ↓
TCP / UDP
    ↓
IP Address       ← Network Layer
    ↓
MAC Address      ← Link Layer
    ↓
Physical Network
```

For example, when accessing a web server:

```text
HTTP
 ↓
TCP
 ↓
IP
 ↓
Ethernet / Wi-Fi
 ↓
Physical medium
```

Each layer has a different responsibility.

# 22. Important Interview Distinction: IP vs MAC

A useful interview answer is:

> **An IP address provides logical network-layer addressing used for routing packets between networks, while a MAC address is a link-layer address used primarily for delivery over a local network link.**

Example:

```text
IP:
192.168.1.10
      ↓
Where is the network-layer destination?


MAC:
AA:BB:CC:DD:EE:01
      ↓
Which interface is the local-link destination?
```

The exact behavior depends on the link technology, but this distinction is fundamental.

# 23. Common Interview Mistakes

### Mistake 1: "IP address uniquely identifies a physical device."

❌ Not necessarily.

An IP address is associated with a network interface/address assignment and can change.

---

### Mistake 2: "MAC address is always permanent."

❌ Too absolute.

A MAC address is associated with a network interface, but it can often be changed or spoofed through software/configuration.

---

### Mistake 3: "Private IP addresses can never communicate with the Internet."

❌ Incorrect.

A private-addressed device can communicate with Internet hosts through mechanisms such as **NAT** at a gateway.

The private address itself is not globally routable.

---

### Mistake 4: "Public IP means the device is accessible from anywhere."

❌ Incorrect.

Firewalls, NAT, routing policies, security groups, and service configuration can prevent inbound connectivity.

---

### Mistake 5: "IPv6 is just IPv4 with more addresses."

Too simplistic.

IPv6 also changes several protocol details, including:

* Addressing model
* Header structure
* Neighbor Discovery
* Autoconfiguration mechanisms
* Multicast usage
* Fragmentation behavior

The larger address space is one of its most important motivations, but not its only difference.

---

### Mistake 6: "Every device has exactly one IP address."

❌ Incorrect.

A device can have multiple interfaces and multiple addresses, including multiple IPv4/IPv6 addresses.

# 26. Interview Takeaway

> **An IP address is a logical network-layer address associated with a network interface or endpoint and used for addressing and routing IP packets. IPv4 uses 32-bit addresses, while IPv6 uses 128-bit addresses. An IP address is not necessarily a permanent identity of a physical device because addresses can change, and a device can have multiple interfaces and addresses.**

### ⭐ One-Line Interview Answer

**An IP address is a logical network-layer address used to identify an interface/endpoint and route IP packets across networks; IPv4 uses 32 bits, while IPv6 uses 128 bits.**

### ⭐ Most Important Distinction

```text
IP Address
   ↓
Logical / Network Layer
   ↓
Routing across networks

   ↓

   ↓
```
