# Q24. What is a Subnet?

A **subnet (subnetwork)** is a **logical subdivision of an IP network into smaller networks**.

Subnetting allows a large IP network to be divided into smaller, more manageable networks for:

* Efficient IP address allocation
* Better network organization
* Routing
* Traffic management
* Network segmentation
* Administrative control
* Potential isolation when combined with routing/firewall policies

In simple words:

> **Subnetting means taking one larger IP network and dividing its address space into smaller logical networks.**

---

# 1. Simple Example

Suppose we have:

```text
192.168.1.0/24
```

A `/24` IPv4 network contains:

```text
2^(32 - 24) = 2^8 = 256 addresses
```

We can divide this network into two equal `/25` subnets:

```text
192.168.1.0/24
        |
        +-------------------------+
        |                         |
        v                         v
192.168.1.0/25             192.168.1.128/25
```

Each `/25` contains:

```text
2^(32 - 25)
= 2^7
= 128 addresses
```

So:

```text
Original:

192.168.1.0/24
256 addresses

       ↓ subnetting

192.168.1.0/25
128 addresses

192.168.1.128/25
128 addresses
```

The total remains:

```text
128 + 128 = 256 addresses
```

Subnetting does not create additional IP addresses. It **reorganizes an existing address space into smaller prefixes**.

---

# 2. What Does `/24` Mean?

The `/24` is called the **prefix length** and is part of **CIDR (Classless Inter-Domain Routing) notation**.

An IPv4 address contains:

```text
32 bits
```

For:

```text
192.168.1.0/24
```

we have:

```text
/24
 ↓
24 bits = Network Prefix
 8 bits = Host Portion
```

Conceptually:

```text
Network Portion                  Host Portion
<------------------------>       <-------->
11111111.11111111.11111111.     00000000
       24 bits                       8 bits
```

Therefore:

```text
192.168.1.0/24
```

means the first **24 bits** represent the network prefix, while the remaining **8 bits** provide addresses within that network.

---

# 3. Subnet Mask for `/24`

The equivalent subnet mask is:

```text
255.255.255.0
```

In binary:

```text
11111111.11111111.11111111.00000000
```

The `1`s represent the network portion:

```text
11111111.11111111.11111111
```

and the `0`s represent the host portion:

```text
00000000
```

Therefore:

```text
/24
=
255.255.255.0
```

---

# 4. Understanding an IPv4 Subnet

Consider:

```text
192.168.1.0/24
```

Its traditional IPv4 layout is:

```text
Network Address
      |
      v
192.168.1.0
      |
      +---- 192.168.1.1
      |
      +---- 192.168.1.2
      |
      +---- ...
      |
      +---- 192.168.1.254
      |
      v
Broadcast Address
192.168.1.255
```

So:

| Address Type                  | Address         |
| ----------------------------- | --------------- |
| Network address               | `192.168.1.0`   |
| First traditional usable host | `192.168.1.1`   |
| Last traditional usable host  | `192.168.1.254` |
| Broadcast address             | `192.168.1.255` |

---

# 5. Network Address

The **network address** identifies the subnet itself.

For:

```text
192.168.1.0/24
```

the network address is:

```text
192.168.1.0
```

It represents the entire subnet rather than an ordinary host.

Conceptually:

```text
192.168.1.0/24
      |
      +---- Network identity
      |
      +---- Hosts
      |
      +---- Broadcast
```

---

# 6. Host Addresses

The host portion identifies individual addresses within the subnet.

For:

```text
192.168.1.0/24
```

the host portion contains:

```text
8 bits
```

Therefore:

```text
2^8 = 256
```

total IPv4 addresses exist in the subnet.

Traditionally, the first address is the network address and the last is the broadcast address.

So the traditional usable host range is:

```text
192.168.1.1
       ↓
192.168.1.254
```

That gives:

```text
256 - 2 = 254
```

usable host addresses.

---

# 7. Broadcast Address

The **broadcast address** is used in IPv4 to represent all hosts on the local subnet.

For:

```text
192.168.1.0/24
```

the broadcast address is:

```text
192.168.1.255
```

Conceptually:

```text
192.168.1.255
      |
      +---- Send to all hosts in this IPv4 subnet
```

So:

```text
Network:
192.168.1.0

Hosts:
192.168.1.1 – 192.168.1.254

Broadcast:
192.168.1.255
```

> **Important:** The traditional `usable hosts = total addresses - 2` rule applies to ordinary IPv4 subnets where network and broadcast addresses have the usual meanings. Special-purpose prefixes such as `/31` and `/32` have different rules.

---

# 8. Why Use Subnets?

Subnetting is useful for several reasons.

## 8.1 Efficient IP Allocation

Suppose a company has:

```text
Engineering → 50 hosts
HR          → 20 hosts
Finance     → 10 hosts
```

Giving the entire company a huge network may waste address space.

Instead, appropriately sized subnets can be allocated.

For example:

```text
Company Network
      |
      +---- Engineering
      |
      +---- HR
      |
      +---- Finance
```

This makes address allocation more efficient.

---

# 9. Network Organization

Subnets can organize a larger network into logical groups.

For example:

```text
Company Network
       |
       +--------------------+
       |         |          |
       v         v          v
Engineering     HR       Finance
 Subnet       Subnet      Subnet
```

A larger organization may have:

```text
Company Network
│
├── Engineering subnet
├── HR subnet
├── Finance subnet
├── Sales subnet
└── Guest subnet
```

Each subnet can have its own IP range and routing policies.

---

# 10. Routing

Subnet prefixes are extremely important for routing.

Suppose a router knows:

```text
10.10.10.0/24 → Interface A
10.10.20.0/24 → Interface B
```

If a packet is destined for:

```text
10.10.20.50
```

the router can determine that the destination belongs to:

```text
10.10.20.0/24
```

and forward it toward Interface B.

Conceptually:

```text
             Router
            /      \
           /        \
          v          v
10.10.10.0/24    10.10.20.0/24
   Network A        Network B
```

Therefore, subnetting and routing are closely connected.

---

# 11. Subnetting and Isolation

Different subnets can also be used for segmentation.

For example:

```text
Company Network
       |
       +---- Employees
       |
       +---- Servers
       |
       +---- Guests
```

A firewall can enforce policies such as:

```text
Employees → Servers     ALLOW
Guests    → Servers     DENY
Guests    → Internet    ALLOW
```

However, an important interview point is:

> **Being in different subnets does not automatically provide security isolation.**

Different subnets can communicate if routing permits it.

Actual isolation may require:

* Routers
* ACLs
* Firewalls
* VLAN configuration
* Security policies

So:

```text
Different subnet
      ≠
Automatically secure
```

---

# 12. Subnet vs IP Address

An **IP address** identifies an address/interface endpoint.

A **subnet** identifies a network prefix/address range.

For example:

```text
IP Address:
192.168.1.25

Subnet:
192.168.1.0/24
```

The subnet tells us which portion of the IP address represents the network.

Conceptually:

```text
192.168.1.25/24

Network portion       Host portion
<---------------->    <-------->
192.168.1             25
```

So:

```text
IP address
→ identifies a particular address/interface

Subnet
→ identifies the network/prefix containing addresses
```

# 13. Subnetting Example: Divide `/24` into Two `/25`s

Start with:

```text
192.168.1.0/24
```

There are:

```text
8 host bits
```

If we borrow one host bit for subnetting:

```text
/24 → /25
```

we now have:

```text
25 network/prefix bits
7 host bits
```

Number of subnets:

```text
2^1 = 2
```

Addresses per subnet:

```text
2^7 = 128
```

The resulting subnets are:

```text
192.168.1.0/25
192.168.1.128/25
```

### First subnet

```text
192.168.1.0/25
```

Range:

```text
Network:   192.168.1.0
Hosts:     192.168.1.1 – 192.168.1.126
Broadcast: 192.168.1.127
```

### Second subnet

```text
192.168.1.128/25
```

Range:

```text
Network:   192.168.1.128
Hosts:     192.168.1.129 – 192.168.1.254
Broadcast: 192.168.1.255
```

Visualization:

```text
192.168.1.0/24
│
├── 192.168.1.0/25
│   ├── Network:   .0
│   ├── Hosts:     .1 – .126
│   └── Broadcast: .127
│
└── 192.168.1.128/25
    ├── Network:   .128
    ├── Hosts:     .129 – .254
    └── Broadcast: .255
```

# 14. Subnetting Example: Divide `/24` into Four Equal Subnets

Suppose:

```text
192.168.1.0/24
```

needs to be divided into **four equal subnets**.

We need:

```text
2^2 = 4
```

subnets.

Therefore, we borrow **2 host bits**:

```text
/24 → /26
```

Now:

```text
Network bits = 26
Host bits    = 6
```

Number of addresses per subnet:

```text
2^6 = 64
```

Therefore, the four subnets are:

```text
192.168.1.0/26
192.168.1.64/26
192.168.1.128/26
192.168.1.192/26
```

---

# 15. `/26` Subnet Details

Each `/26` contains:

```text
2^(32 - 26)
= 2^6
= 64 addresses
```

Traditionally:

```text
64 - 2 = 62 usable host addresses
```

### Subnet 1

```text
192.168.1.0/26

Network:   192.168.1.0
Hosts:     192.168.1.1 – 192.168.1.62
Broadcast: 192.168.1.63
```

### Subnet 2

```text
192.168.1.64/26

Network:   192.168.1.64
Hosts:     192.168.1.65 – 192.168.1.126
Broadcast: 192.168.1.127
```

### Subnet 3

```text
192.168.1.128/26

Network:   192.168.1.128
Hosts:     192.168.1.129 – 192.168.1.190
Broadcast: 192.168.1.191
```

### Subnet 4

```text
192.168.1.192/26

Network:   192.168.1.192
Hosts:     192.168.1.193 – 192.168.1.254
Broadcast: 192.168.1.255
```

Visualization:

```text
192.168.1.0/24
│
├── /26 → .0   – .63
│
├── /26 → .64  – .127
│
├── /26 → .128 – .191
│
└── /26 → .192 – .255
```

# 16. How to Calculate Number of Addresses

For an IPv4 subnet:

```text
Total addresses = 2^(32 - prefix length)
```

Examples:

| CIDR  | Host Bits | Total Addresses | Traditional Usable Hosts |
| ----- | --------: | --------------: | -----------------------: |
| `/24` |         8 |             256 |                      254 |
| `/25` |         7 |             128 |                      126 |
| `/26` |         6 |              64 |                       62 |
| `/27` |         5 |              32 |                       30 |
| `/28` |         4 |              16 |                       14 |
| `/29` |         3 |               8 |                        6 |
| `/30` |         2 |               4 |                        2 |

The traditional formula is:

```text
Usable hosts = 2^(32 - prefix) - 2
```

for ordinary IPv4 subnets where the network and broadcast addresses are reserved.

---

# 17. Prefix Length and Host Capacity

There is an important trade-off:

```text
Larger prefix length
        ↓
More network bits
        ↓
Fewer host bits
        ↓
Fewer addresses per subnet
```

For example:

```text
/24 → 256 addresses

/25 → 128 addresses

/26 → 64 addresses

/27 → 32 addresses
```

Therefore:

```text
Prefix length ↑
Host capacity ↓
```

Conversely:

```text
Prefix length ↓
Host capacity ↑
```

# 19. Finding the Subnet of an IP Address

Suppose we have:

```text
IP:
192.168.1.75/26
```

A `/26` has blocks of:

```text
64 addresses
```

So the subnet boundaries are:

```text
0
64
128
192
```

`75` lies between:

```text
64 and 127
```

Therefore:

```text
Subnet:
192.168.1.64/26
```

Its range is:

```text
Network:   192.168.1.64
Hosts:     192.168.1.65 – 192.168.1.126
Broadcast: 192.168.1.127
```

So:

```text
192.168.1.75/26
        ↓
192.168.1.64/26
```

This type of calculation is frequently asked in networking interviews.

# 20. Subnetting and CIDR

Modern IP networks use **CIDR notation** rather than relying only on old class-based addressing.

For example:

```text
192.168.1.0/24
10.0.0.0/16
172.16.10.0/24
```

The `/number` tells us how many leading bits belong to the network prefix.

Examples:

```text
/16 → 16 network bits
/20 → 20 network bits
/24 → 24 network bits
/26 → 26 network bits
```

CIDR makes IP allocation more flexible.

---

# 21. Subnetting vs Supernetting

Subnetting divides a larger network into smaller networks:

```text
Large Network
     ↓
Smaller Networks
```

Supernetting combines multiple contiguous networks into a larger summarized prefix:

```text
Multiple Networks
       ↓
Larger Summary Prefix
```

This distinction becomes important in routing.

For example, a router may advertise a summarized route rather than maintaining separate routes for every smaller network.

---

# 22. Subnetting and Route Summarization

Suppose a router has:

```text
10.10.0.0/24
10.10.1.0/24
10.10.2.0/24
10.10.3.0/24
```

Depending on alignment and routing design, these can be summarized as:

```text
10.10.0.0/22
```

This reduces the number of routing entries that another router may need to maintain.

So subnetting and CIDR also play an important role in scalable routing.

---

# 23. Subnetting and VLSM

In real networks, subnets do not always need to be equal-sized.

This is where **VLSM (Variable Length Subnet Masking)** becomes useful.

Suppose:

```text
Engineering → 100 hosts
HR          → 30 hosts
Finance     → 10 hosts
```

Instead of giving every department the same-sized subnet, we can allocate different prefix lengths according to requirements.

Conceptually:

```text
Company Address Space
       |
       +---- Engineering → Larger subnet
       |
       +---- HR          → Medium subnet
       |
       +---- Finance     → Smaller subnet
```

This helps avoid unnecessary address waste.

---

# 24. Subnet vs VLAN

These concepts are related but not identical.

### Subnet

A logical IP network/prefix.

```text
192.168.10.0/24
```

### VLAN

A Layer-2 logical broadcast domain.

For example:

```text
VLAN 10 → Employees
VLAN 20 → Guests
```

A common enterprise design is:

```text
VLAN 10
   ↕
192.168.10.0/24

VLAN 20
   ↕
192.168.20.0/24
```

But:

> **VLAN and subnet are not the same thing.**

Routing is typically required for communication between different IP subnets.

# 25. Common Interview Mistakes

### Mistake 1: "`/24` means 24 hosts."

❌ Incorrect.

`/24` means:

```text
24 network/prefix bits
```

It leaves:

```text
8 host bits
```

and therefore:

```text
2^8 = 256 addresses
```

---

### Mistake 2: "A `/24` has 254 total addresses."

❌ Incorrect.

It has:

```text
256 total addresses
```

Traditionally:

```text
254 usable host addresses
```

because network and broadcast addresses are reserved.

---

### Mistake 3: "Different subnets cannot communicate."

❌ Incorrect.

They can communicate through routing when appropriate routes and policies exist.

```text
Subnet A
   |
 Router
   |
Subnet B
```

---

### Mistake 4: "Different subnets automatically provide security."

❌ Incorrect.

Routing and firewall/ACL policies determine whether communication is allowed.

---

### Mistake 5: "Subnet mask and IP address are the same."

❌ Incorrect.

For example:

```text
IP:
192.168.1.25

Subnet mask:
255.255.255.0
```

They have different purposes.

---

### Mistake 6: "Subnetting creates more IP addresses."

❌ Incorrect.

Subnetting divides an existing address space into smaller prefixes.

The total address space remains the same.

```text
256 addresses
     ↓
128 + 128

Still:
256 total addresses
```

---

### Mistake 7: "Every subnet always has exactly two reserved addresses."

This is a useful traditional IPv4 rule for ordinary subnets, but it has exceptions.

For example:

```text
/31
```

is commonly used for point-to-point links and does not follow the ordinary `-2` host calculation.

Similarly:

```text
/32
```

represents a single IPv4 address.

So always consider the context.

# 27. Important Formulas

For IPv4:

### Total addresses

```text
2^(32 - prefix length)
```

Example:

```text
/26

2^(32 - 26)
= 2^6
= 64
```

### Traditional usable hosts

```text
2^(32 - prefix length) - 2
```

Example:

```text
/26

64 - 2
= 62
```

### Number of equal subnets

If you borrow `n` host bits:

```text
Number of subnets = 2^n
```

Example:

```text
/24 → /26

Borrowed bits = 2

2² = 4 subnets
```

# 28. Memory Trick

Remember:

> **CIDR prefix = Network bits.**

So:

```text
/24
↓
24 network bits
↓
8 host bits
↓
2^8 = 256 addresses
```

And:

```text
Prefix ↑
   ↓
Host bits ↓
   ↓
Addresses/subnet ↓
```

For example:

```text
/24 → 256 addresses
/25 → 128
/26 → 64
/27 → 32
```

# 29. Interview Takeaway

> **A subnet is a logical subdivision of an IP network. Subnetting divides an address space into smaller network prefixes, improving IP address allocation, routing, organization, and potentially network segmentation. CIDR notation such as `/24` specifies how many leading bits represent the network prefix.**

### ⭐ One-Line Interview Answer

**A subnet is a logical subdivision of an IP network into smaller network prefixes, allowing efficient addressing, routing, organization, and segmentation.**

```text
Original Network:

192.168.1.0/24
        |
        | Borrow 2 host bits
        ↓
      /26
        |
        +── 192.168.1.0/26
        |
        +── 192.168.1.64/26
        |
        +── 192.168.1.128/26
        |

```

Each subnet:

```text
64 total addresses

```

The core idea is:

```text
Large IP Network
       ↓
   Subnetting
       ↓
Smaller IP Networks
       ↓
Better allocation + organization + routing
```
