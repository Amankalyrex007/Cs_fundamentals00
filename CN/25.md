# Q25. What is a Router?

A **router** is a networking device that **forwards IP packets between different networks based on their destination IP addresses**.

In simple terms:

> **A router decides where an IP packet should go next.**

Routers are primarily associated with **Layer 3 (Network layer)** functionality because they make forwarding decisions using IP addressing.

---

# 1. Simple Example

Imagine a typical home network:

```text
             Home Network
                 
Laptop ─┐
Phone  ─┼──→ Router ───→ Internet
TV     ─┘
```

The router connects the local network to other networks, such as:

* ISP network
* Internet
* Another internal network
* Cloud/network infrastructure

For example:

```text
Source IP:      192.168.1.10
Destination IP: 142.250.x.x

       ↓

     Router

       ↓

    Internet
```

The router examines the **destination IP address** and uses its **routing table** to determine where the packet should be forwarded next.

---

# 2. What Does a Router Actually Do?

A router primarily performs **packet forwarding**.

Suppose a router receives an IP packet:

```text
Destination:
10.20.30.40
```

The router roughly performs:

```text
1. Receive packet
       ↓
2. Read destination IP
       ↓
3. Look up routing table
       ↓
4. Select best matching route
       ↓
5. Determine next hop/interface
       ↓
6. Forward packet
```

The important idea is:

```text
Destination IP
      ↓
Routing Table
      ↓
Best Route
      ↓
Next Hop / Interface
      ↓
Forward Packet
```

---

# 3. What Is a Routing Table?

A **routing table** contains information about which destinations are reachable through which interfaces or next hops.

A simplified routing table might look like:

| Destination      | Next Hop / Interface |
| ---------------- | -------------------- |
| `10.20.0.0/16`   | Interface A          |
| `192.168.1.0/24` | Interface B          |
| `172.16.0.0/16`  | Interface C          |
| `0.0.0.0/0`      | ISP Gateway          |

Suppose the router receives a packet destined for:

```text
10.20.30.40
```

The destination belongs to:

```text
10.20.0.0/16
```

so the router can forward it through:

```text
Interface A
```

---

# 4. Default Route

What happens if the routing table does not contain a more specific route?

The router may use the **default route**.

For IPv4, the default route is:

```text
0.0.0.0/0
```

It essentially means:

> "For destinations for which I do not have a more specific route, use this next hop."

For a home router, this is commonly the ISP-facing path.

Conceptually:

```text
Destination:
142.250.x.x

No specific matching route
        ↓
Default Route
0.0.0.0/0
        ↓
ISP Gateway
        ↓
Internet
```

---

# 5. Longest Prefix Match

A router does not simply choose the first matching route.

When multiple routes match a destination, IP routing generally uses **longest-prefix matching**.

Consider:

```text
10.0.0.0/8
10.20.0.0/16
10.20.30.0/24
```

Suppose the destination is:

```text
10.20.30.40
```

All three prefixes can potentially match:

```text
10.0.0.0/8
      ↓
10.20.0.0/16
      ↓
10.20.30.0/24
```

The most specific route is:

```text
10.20.30.0/24
```

because `/24` has more matching prefix bits than `/16` or `/8`.

So the router chooses:

```text
/24
```

This is called:

> **Longest Prefix Match (LPM)**

It is an important concept in IP routing.

---

# 6. Router Forwarding Example

Suppose we have:

```text
             Router
          /     |      \
         /      |       \
        v       v        v
     Network A Network B Network C
```

Routing table:

```text
Destination       Interface
────────────────────────────
192.168.1.0/24    LAN
10.0.0.0/8        Interface A
172.16.0.0/16     Interface B
0.0.0.0/0         ISP
```

Now a packet arrives:

```text
Destination:
172.16.5.20
```

The router checks its table:

```text
172.16.0.0/16
```

matches the destination.

Therefore:

```text
Packet
  ↓
Router
  ↓
172.16.0.0/16 route
  ↓
Interface B
```

---

# 7. Routers Work Hop by Hop

A router usually does **not** know the entire physical path that a packet will travel across the Internet.

Instead, each router makes its own forwarding decision.

For example:

```text
Host A
  |
  v
Router 1
  |
  v
Router 2
  |
  v
Router 3
  |
  v
Server
```

The process is approximately:

```text
Host A
  ↓
Router 1
  ↓
Router 2
  ↓
Router 3
  ↓
Server
```

Each router examines the destination IP and decides:

> "Where should I send this packet next?"

This is why routing is fundamentally **hop-by-hop forwarding**.

---

# 8. Routing vs Forwarding

These two terms are often confused.

### Routing

**Routing** is the process of determining paths/reachability information.

It may involve:

* Static routes
* OSPF
* BGP
* IS-IS
* RIP
* Other routing mechanisms

Conceptually:

```text
Network Information
        ↓
Routing Process
        ↓
Routing Table
```

### Forwarding

**Forwarding** is the actual process of taking an arriving packet and sending it toward the selected next hop/interface.

```text
Packet arrives
      ↓
Lookup destination
      ↓
Forwarding decision
      ↓
Outgoing interface
      ↓
Packet transmitted
```

A useful distinction:

> **Routing builds or determines forwarding information; forwarding uses that information to move packets.**

---

# 9. Router vs Switch

This is one of the most common networking interview questions.

| Router                         | Switch                                  |
| ------------------------------ | --------------------------------------- |
| Primarily Layer 3              | Primarily Layer 2                       |
| Forwards IP packets            | Forwards Ethernet frames                |
| Uses destination IP            | Uses destination MAC                    |
| Uses routing/forwarding tables | Uses MAC address table                  |
| Connects different IP networks | Connects devices within a LAN/VLAN      |
| Separates IP subnets           | Primarily provides Layer-2 connectivity |

Simplified:

```text
Device
   |
   v
Switch
   |
   v
Router
   |
   v
Internet
```

Think:

```text
Switch → MAC → Local Layer-2 forwarding

Router → IP → Between networks
```

---

# 10. How a Switch and Router Work Together

Suppose:

```text
Laptop:
192.168.1.10

Destination:
8.8.8.8
```

The laptop determines that:

```text
8.8.8.8
```

is outside its local subnet.

Therefore, it sends the packet toward its **default gateway**, typically the local router.

Conceptually:

```text
Laptop
192.168.1.10
    |
    | Ethernet/Wi-Fi frame
    v
Switch / Wi-Fi AP
    |
    v
Router
    |
    | IP forwarding
    v
ISP / Internet
```

The switch handles local Layer-2 delivery.

The router handles forwarding toward another IP network.

---

# 11. Router Uses IP Addresses

A router makes its main forwarding decision using the **destination IP address**.

For example:

```text
Source IP:
192.168.1.10

Destination IP:
8.8.8.8
```

The router examines:

```text
Destination = 8.8.8.8
```

and performs a routing lookup.

It does not primarily make its inter-network routing decision using the destination MAC address.

MAC addresses are important for the **local link** used to reach the next hop.

---

# 12. What Happens to the MAC Address at Each Hop?

This is an important interview concept.

Suppose:

```text
Laptop → Router → ISP Router → Server
```

The IP packet may continue toward the same final destination:

```text
Destination IP:
Server IP
```

but the Layer-2 frame is generally rebuilt for each link.

Conceptually:

```text
Hop 1:

Source MAC      → Laptop
Destination MAC → Router

IP destination → Server
```

Then after the router forwards it:

```text
Hop 2:

Source MAC      → Router
Destination MAC → Next Router

IP destination → Server
```

So:

```text
IP destination
→ remains the ultimate network-layer destination

MAC addresses
→ are relevant to the current local link/next hop
```

This is why MAC addresses are often described as **link-local**, while IP addressing supports routing across networks.

---

# 13. Router vs NAT

A router and NAT are **not the same thing**.

### Routing

Determines where an IP packet should go.

```text
Destination IP
      ↓
Routing Table
      ↓
Next Hop
```

### NAT

Translates addresses and often ports.

```text
Private Address
      ↓
NAT
      ↓
Public/Translated Address
```

A typical home router may perform both functions.

```text
              Home Router
             /           \
            /             \
       Routing             NAT
          |                  |
          v                  v
   Choose next hop     Translate addresses
```

---

# 14. A Typical Home Router Performs Multiple Functions

The device called a "router" in a home network is often actually a multifunction networking device.

It may provide:

```text
             Home Router
                  |
      +-----------+-----------+
      |           |           |
      v           v           v
   Routing       NAT       Firewall
      |
      +------ DHCP
      |
      +------ Wi-Fi
      |
      +------ DNS forwarding/cache
```

So when someone says:

> "My router provides Wi-Fi."

the device may actually contain:

* Router
* Ethernet switch
* Wireless access point
* NAT gateway
* Firewall
* DHCP server
* Sometimes DNS forwarding/caching

These are separate networking functions even though they may exist inside one physical box.

---

# 15. Router vs Gateway

A common follow-up question is:

> **What is the difference between a router and a gateway?**

A **router** is specifically a device/function that forwards packets between IP networks.

A **gateway** is a broader term for a device or system that provides a path between networks or potentially performs translation between different protocols or network environments.

For example:

```text
Laptop
192.168.1.10
    |
    v
Default Gateway
192.168.1.1
    |
    v
Internet
```

In a typical home network:

```text
Router = Default Gateway
```

for the local devices.

But the terms are not perfectly interchangeable in every context.

---

# 16. What Is a Default Gateway?

A **default gateway** is the router/interface that a host uses when the destination is outside the host's local subnet and there is no more specific local route.

For example:

```text
Laptop:
192.168.1.10/24

Default Gateway:
192.168.1.1
```

If the laptop wants to communicate with:

```text
192.168.1.20
```

that may be local to the same subnet.

But if it wants:

```text
8.8.8.8
```

the destination is outside:

```text
192.168.1.0/24
```

so the laptop sends the packet toward:

```text
192.168.1.1
```

its default gateway.

Conceptually:

```text
Local destination
      ↓
Directly reachable


Remote destination
      ↓
Default Gateway
      ↓
Router
      ↓
Other networks
```

# 18. Router Forwarding in More Detail

Suppose a router receives:

```text
Destination IP:
10.20.30.40
```

The forwarding process is conceptually:

```text
                Incoming Packet
                       |
                       v
              Read IP Header
                       |
                       v
             Destination = 10.20.30.40
                       |
                       v
              Routing Lookup
                       |
                       v
              Longest Prefix Match
                       |
                       v
                Select Next Hop
                       |
                       v
             Select Outgoing Interface
                       |
                       v
             Resolve Link-Layer Next Hop
                       |
                       v
                 Send Frame
```

The exact internal implementation is more complex, especially on high-speed routers, but this is a useful conceptual model.

# 19. Router and ARP

For IPv4 on Ethernet-like networks, a router may need to determine the Layer-2 address of the next hop.

Suppose:

```text
Router wants to forward a packet to:
192.168.2.20
```

The router may use **ARP** on the directly connected IPv4 network to discover:

```text
192.168.2.20
      ↓
MAC address
```

Then it can construct an Ethernet frame addressed to that next-hop MAC.

Conceptually:

```text
IP forwarding decision
        ↓
Next-hop IP
        ↓
ARP lookup
        ↓
Next-hop MAC
        ↓
Ethernet frame
```

For IPv6, the corresponding neighbor-resolution mechanism is **Neighbor Discovery (NDP)** rather than ARP.

---

# 20. Router Does Not Usually Change the Destination IP

A router forwarding a normal IP packet generally does not change the ultimate destination IP.

For example:

```text
Source IP:
192.168.1.10

Destination IP:
198.51.100.20
```

At the next router:

```text
Source IP:
192.168.1.10

Destination IP:
198.51.100.20
```

The IP packet continues toward the destination.

However, there are exceptions when additional mechanisms are involved, such as **NAT**, tunneling, proxies, or other network functions.

So:

```text
Routing
→ forwards based on IP

NAT
→ may modify IP/port information
```

---

# 21. TTL and Routers

IPv4 packets contain a **TTL (Time To Live)** field.

Each router forwarding the packet decreases the TTL.

For example:

```text
Host
TTL = 64
   ↓
Router 1
TTL = 63
   ↓
Router 2
TTL = 62
   ↓
Router 3
TTL = 61
```

This helps prevent packets from circulating forever due to routing loops.

When the TTL reaches zero, the packet is discarded and an ICMP message may be generated.

IPv6 uses a corresponding field called **Hop Limit**.

# 22. Router vs Layer-2 Switch: Practical Example

Suppose two devices are:

```text
PC1:
192.168.1.10/24

PC2:
192.168.1.20/24
```

They are on the same subnet.

Their communication can stay within the local Layer-2 network:

```text
PC1
 |
 v
Switch
 |
 v
PC2
```

But suppose:

```text
PC1:
192.168.1.10/24

Server:
10.0.0.20/24
```

These are different IP networks.

A router is needed for Layer-3 communication:

```text
PC1
 |
 v
Switch
 |
 v
Router
 |
 v
Server Network
 |
 v
10.0.0.20
```

This is the fundamental distinction:

```text
Same Layer-2 network
→ Switch primarily handles local forwarding

Different IP networks
→ Router performs Layer-3 forwarding
```

---

# 23. Modern Multilayer Switches

The simple rule:

```text
Switch = Layer 2
Router = Layer 3
```

is useful for interviews, but it is not an absolute hardware limitation.

Modern **Layer-3/multilayer switches** can perform routing.

For example:

```text
Multilayer Switch

Layer 2:
MAC-based forwarding

Layer 3:
IP-based routing
```

Therefore, a better statement is:

> **A traditional switch primarily provides Layer-2 forwarding, while a router primarily performs Layer-3 forwarding. Modern multilayer switches can perform both.**

# 24. Routing Protocols

Routers may learn routes in several ways.

### Static Routing

An administrator manually configures a route:

```text
10.20.0.0/16
      ↓
Next Hop 192.168.1.1
```

### Dynamic Routing

Routers exchange routing information using protocols such as:

* OSPF
* BGP
* IS-IS
* RIP

These protocols help routers learn and maintain routes.

For example:

```text
Router A ←→ Router B ←→ Router C
    \                      /
     +---- Routing Info ---+
```

The routing protocol determines or helps maintain reachability information, while the forwarding plane uses the resulting information to forward packets.

# 25. Common Interview Mistakes

### Mistake 1: "Router connects devices."

Too vague.

A switch can also connect devices.

Better:

> **A router forwards IP packets between different networks.**

---

### Mistake 2: "Router uses MAC addresses for routing."

❌ Not as its primary Layer-3 routing decision.

A router uses:

```text
Destination IP
```

to make the routing/forwarding decision.

MAC addresses are used for the local link to reach the next hop.

---

### Mistake 3: "Router and NAT are the same."

❌ Incorrect.

```text
Routing
→ Determines where packets go

NAT
→ Translates addresses/ports
```

A home device can perform both.

---

### Mistake 4: "Router and gateway are exactly the same."

❌ Too simplistic.

A router can act as a default gateway, but **gateway** is a broader term.

---

### Mistake 5: "Every router knows the entire Internet path."

❌ Not necessarily.

Routers generally make **hop-by-hop forwarding decisions** based on their available routing information.

---

### Mistake 6: "The MAC address stays the same from source to destination."

❌ Incorrect.

Layer-2 addresses are generally rewritten for each link.

The IP destination identifies the ultimate network-layer destination, while MAC addresses identify local-link endpoints.

---

### Mistake 7: "Different subnets automatically mean they cannot communicate."

❌ Incorrect.

Routers can provide communication between different subnets when routes and security policies allow it.

---

### Mistake 8: "The router always uses the default route."

❌ Incorrect.

A router first considers available matching routes and generally selects the **most specific matching prefix**.

The default route is used when no more specific route is available.

# 28. Memory Trick

Remember:

> **Switch asks: "Which local device/MAC should receive this frame?"**

> **Router asks: "Which network/next hop should receive this IP packet?"**

So:

```text

 ↓

 ↓

IP
 ↓

 ↓
Layer-3 forwarding
```

# 29. Interview Takeaway

> **A router is primarily a Layer-3 networking device that forwards IP packets between different networks by examining destination IP addresses and selecting an appropriate route from its routing/forwarding information. Routers operate hop by hop, typically use longest-prefix matching to select the most specific route, and may also provide additional functions such as NAT, firewalling, DHCP, or wireless access in consumer devices.**

### ⭐ One-Line Interview Answer

**A router forwards IP packets between different networks by examining their destination IP addresses and selecting the appropriate next hop/interface using its routing table.**
