# Q26. What Is a MAC Address?

A **MAC (Media Access Control) address** is a **Layer 2 (Data Link Layer)** address used to identify a **network interface on a local network**.

It is primarily used for **local-link communication**, such as communication between devices connected to the same Ethernet network or Wi-Fi network.

---

## Simple Definition

A **MAC address identifies a network interface for communication within the local network (LAN).**

For example:

```text
00:1A:2B:3C:4D:5E
```

A typical MAC address is **48 bits (6 bytes)** and is usually written as **six hexadecimal pairs**:

```text
00 : 1A : 2B : 3C : 4D : 5E
```

Since each hexadecimal digit represents 4 bits:

```text
12 hexadecimal digits × 4 bits
= 48 bits
= 6 bytes
```

### Example

Suppose a laptop has:

```text
IP Address  : 192.168.1.10
MAC Address : 00:1A:2B:3C:4D:5E
```

The IP address is used for **logical addressing and routing**, while the MAC address is used for **delivery on the local network link**.

---

# How Does a MAC Address Work?

Suppose your laptop wants to send data to another device connected to the **same Wi-Fi network**.

```text
Laptop
192.168.1.10
MAC: AA:AA:AA:AA:AA:AA
        |
        | Wi-Fi Frame
        | Destination MAC:
        | BB:BB:BB:BB:BB:BB
        ↓
  Wi-Fi Access Point
        |
        ↓
Destination Device
192.168.1.20
MAC: BB:BB:BB:BB:BB:BB
```

The data is transmitted inside a **Layer-2 frame**.

The frame contains information such as:

```text
Source MAC      → AA:AA:AA:AA:AA:AA
Destination MAC → BB:BB:BB:BB:BB:BB
Payload         → Network-layer data
```

The network device handling the local link uses the destination MAC address to determine where the frame should go.

---

# MAC Address and Switches

In an Ethernet LAN, a **switch primarily uses MAC addresses** to decide which port should receive a frame.

For example:

```text
              Switch
          +-------------+
          |             |
          |             |
        Port 1        Port 2
          |             |
       Laptop        Desktop
       MAC A         MAC B
```

Suppose the switch receives:

```text
Destination MAC = MAC B
```

The switch checks its **MAC address table** and may find:

```text
MAC Address                  Port
------------------------------------
AA:AA:AA:AA:AA:AA             1
BB:BB:BB:BB:BB:BB             2
CC:CC:CC:CC:CC:CC             3
```

Therefore, it forwards the frame toward **Port 2**.

### Important

A switch does **not normally make its forwarding decision using the destination IP address**.

Conceptually:

```text
Switch
   ↓
Destination MAC
   ↓
Which local port?
   ↓
Forward Ethernet frame
```

A router, in contrast, primarily makes forwarding decisions using **IP addresses**.

---

# MAC Address and ARP

Suppose your laptop knows that another device has this IPv4 address:

```text
192.168.1.20
```

But your laptop needs the device's MAC address to send an Ethernet/Wi-Fi frame on the local network.

For IPv4, **ARP (Address Resolution Protocol)** can be used to discover the MAC address associated with that IP address.

Conceptually:

```text
Known IP
192.168.1.20
    |
    ↓
   ARP
    |
    ↓
MAC Address
BB:BB:BB:BB:BB:BB
```

The laptop can then construct a Layer-2 frame:

```text
Source MAC      → AA:AA:AA:AA:AA:AA
Destination MAC → BB:BB:BB:BB:BB:BB
```

### ARP Request Example

The laptop may broadcast an ARP request similar to:

```text
"Who has 192.168.1.20?"
```

The device owning that IPv4 address responds with its MAC address:

```text
"192.168.1.20 is at BB:BB:BB:BB:BB:BB"
```

The sender can then cache this mapping temporarily.

> **Important:** ARP is used for **IPv4 local-link address resolution**. IPv6 uses **Neighbor Discovery Protocol (NDP)** instead.

---

# MAC Address Is Mainly a Local-Link Address

One of the most important concepts is that a MAC address is primarily meaningful on the **current local network link**.

Consider:

```text
Laptop
   |
   | LAN
   ↓
Router
   |
   | Internet
   ↓
Web Server
```

When the laptop sends an IP packet to a remote server, the laptop does **not** need the remote server's MAC address.

Instead, it needs the MAC address of the **next hop**, usually its default gateway.

For example:

```text
Laptop
IP: 192.168.1.10
MAC: AA:AA:AA:AA:AA:AA
        |
        | Frame
        | Destination MAC = Router MAC
        ↓
Router
        |
        | New Layer-2 frame
        ↓
Next Router
        |
        ↓
Internet
        |
        ↓
Server
```

At each routed hop, the Layer-2 frame is normally replaced for the next link.

Conceptually:

```text
IP packet:
Source IP      → Laptop IP
Destination IP → Server IP

Frame on Link 1:
Source MAC      → Laptop MAC
Destination MAC → Router MAC

Frame on Link 2:
Source MAC      → Router's outgoing MAC
Destination MAC → Next-hop MAC
```

This is why we say:

> **MAC addresses are primarily used for local-link delivery, while IP addresses provide logical addressing across networks.**

# MAC Address vs IP Address

| Feature             | MAC Address                                      | IP Address                                                       |
| ------------------- | ------------------------------------------------ | ---------------------------------------------------------------- |
| Layer               | Layer 2 — Data Link                              | Layer 3 — Network                                                |
| Purpose             | Local-link delivery                              | Logical addressing and routing                                   |
| Example             | `00:1A:2B:3C:4D:5E`                              | `192.168.1.10`                                                   |
| Commonly used by    | Switches / bridges / Wi-Fi infrastructure        | Routers / Layer-3 devices                                        |
| Scope               | Primarily local network/link                     | Can identify an endpoint/address across routed networks          |
| Common size         | 48 bits                                          | IPv4: 32 bits                                                    |
| IPv6 size           | —                                                | IPv6: 128 bits                                                   |
| Changes at routers? | Layer-2 frame addresses normally change per link | Destination IP normally remains the same during ordinary routing |
| Address type        | Link-layer address                               | Network-layer address                                            |

### Easy way to remember

```text
MAC → "Who should receive this frame on this local link?"

IP  → "Which network/address should this packet ultimately reach?"
```

---

# MAC Address and IP Address Work Together

They are not competing addressing systems. They operate at different layers.

For example:

```text
Application Data
       ↓
TCP Segment
       ↓
IP Packet
       ↓
Ethernet/Wi-Fi Frame
       ↓
Network Medium
```

The IP packet might contain:

```text
Source IP      = 192.168.1.10
Destination IP = 8.8.8.8
```

The local frame could contain:

```text
Source MAC      = AA:AA:AA:AA:AA:AA
Destination MAC = Router-MAC
```

So a useful mental model is:

```text
IP address
   ↓
Identifies the network-layer destination
   ↓
Routing determines next hop
   ↓
ARP/NDP can resolve next-hop link-layer address
   ↓
MAC address
   ↓
Local frame delivery
```

# Is a MAC Address Permanently Tied to Hardware?

Not necessarily.

Historically, MAC addresses were commonly associated with network hardware and often called **hardware addresses**.

However, modern operating systems and network interfaces can use:

* **Locally administered MAC addresses**
* **MAC address overrides**
* **MAC address spoofing**
* **MAC randomization**

Wi-Fi devices may use **randomized MAC addresses** when scanning for or connecting to wireless networks to improve privacy.

Therefore, saying:

> "A MAC address is permanently burned into the physical device and can never change."

is an oversimplification.

A better statement is:

> **A MAC address is an identifier/address used by a network interface at the link layer, and the address used by an interface can sometimes be configured or randomized.**

---

# Globally Unique vs Locally Administered MAC Addresses

A commonly encountered MAC address format is:

```text
00:1A:2B:3C:4D:5E
```

MAC addresses can contain information about whether they are **universally administered** or **locally administered**.

The relevant bits are in the first octet.

Conceptually:

```text
First Octet
    ↓
+---+---+---+---+---+---+---+---+
|   |   |   |   |   |   |   |   |
+---+---+---+---+---+---+---+---+
    ↑
    |
Locally Administered bit
```

You generally do not need to memorize the bit position for basic interviews, but you should know:

> **Not every MAC address in use must be globally assigned by a hardware manufacturer.**

---

# MAC Address in Wi-Fi

MAC addresses are also important in wireless networks.

For example:

```text
        Wi-Fi Access Point
        MAC: AP-MAC
             |
       +-----+-----+
       |           |
     Laptop      Phone
     MAC-A       MAC-B
```

The wireless network uses link-layer addressing to deliver frames between wireless stations and the access point.

However, Wi-Fi framing and behavior are more complex than simply treating Wi-Fi as identical to Ethernet. Wireless networks have their own Layer-2 mechanisms and frame types.

For basic networking understanding:

```text
Ethernet → MAC-based Layer-2 communication
Wi-Fi    → MAC-based Layer-2 communication
```

---

# MAC Address vs Port Number

These are also commonly confused.

Consider:

```text
MAC Address
    ↓
Identifies the network interface at Layer 2

IP Address
    ↓
Identifies the network-layer endpoint/address

Port Number
    ↓
Identifies the application/service at the transport layer
```

For example:

```text
MAC:  AA:AA:AA:AA:AA:AA
IP:   192.168.1.10
Port: 443
```

Conceptually:

```text
MAC  → Which local network interface/link endpoint?
IP   → Which network-layer destination?
Port → Which application/service?
```

---

# MAC Address and Broadcast

Ethernet supports a broadcast destination MAC address:

```text
FF:FF:FF:FF:FF:FF
```

A Layer-2 broadcast frame is intended for all devices on the relevant local broadcast domain.

For example, an IPv4 ARP request is commonly sent using a broadcast Ethernet destination:

```text
Destination MAC:
FF:FF:FF:FF:FF:FF
```

This allows devices on the local network to inspect the request and determine whether the requested IPv4 address belongs to them.

---

# MAC Address and Broadcast Domain

Routers normally separate Layer-2 broadcast domains.

For example:

```text
        Network A
     +-------------+
     | PC1   PC2   |
     +------+------+
            |
          Router
            |
     +------+------+
     | PC3   PC4   |
     +-------------+
        Network B
```

A Layer-2 broadcast from Network A does not normally cross the router into Network B.

This is one reason routers are important for separating IP networks.

# Important Interview Points

### 1. MAC is Layer 2

```text
MAC → Data Link Layer → Layer 2
IP  → Network Layer   → Layer 3
```

---

### 2. MAC is mainly local

A MAC address is primarily used for **communication on the current local link**.

It is not normally used to route a packet across the entire Internet.

---

### 3. Switches use MAC addresses

A switch primarily uses the **destination MAC address** to forward Layer-2 frames.

```text
Frame
  ↓
Destination MAC
  ↓
MAC Address Table
  ↓
Output Port
```

---

### 4. Routers use IP addresses

A router primarily examines the **destination IP address** to make a Layer-3 forwarding decision.

```text
Packet
  ↓
Destination IP
  ↓
Routing Table
  ↓
Next Hop / Interface
```

---

### 5. ARP maps IPv4 addresses to MAC addresses

For local IPv4 communication:

```text
IPv4 Address
      ↓
     ARP
      ↓
MAC Address
```

For IPv6, Neighbor Discovery performs the corresponding local-link discovery functions.

---

### 6. MAC addresses can be changed or randomized

Do not say that MAC addresses are always permanently fixed to hardware.

Modern systems may use:

```text
Original MAC
     ↓
Randomized / Locally administered MAC
```

especially for Wi-Fi privacy.

# Common Interview Confusions

### Confusion 1: "MAC address identifies a device."

More precise:

> A MAC address identifies a **network interface at the link layer**, not necessarily the entire physical device.

A laptop can have multiple network interfaces:

```text
Laptop
 ├── Wi-Fi interface → MAC A
 └── Ethernet interface → MAC B
```

So one physical device can have multiple MAC addresses.

---

### Confusion 2: "The router sends packets using the destination server's MAC address."

Not normally.

The router needs the MAC address of the **next hop on its outgoing link**, not the final remote server's MAC address.

---

### Confusion 3: "MAC addresses are used for Internet routing."

Not directly.

A simplified view is:

```text
MAC → local-link delivery
IP  → routed delivery
```

---

### Confusion 4: "MAC address and IP address are alternatives."

They serve different layers and work together.

```text
IP → Layer 3 addressing/routing
MAC → Layer 2 local delivery
```

---

### Confusion 5: "Every MAC address is exactly 48 bits."

**48-bit MAC addresses are the common case**, especially traditional Ethernet MAC addresses, but the broader IEEE MAC addressing ecosystem includes other address lengths/forms.

For standard interview questions, **48-bit MAC = the expected answer**.

# Practical Example: Opening a Website

Suppose your laptop is:

```text
IP  = 192.168.1.10
MAC = AA:AA:AA:AA:AA:AA
```

and your home router is:

```text
IP  = 192.168.1.1
MAC = RR:RR:RR:RR:RR:RR
```

You open:

```text
https://example.com
```

The destination server is somewhere on the Internet.

Your laptop does not need the server's MAC address.

Instead:

```text
Laptop
   |
   | Destination MAC = Router MAC
   ↓
Home Router
   |
   | Routing
   ↓
Internet
   |
   ↓
Destination Server
```

The IP packet carries the remote destination IP, while each local link uses its own Layer-2 addressing.

Simplified:

```text
                IP Packet
       +-----------------------+
       | Src IP: Laptop        |
       | Dst IP: Web Server    |
       +-----------------------+

             Encapsulated in

              Local Frame
       +-----------------------+
       | Src MAC: Laptop      |
       | Dst MAC: Router      |
       |       IP Packet      |
       +-----------------------+
```

At the next routed hop, a new Layer-2 frame is created for that link.

# Interview Takeaway

A **MAC address is a Layer-2 Data Link address used primarily to identify a network interface for local-link communication**. A common MAC address is **48 bits**, written as six hexadecimal pairs. Ethernet switches use MAC addresses to forward frames, while IPv4 ARP can resolve a known local IPv4 address to its corresponding MAC address. Unlike IP routing, MAC addressing is primarily relevant to the **current local link**, so the Layer-2 source and destination addresses normally change as an IP packet crosses routed networks.

### One-Line Interview Answer

> **A MAC address is a Layer-2 address, commonly 48 bits long, used to identify a network interface and enable local-link frame delivery, while IP addresses provide logical addressing and routing between networks.**
