# Q27. MAC Address vs IP Address

Both **MAC addresses** and **IP addresses** are used in network communication, but they operate at **different layers** and serve **different purposes**.

The simplest distinction is:

> **IP address = logical addressing and routing**
> **MAC address = local-link frame delivery**

They work together rather than replacing each other.

---

# MAC Address vs IP Address

| Feature                       | MAC Address                                               | IP Address                                                    |
| ----------------------------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| Full form                     | Media Access Control                                      | Internet Protocol                                             |
| OSI layer                     | Layer 2 — Data Link                                       | Layer 3 — Network                                             |
| Main purpose                  | Local network/frame delivery                              | Logical addressing and routing                                |
| Example                       | `00:1A:2B:3C:4D:5E`                                       | `192.168.1.10`                                                |
| Size                          | Commonly 48 bits                                          | IPv4: 32 bits, IPv6: 128 bits                                 |
| Used by                       | Switches / bridges / access points                        | Routers / Layer-3 devices                                     |
| Scope                         | Primarily local network/link                              | Can be used across routed networks                            |
| Changes when moving networks? | Not necessarily; can also be randomized/changed           | Often changes when the interface joins a different IP network |
| Assignment                    | Often interface-configured, but can be randomized/changed | Static or dynamically assigned                                |
| Used in                       | Ethernet/Wi-Fi frames                                     | IP packets                                                    |
| Address type                  | Link-layer address                                        | Network-layer address                                         |
| Typical delivery question     | "Which interface should receive this frame on this link?" | "Which network/address should this packet reach?"             |

---

# 1. MAC Address

A **MAC address** is a Layer-2 address associated with a network interface and is primarily used for **local-link communication**.

Example:

```text id="2s9wbf"
00:1A:2B:3C:4D:5E
```

A common MAC address is:

```text id="uj8j3d"
48 bits = 6 bytes
```

MAC addresses are used in technologies such as:

* Ethernet
* Wi-Fi

A switch primarily uses the destination MAC address to determine where a Layer-2 frame should be forwarded.

Conceptually:

```text id="m4a4nq"
Ethernet/Wi-Fi Frame
        ↓
Destination MAC
        ↓
Switch MAC table
        ↓
Local output port/link
```

---

# 2. IP Address

An **IP address** is a Layer-3 logical address used to identify an address/interface within an IP network and enable **routing between networks**.

Examples:

```text id="dzc7cg"
IPv4:
192.168.1.10

IPv6:
2001:db8::10
```

IPv4 uses:

```text
32 bits
```

IPv6 uses:

```text
128 bits
```

Routers examine the destination IP address to determine how an IP packet should be forwarded toward its destination.

Conceptually:

```text id="yb6c4e"
IP Packet
   ↓
Destination IP
   ↓
Routing Table
   ↓
Next Hop / Output Interface
```

---

# 3. The Main Difference: Local Delivery vs Routing

This is the most important concept to understand.

```text id="c9d9a2"
MAC
 ↓
Local-link delivery
 ↓
Layer 2 frame

IP
 ↓
Logical addressing
 ↓
Routing between networks
 ↓
Layer 3 packet
```

A MAC address is primarily meaningful on the **current network link**.

An IP address provides addressing information that allows routers to move packets between different IP networks.

---

# Practical Example

Suppose your laptop has:

```text id="g4m8bj"
MAC: AA:AA:AA:AA:AA:AA
IP : 192.168.1.10
```

Your laptop wants to communicate with a server:

```text id="s8z7eu"
Server IP: 203.0.113.20
```

The overall path might look like:

```text id="9h0qly"
Laptop
MAC: AA:AA:AA:AA:AA:AA
IP : 192.168.1.10
       |
       | Local Network
       ↓
    Router
       |
       | Internet
       ↓
    Routers
       |
       ↓
    Server
IP: 203.0.113.20
```

The **IP address** helps the network determine where the packet should ultimately go.

The **MAC address** helps deliver the Layer-2 frame on the **current local link**.

---

# 4. MAC Address Is Not Used End-to-End Across the Internet

This is a very important interview concept.

Suppose:

```text id="y6k6iw"
Laptop → Home Router → ISP Router → Internet Router → Server
```

The IP packet is logically traveling toward:

```text
Destination IP = Server IP
```

But the Layer-2 frame is different on each link.

For example:

```text id="4oyqxy"
Link 1:

Source MAC      = Laptop MAC
Destination MAC = Home Router MAC
```

After the router forwards the packet:

```text id="p8b1h7"
Link 2:

Source MAC      = Router/Interface MAC
Destination MAC = ISP Next-Hop MAC
```

Another hop may use:

```text id="k6t5p8"
Link 3:

Source MAC      = Router MAC
Destination MAC = Next Router MAC
```

So:

> **The IP packet is routed hop-by-hop, while the Layer-2 frame is delivered separately on each individual link.**

This is one of the best ways to understand why MAC and IP addresses are both necessary.

---

# 5. Example: Same Local Network

Suppose:

```text id="b9u1dv"
Laptop:
IP  = 192.168.1.10
MAC = AA:AA:AA:AA:AA:AA

Desktop:
IP  = 192.168.1.20
MAC = BB:BB:BB:BB:BB:BB
```

Both are on:

```text
192.168.1.0/24
```

The laptop wants to communicate with:

```text
192.168.1.20
```

Because the destination is on the same local IP network, the laptop can send the frame directly to the destination interface.

For IPv4, it can use **ARP** to discover the MAC address:

```text id="6v5jfi"
Destination IP
192.168.1.20
       |
       ↓
      ARP
       |
       ↓
Destination MAC
BB:BB:BB:BB:BB:BB
```

The resulting local frame can conceptually contain:

```text id="fqu7to"
Source MAC      = AA:AA:AA:AA:AA:AA
Destination MAC = BB:BB:BB:BB:BB:BB
```

---

# 6. What Happens When the Destination Is on Another Network?

Now suppose the laptop wants to communicate with:

```text id="s7q8s0"
Destination IP = 203.0.113.20
```

The destination is not on the laptop's local network.

The laptop therefore sends the local Layer-2 frame toward its **default gateway**.

For example:

```text id="3f5l9u"
Laptop
IP  = 192.168.1.10
MAC = AA:AA:AA:AA:AA:AA

        |
        | Destination MAC = Router's MAC
        ↓

Router
IP  = 192.168.1.1
MAC = RR:RR:RR:RR:RR:RR
```

Notice the important distinction:

```text id="2a4g9m"
Destination IP in packet:
203.0.113.20
          ↓
Remote server

Destination MAC in local frame:
RR:RR:RR:RR:RR:RR
          ↓
Local router / next hop
```

So:

> **The destination IP can represent the remote endpoint, while the destination MAC represents the next local Layer-2 destination.**

---

# 7. ARP Connects IP and MAC on a Local IPv4 Network

Suppose:

```text id="5n1c5c"
Destination IP = 192.168.1.20
```

The laptop needs the corresponding local MAC address.

ARP can provide:

```text id="3q9z0m"
192.168.1.20
      ↓
     ARP
      ↓
00:1A:2B:3C:4D:5E
```

This mapping can be cached for some time.

A useful conceptual flow is:

```text id="6v0l6f"
Application
    ↓
Destination IP
    ↓
Is destination local?
    ↓
   Yes
    ↓
ARP / Neighbor information
    ↓
Destination MAC
    ↓
Create Layer-2 frame
```

For IPv6, **Neighbor Discovery (NDP)** performs the corresponding address-resolution functionality rather than ARP.

---

# 8. MAC and IP Work at Different Layers

Consider a simplified protocol stack:

```text id="o9v2x5"
Application Data
       ↓
TCP Segment / UDP Datagram
       ↓
IP Packet
       ↓
Ethernet / Wi-Fi Frame
       ↓
Physical Medium
```

Different layers provide different addressing information.

```text id="w3k9rc"
Transport Layer
    ↓
Port Number
    ↓
Which application/service?

Network Layer
    ↓
IP Address
    ↓
Which network-layer destination?

Data Link Layer
    ↓
MAC Address
    ↓
Which local-link interface?
```

This layered design allows each layer to perform its own responsibility.

---

# 9. Why Do We Need Both MAC and IP?

Suppose a company has thousands of networks and millions of devices.

A Layer-2 MAC address alone is not sufficient for scalable Internet routing.

IP addressing provides **hierarchical addressing**.

For example:

```text id="m4n8sq"
10.20.30.0/24
```

The prefix provides information about the network.

Routers can use prefixes to make forwarding decisions:

```text id="3qj4b9"
Destination IP
      ↓
Longest Prefix Match
      ↓
Routing Table
      ↓
Next Hop
```

MAC addressing then handles delivery across the individual local link.

So a simplified model is:

```text id="p5b0g0"
IP
 ↓
Find the direction / next hop
 ↓
MAC
 ↓
Deliver frame on current link
```

# 10. MAC Address vs IP Address When Moving Networks

Suppose your laptop connects to a different Wi-Fi network.

Before:

```text id="5c3x9e"
Network A

IP  = 192.168.1.10
MAC = AA:AA:AA:AA:AA:AA
```

After connecting to another network:

```text id="g3l3vo"
Network B

IP  = 10.0.0.25
MAC = AA:AA:AA:AA:AA:AA
```

The MAC address **may remain the same**, while the IP address can change because the interface is now participating in a different IP network.

However, modern systems can also use MAC randomization or other interface configurations, so the MAC should not be treated as permanently immutable.

This is why:

> **IP addressing is more closely tied to the current network configuration, while MAC addressing is primarily tied to the local-link interface configuration.**

# 11. Assignment

### MAC Address

A MAC address is often assigned/configured for a network interface, but it may be:

* hardware-assigned,
* locally administered,
* manually overridden,
* randomized,
* changed by software.

Example:

```text id="drp9i6"
Wi-Fi interface
       ↓
MAC address
       ↓
May be randomized for privacy
```

### IP Address

An IP address may be:

* statically configured,
* dynamically assigned through DHCP,
* automatically configured using mechanisms such as IPv6 SLAAC,
* manually changed.

For example:

```text id="3ec7az"
Laptop joins Wi-Fi
       ↓
DHCP
       ↓
IP address assigned
```

# 12. MAC Address vs IP Address: Address Size

### MAC

A common MAC address is:

```text id="0v3v5v"
48 bits
= 6 bytes
```

Example:

```text
00:1A:2B:3C:4D:5E
```

### IPv4

```text id="qly3ry"
32 bits
= 4 bytes
```

Example:

```text
192.168.1.10
```

### IPv6

```text id="7u4h19"
128 bits
= 16 bytes
```

Example:

```text
2001:db8::10
```

Therefore:

```text id="v1m1kl"
MAC → Commonly 48 bits
IPv4 → 32 bits
IPv6 → 128 bits
```

# 13. MAC Address vs IP Address in a Switch and Router

### Switch

A switch primarily works with:

```text id="p8zj43"
MAC addresses
     ↓
MAC address table
     ↓
Frame forwarding
```

### Router

A router primarily works with:

```text id="5r7xqi"
IP addresses
     ↓
Routing table
     ↓
Packet forwarding
```

Simplified:

```text id="v8h3z1"
        Layer 2
           ↓
      MAC Address
           ↓
        Switch
           ↓
     Local Frame

----------------------------

        Layer 3
           ↓
       IP Address
           ↓
         Router
           ↓
      IP Packet
```

Modern networking devices can combine multiple functions, so this is a conceptual distinction rather than a statement that every physical device performs only one layer's functions.

# 14. Can a Device Have Multiple IP Addresses but One MAC Address?

**Yes.**

A network interface can have multiple IP addresses.

For example:

```text id="5e7e2n"
One network interface

MAC:
AA:AA:AA:AA:AA:AA

IP addresses:
192.168.1.10
192.168.1.20
192.168.1.30
```

This can occur for legitimate networking purposes such as:

* multiple services,
* virtual IPs,
* aliases,
* application/network configurations,
* containers or virtualization.

However, the reverse relationship is also not necessarily one-to-one.

A device can have multiple interfaces:

```text id="h8g4gi"
Laptop
 ├── Wi-Fi
 │    ├── MAC A
 │    └── IP address(es)
 │
 └── Ethernet
      ├── MAC B
      └── IP address(es)
```

Therefore:

> **There is no universal rule that one device = one MAC = one IP.**

---

# 15. One MAC Can Be Associated With Multiple IP Addresses

Consider:

```text id="h2y3fm"
MAC:
AA:AA:AA:AA:AA:AA

IP addresses:
192.168.1.10
192.168.1.11
```

Both IP addresses can be associated with the same network interface.

Conceptually:

```text id="3n7pr8"
            Network Interface
                   |
            MAC: AA:AA:AA:AA:AA:AA
                   |
          +--------+--------+
          |                 |
     IP: 192.168.1.10  IP: 192.168.1.11
```

The exact relationship depends on the host configuration and networking environment.

---

# 16. Important Interview Distinction: MAC Is Not a Permanent Device Identity

A common incorrect statement is:

> "MAC address uniquely identifies the physical device forever."

This is not reliable.

A more accurate statement is:

> **A MAC address identifies a network interface at the link layer, but the address can sometimes be changed, overridden, virtualized, or randomized.**

For example:

```text id="s9q6fp"
Physical/Virtual Interface
          ↓
     MAC Address
          ↓
Can potentially be:
- configured
- randomized
- overridden
- virtualized
```

This is particularly relevant with modern Wi-Fi privacy features and virtual networking.

# 17. MAC vs IP: Easy Analogy

Imagine a large apartment complex.

### IP address

Think of the IP address as the **logical postal address**:

```text
City → Building → Network → Apartment
```

It helps determine where something needs to go.

### MAC address

Think of the MAC address more like identifying the **local delivery interface** for the current building/link.

The analogy is not exact, but it helps remember:

```text
IP  → Where should the packet go?
MAC → Which local interface should receive the frame?
```

# Common Interview Mistakes

### Mistake 1: "MAC is used for routing."

Not primarily.

```text
MAC → Local-link frame delivery
IP  → Routing between networks
```

---

### Mistake 2: "The remote server's MAC is used by my laptop."

Usually no.

Your laptop needs the MAC of the **next local hop**, often the default gateway.

---

### Mistake 3: "MAC address never changes."

Not necessarily.

MAC addresses can be:

* randomized,
* locally administered,
* overridden,
* virtualized.

---

### Mistake 4: "One device always has exactly one MAC and one IP."

No.

A device can have:

```text
Multiple interfaces
       ↓
Multiple MAC addresses
       ↓
Multiple IP addresses
```

Even one interface can have multiple IP addresses.

---

### Mistake 5: "IP addresses identify physical hardware."

Not exactly.

An IP address is a **logical network-layer address** associated with an interface/address assignment.

It can change, move, or be reassigned.

---

### Mistake 6: "MAC addresses work across the Internet."

MAC addresses are primarily relevant to the **current Layer-2 link**. They are not the addressing mechanism used for end-to-end Internet routing.

# Interview Takeaway

**MAC and IP addresses work at different layers and solve different networking problems.**

* **MAC address** → Layer 2 → local-link/frame delivery.
* **IP address** → Layer 3 → logical addressing and routing.
* **Switches** primarily use MAC addresses.
* **Routers** primarily use IP addresses.
* **ARP** can map a known IPv4 address to a MAC address on the local link.
* A MAC address is commonly **48 bits**, while IPv4 is **32 bits** and IPv6 is **128 bits**.
* MAC addresses are not necessarily permanent or immutable.
* A device/interface can have **multiple IP addresses**, and a device can have **multiple network interfaces and therefore multiple MAC addresses**.

### One-Line Interview Answer

> **A MAC address is a Layer-2 local-link address used for frame delivery, while an IP address is a Layer-3 logical address used to identify network destinations and route packets between networks.**
