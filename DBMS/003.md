31.What is a database schema?
Answer

A database schema is the logical structure or blueprint of a database. It defines how data is organized and how different pieces of data are related.

It describes things such as:

Tables
Columns and their data types
Primary keys
Foreign keys
Relationships
Constraints
Indexes
Views and other database objects
Simple intuition

Think of a schema as the blueprint of a database, not the actual data.

For example, an e-commerce database might have this schema:

Customers
-------------------------
customer_id  INT  PK
name         VARCHAR
email        VARCHAR


Orders
-------------------------
order_id     INT  PK
customer_id  INT  FK
amount       DECIMAL

The schema tells us:

“There is a Customers table with these columns, an Orders table with these columns, and customer_id connects the two.”

The actual rows are the data stored according to that structure.

Example using SQL

We can define part of a schema using:

CREATE TABLE Customers (
    customer_id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(150) UNIQUE
);

CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    amount DECIMAL(10, 2),
    FOREIGN KEY (customer_id)
        REFERENCES Customers(customer_id)
);

Here, the schema specifies:

Customers and Orders tables
Column names
Data types
Primary keys
Foreign-key relationship
Uniqueness constraint on email
Schema vs Data
Schema	Data
Defines database structure	Actual stored information
Acts like a blueprint	Represents real records
Changes relatively less frequently	Changes frequently
Example: customer_id INT	Example: customer_id = 101

For example:

Schema:
Customer(customer_id INT, name VARCHAR)

Data:
101, "Rahul"
102, "Priya"

The schema defines what the data should look like, while the data contains the actual values.

Schema vs Database

A database is the overall data-management environment containing stored data and database objects, while a schema describes an organizational structure within that environment. The exact meaning of “schema” can vary somewhat across database systems.

In PostgreSQL, for example, a database can contain multiple schemas:

Database
│
├── sales schema
│   ├── customers
│   └── orders
│
└── analytics schema
    ├── reports
    └── metrics
Interview takeaway

A database schema is the logical blueprint of a database that defines its structure—tables, columns, data types, relationships, constraints, and other database objects—without representing the actual records stored in those structures.

Common mistake: Don't confuse a schema with the actual data. The schema defines the structure; the rows contain the data.
