5.What are primary and foreign keys?
Answer

Primary key and foreign key are important concepts in relational databases. They are used to identify records uniquely and establish relationships between tables.

1. Primary Key

A primary key is a column or combination of columns that uniquely identifies each row in a table.

Example:

student_id	name	course
101	Rahul	B.Tech
102	Priya	BCA
103	Amit	B.Tech

Here, student_id can be the primary key:

CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    course VARCHAR(50)
);

Therefore:

Every student_id must be unique.
A primary-key value cannot be NULL.
A table has one primary-key constraint; that key can consist of multiple columns (a composite primary key).
2. Foreign Key

A foreign key is a column or combination of columns in one table that references a candidate/primary key in another table, establishing a relationship between the tables.

For example:

Students

student_id	name
101	Rahul
102	Priya

Orders

order_id	student_id	amount
501	101	500
502	102	800

Here:

Students.student_id
        ↑
        │ referenced by
        │
Orders.student_id

We can define it as:

CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    student_id INT,
    amount DECIMAL(10, 2),

    FOREIGN KEY (student_id)
        REFERENCES Students(student_id)
);

The foreign key helps enforce referential integrity. For example, an order generally cannot reference a student ID that doesn't exist in the referenced table, subject to the database's constraint behavior.

Primary Key vs Foreign Key
Primary Key	Foreign Key
Uniquely identifies a row in its table	References a key in another table
Must be unique	Does not necessarily have to be unique
Cannot contain NULL	Can often contain NULL, if the column permits it
Identifies the entity/record	Establishes a relationship
One primary-key constraint per table	A table can have multiple foreign-key constraints
Real-world analogy

Think about a college system:

Students
----------------
student_id  ← Primary Key
name
course
Courses
----------------
course_id   ← Primary Key
course_name

If students are enrolled in courses:

Enrollments
----------------
student_id  ← Foreign Key
course_id   ← Foreign Key

The foreign keys connect the enrollment records to the corresponding students and courses.

Why are keys important?

They help with:

Unique identification of records
Relationships between tables
Referential integrity
Data consistency
Efficient querying and joins

For example:

SELECT Students.name, Orders.amount
FROM Students
JOIN Orders
    ON Students.student_id = Orders.student_id;

The keys provide the logical connection needed for this join.

Interview takeaway

A primary key uniquely identifies a row within a table, while a foreign key references a key in another table and is used to establish relationships and maintain referential integrity.
