6.What is a candidate key?
Answer

A candidate key is a minimal set of one or more attributes that can uniquely identify each row in a table.

A table can have multiple candidate keys, but only one candidate key is selected as the primary key.

Example

Suppose we have:

student_id	email	name	course
101	rahul@example.com	Rahul	B.Tech
102	priya@example.com	Priya	BCA
103	amit@example.com	Amit	B.Tech

Here, both:

student_id
email

can uniquely identify a student.

Therefore, both can be candidate keys.

We might choose:

student_id → Primary Key

while email remains another candidate key, often enforced with a UNIQUE constraint.

Why "minimal"?

The key must contain no unnecessary attributes.

Suppose:

(student_id, email)

uniquely identifies a student.

But student_id alone already uniquely identifies the student. Therefore, (student_id, email) is not a candidate key, because it is not minimal.

Candidate Key vs Primary Key
Candidate Key	Primary Key
Any minimal key capable of uniquely identifying rows	The candidate key chosen as the main identifier
A table can have multiple candidate keys	A table has one primary-key constraint
Not every candidate key becomes the primary key	Selected from candidate keys
Other candidate keys are often called alternate keys	Main key used for identification
Simple hierarchy
Possible unique attributes
          ↓
   Candidate Keys
      /       \
student_id    email
      ↓
  Choose one
      ↓
 Primary Key

For example:

CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE,
    name VARCHAR(100)
);

Here:

student_id → primary key
email → another candidate key / alternate key, assuming it is guaranteed to uniquely identify students
Candidate Key vs Super Key

This is a common interview question.

A super key is any set of attributes that uniquely identifies a row.

A candidate key is a minimal super key.

For example:

{student_id}             → Candidate key
{email}                  → Candidate key
{student_id, name}       → Super key, but not candidate key

{student_id, name} is not minimal because student_id alone is sufficient.

Interview takeaway

A candidate key is a minimal set of attributes that uniquely identifies each row. A table can have multiple candidate keys, and one of them is selected as the primary key.

Common mistake: Don't say “candidate key is any unique column.” It can be one or more columns, and the defining property is uniqueness + minimality.
