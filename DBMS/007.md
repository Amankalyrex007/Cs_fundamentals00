7.What is a composite key?
Answer

A composite key is a key made up of two or more columns together that uniquely identify a row in a table.

A single column may not be unique, but the combination of multiple columns is unique.

Example

Consider a student enrollment table:

student_id	course_id	semester
101	C01	2026
101	C02	2026
102	C01	2026
102	C02	2026

Here, student_id alone is not unique because a student can enroll in multiple courses.

Similarly, course_id alone is not unique because many students can take the same course.

But:

(student_id, course_id)

together can uniquely identify an enrollment.

We can define it as:

CREATE TABLE Enrollments (
    student_id INT,
    course_id INT,
    semester INT,

    PRIMARY KEY (student_id, course_id)
);

Now the combination of student_id and course_id forms the composite primary key.

Why use a composite key?

It is useful when the relationship itself is uniquely identified by multiple attributes.

A common example is a many-to-many relationship:

Students                 Courses
   |                        |
   |                        |
   +------ Enrollments -----+

The enrollment table can use:

(student_id, course_id)

to identify each student-course relationship.

Composite Key vs Single-column Key
Single-column key	Composite key
Uses one column	Uses two or more columns
Example: student_id	Example: (student_id, course_id)
One attribute must be sufficient for uniqueness	Combination provides uniqueness
Simpler to reference	Can require multiple columns when referencing
Composite Key vs Composite Index

Don't confuse these:

Composite key → participates in uniquely identifying records and may enforce a key constraint.
Composite index → index built on multiple columns to improve query performance; it does not necessarily enforce uniqueness.

For example:

CREATE INDEX idx_student_course
ON Enrollments(student_id, course_id);

This creates a composite index, not a primary key.

Interview takeaway

A composite key is a key consisting of multiple columns whose combination uniquely identifies a record. It is especially common in junction/associative tables representing many-to-many relationships.

Common mistake: A composite key does not mean each column individually must be unique. The combination of the columns must satisfy the key's uniqueness requirement.
