8.What are constraints?
Answer

Constraints are rules enforced by a database on columns or tables to maintain data accuracy, consistency, and integrity.

They prevent invalid or unwanted data from being stored.

Common types of constraints
Constraint	Purpose	Example
PRIMARY KEY	Uniquely identifies each row	student_id
FOREIGN KEY	Maintains relationships between tables	course_id
NOT NULL	Prevents missing values	name
UNIQUE	Prevents duplicate values	email
CHECK	Ensures a condition is satisfied	age >= 18
DEFAULT	Provides a value when none is supplied	status = 'Active'
Example
CREATE TABLE Students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE,
    age INT CHECK (age >= 18),
    status VARCHAR(20) DEFAULT 'Active'
);

Here:

1. PRIMARY KEY

student_id INT PRIMARY KEY

Every student must have a unique identifier.

2. NOT NULL

name VARCHAR(100) NOT NULL

A student cannot be inserted without a name.

3. UNIQUE

email VARCHAR(150) UNIQUE

Two students cannot have the same email value.

4. CHECK

age INT CHECK (age >= 18)

The database rejects values that violate the specified condition.

5. DEFAULT

status VARCHAR(20) DEFAULT 'Active'

If no status is provided, the database can use 'Active'.

6. FOREIGN KEY

For example:

CREATE TABLE Enrollments (
    student_id INT,
    course_id INT,

    FOREIGN KEY (student_id)
        REFERENCES Students(student_id)
);

This ensures that a referenced student must satisfy the foreign-key relationship according to the database's referential-integrity rules.

Why are constraints important?

Without constraints, an application could accidentally store data such as:

student_id = NULL
email = same@email.com
age = -10

Constraints allow the database itself to enforce important rules instead of relying entirely on application code.

This provides:

Data integrity
Data consistency
Error prevention
Referential integrity
Reliable database design
Constraints vs Validation

They are related but not identical.

Application validation happens in application code:

if age < 18:
    raise ValueError("Invalid age")

Database constraints are enforced by the database:

CHECK (age >= 18)

For important data-integrity rules, database constraints provide protection even if data comes from multiple applications or clients.

Interview takeaway

Constraints are rules enforced by a database to ensure that stored data satisfies specific integrity and consistency requirements. Common constraints include PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, CHECK, and DEFAULT.

Common mistake: Don't think constraints are only for validation in application code. A key advantage is that they provide database-level enforcement of important integrity rules.
