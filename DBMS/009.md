9.What is normalization?
Answer

Normalization is the process of organizing data in a relational database to reduce data redundancy, avoid data anomalies, and improve data integrity.

The basic idea is to divide large tables into smaller, logically related tables and connect them using keys.

Simple example

Suppose we store student and course information in one table:

student_id	student_name	course_id	course_name	instructor
101	Rahul	C01	DBMS	Sharma
102	Priya	C01	DBMS	Sharma
103	Amit	C02	Python	Verma

Here, information about the DBMS course is repeated for every student enrolled in it.

This creates data redundancy.

Instead, normalization can separate the data:

Students

student_id	student_name
101	Rahul
102	Priya
103	Amit

Courses

course_id	course_name	instructor
C01	DBMS	Sharma
C02	Python	Verma

Enrollments

student_id	course_id
101	C01
102	C01
103	C02

The tables are connected using keys.

Students
   │
   │ student_id
   ↓
Enrollments
   ↑
   │ course_id
   │
Courses
Why do we normalize?

Normalization primarily helps prevent data anomalies.

1. Update anomaly

Suppose Sharma's name changes and the instructor's name is repeated across 1,000 rows.

You would need to update many records.

With normalization, the instructor information can be stored in one appropriate place.

2. Insert anomaly

You may want to add a new course even though no student has enrolled yet.

If student and course information are forced into the same table, inserting the course may require unnecessary student information.

Separating the tables avoids this problem.

3. Delete anomaly

Suppose the only student enrolled in a particular course leaves.

Deleting that student's row could accidentally remove the only stored information about the course.

With separate Students, Courses, and Enrollments tables, deleting an enrollment doesn't delete the course itself.

Normal Forms

Normalization is commonly discussed using normal forms.

1NF — First Normal Form

A table is in 1NF when each column contains atomic/single values, rather than repeating groups or lists.

Bad:

student_id	name	courses
101	Rahul	DBMS, Python, Java

Better:

student_id	name	course
101	Rahul	DBMS
101	Rahul	Python
101	Rahul	Java
2NF — Second Normal Form

A table is in 2NF when:

It is already in 1NF.
Every non-key attribute depends on the whole candidate key, not just part of a composite key.

This mainly matters when a table has a composite key.

For example:

(student_id, course_id)

If student_name depends only on student_id, it does not depend on the whole key.

That creates a partial dependency, which 2NF aims to remove.

3NF — Third Normal Form

A table is in 3NF when:

It is in 2NF.
Non-key attributes do not depend on other non-key attributes in a way that creates a transitive dependency.

For example:

student_id → department_id → department_name

If department_name is stored in the student table, it depends indirectly on student_id through department_id.

We can separate department information into its own table.

BCNF

Boyce-Codd Normal Form (BCNF) is a stronger version of 3NF that handles certain dependency cases that 3NF may allow.

For most placement interviews, understanding 1NF, 2NF, 3NF, and the basic idea of BCNF is important.

Normalization vs Denormalization
Normalization	Denormalization
Reduces redundancy	Intentionally introduces some redundancy
Improves data integrity	Can improve read performance in some workloads
Usually creates more tables	May combine or duplicate data
May require more joins	Can reduce joins
Common in transactional systems	Often considered for read-heavy/analytical workloads

Normalization is not about making the database “as normalized as possible” in every situation. Real systems may deliberately denormalize for performance or simplicity after considering workload and consistency requirements.

Interview takeaway

Normalization is the process of organizing relational data into well-structured tables to reduce redundancy and prevent insertion, update, and deletion anomalies while maintaining data integrity.
