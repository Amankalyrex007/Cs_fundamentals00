10.Explain 1NF, 2NF, 3NF, and BCNF.
Answer

These are normal forms used in database normalization. Each normal form imposes stronger rules on how data and dependencies are organized.

A useful progression is:

1NF → remove repeating/multi-valued attributes
2NF → remove partial dependencies
3NF → remove transitive dependencies
BCNF → strengthen the dependency rule further

1. First Normal Form (1NF)

A table is in 1NF when:

Each column contains atomic/single values.
There are no repeating groups or multi-valued attributes in a single cell.
Not in 1NF
student_id	name	courses
101	Rahul	DBMS, Python
102	Priya	Java

courses contains multiple values in one cell.

Convert to 1NF
student_id	name	course
101	Rahul	DBMS
101	Rahul	Python
102	Priya	Java

Now each cell contains one value.

Key idea:

1NF = atomic values, no repeating groups.

2. Second Normal Form (2NF)

A table is in 2NF when:

It is already in 1NF.
Every non-key attribute depends on the whole candidate key, not just part of it.

This is mainly relevant when the table has a composite candidate key.

Example

Consider:

student_id	course_id	student_name	course_name
101	C01	Rahul	DBMS
101	C02	Rahul	Python
102	C01	Priya	DBMS

Suppose the candidate key is:

(student_id, course_id)

But:

student_id → student_name
course_id  → course_name

student_name depends only on student_id, and course_name depends only on course_id.
This is a transitive dependency.

Convert to 3NF

Students

student_id	student_name	department_id
101	Rahul	D01
102	Priya	D02

Departments

department_id	department_name
D01	Computer Science
D02	Mathematics

Now department information is stored separately.

Key idea:

3NF = 2NF + no transitive dependency of non-key attributes on a key.

4. BCNF — Boyce-Codd Normal Form

BCNF is a stronger version of 3NF.

A relation is in BCNF if:

For every non-trivial functional dependency X → Y, X must be a superkey.

In simpler interview language:

Every determinant must be a candidate key/superkey.

Why do we need BCNF?

There are some schemas that satisfy 3NF but still have redundancy or dependency problems that BCNF addresses.

Consider:

student	course	instructor
Rahul	DBMS	Sharma
Priya	DBMS	Sharma
Amit	Python	Verma

Suppose the business rules are:

(student, course) → instructor
instructor → course

If each instructor teaches only one course, then instructor → course.

But instructor is not necessarily a candidate key for the entire relation because multiple students can have the same instructor.

Therefore, the determinant instructor is not a superkey, violating BCNF.

The exact decomposition depends on the functional dependencies and business rules.

Key idea:

BCNF = for every functional dependency, the determinant must be a superkey.

1NF vs 2NF vs 3NF vs BCNF
Normal Form	Main condition	Removes
1NF	Atomic values; no repeating groups	Multi-valued/repeating attributes
2NF	1NF + no partial dependency	Partial dependency
3NF	2NF + no problematic transitive dependency	Transitive dependency
BCNF	Every determinant is a superkey	Certain dependency anomalies remaining under 3NF

Important interview point

Don't reduce the definitions to:

1NF = 1 column, 2NF = 2 columns, 3NF = 3 columns.

That is incorrect.

The normal forms are about functional dependencies and the structure of the relation, not the number of columns.

Interview takeaway

1NF ensures atomic values, 2NF removes partial dependencies, 3NF removes transitive dependencies, and BCNF strengthens 3NF by requiring every determinant in a non-trivial functional dependency to be a superkey.
