11.Why is normalization needed?
Answer

Normalization is needed to organize data efficiently and reduce problems caused by storing the same information repeatedly.

The main goals are to:

Reduce data redundancy
Prevent data anomalies
Improve data integrity and consistency
Make database structure easier to maintain
1. Reduce data redundancy

Suppose we store student and department information in one table:

student_id	student_name	department_id	department_name
101	Rahul	D01	Computer Science
102	Priya	D01	Computer Science
103	Amit	D01	Computer Science

Computer Science is repeated for every student in the department.

With normalization, we can separate it:

Students

student_id	student_name	department_id
101	Rahul	D01
102	Priya	D01
103	Amit	D01

Departments

department_id	department_name
D01	Computer Science

Now the department name is stored once.

2. Prevent update anomalies

Suppose the department name changes from:

Computer Science

to:

Computer Science & Engineering

In the unnormalized design, we might have to update many student records.

If one row is missed, the database could contain inconsistent values:

Rahul  → Computer Science
Priya  → Computer Science & Engineering

With normalization, the department name exists in one appropriate location.

3. Prevent insertion anomalies

Suppose we want to add a new department, but currently no student belongs to it.

If department and student information are forced into the same table, we may have difficulty representing the department without inventing student information or using unnecessary NULL values.

With separate tables:

Departments

can store the new department independently.

4. Prevent deletion anomalies

Suppose a department currently has only one student.

If that student's row is deleted from a poorly designed combined table, we might accidentally lose the only stored information about the department.

With normalized tables:

Students
Departments

deleting the student does not automatically mean deleting the department's information.

5. Improve data integrity

Normalization helps ensure that each piece of information has an appropriate place.

For example:

Student → student information
Department → department information
Enrollment → student-course relationship

This makes it easier to maintain consistent data and enforce relationships using keys and constraints.

But is more normalization always better?

No.

Highly normalized databases can require more joins, which may make some read-heavy workloads more complex or potentially less efficient.

Therefore, real systems sometimes use denormalization deliberately—for example, duplicating certain data to simplify or accelerate frequently used reads.

The choice depends on:

Read/write workload
Query patterns
Consistency requirements
Performance requirements
Storage considerations
Application architecture
Simple intuition

Think of normalization like organizing a library:

Poor organization:

Every student's record contains the same complete department information.

Normalized organization:

Store student information once, department information once, and connect them with IDs.

This reduces duplication and makes changes easier to manage.

Interview takeaway

Normalization is needed to reduce redundancy, prevent insertion/update/deletion anomalies, and maintain data integrity by organizing data into logically related tables. However, normalization involves trade-offs, especially additional joins, so practical database designs may use controlled denormalization when justified.
