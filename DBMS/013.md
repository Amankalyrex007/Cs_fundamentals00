13.What is a transaction?
A transaction is a sequence of one or more database operations that are treated as one logical unit of work.

The key idea is:

A transaction should either complete successfully as a whole, or its changes should be rolled back so the database does not remain in an inconsistent state.

Example

Suppose we transfer ₹1,000 from Account A to Account B:

1. Deduct ₹1,000 from Account A
2. Add ₹1,000 to Account B

Both operations should belong to the same transaction.

If step 1 succeeds but step 2 fails, the transaction should roll back step 1.

Before:  A = ₹10,000, B = ₹5,000

Transaction:
    A = A - ₹1,000
    B = B + ₹1,000

After:
    A = ₹9,000, B = ₹6,000

If something fails midway:

ROLLBACK

and the database returns to its previous consistent state.

ACID properties

Transactions are commonly explained using ACID:

Property	Meaning
Atomicity	All operations succeed, or none are applied
Consistency	The transaction preserves database rules and constraints
Isolation	Concurrent transactions should not improperly interfere with each other
Durability	Once committed, changes survive failures such as a crash
COMMIT vs ROLLBACK
BEGIN;

UPDATE accounts
SET balance = balance - 1000
WHERE account_id = 1;

UPDATE accounts
SET balance = balance + 1000
WHERE account_id = 2;

COMMIT;
COMMIT → permanently save the transaction's changes.
ROLLBACK → undo the transaction's changes.
Why are transactions important?

They are especially important for operations where partial updates would be incorrect, such as:

Bank transfers
Order creation and payment processing
Inventory updates
Ticket/seat booking
Updating multiple related tables
Interview takeaway

A transaction is a logical unit of database work whose operations are handled together, providing reliable behavior through properties such as atomicity, consistency, isolation, and durability (ACID).
