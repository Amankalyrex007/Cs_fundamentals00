16.What are dirty reads, non-repeatable reads, and phantom reads?
These are concurrency anomalies that can occur when multiple transactions execute at the same time.

1. Dirty Read

A dirty read occurs when one transaction reads data that another transaction has changed but not yet committed.

Example:

Transaction A:
Balance = ₹5,000
UPDATE → ₹4,000   (not committed yet)

Transaction B:
Reads balance → ₹4,000

Transaction A:
ROLLBACK

Transaction B read ₹4,000, but that value was never actually committed.

Problem: Transaction B used temporary/uncommitted data.

Prevented by: READ COMMITTED and stronger isolation levels.

2. Non-repeatable Read

A non-repeatable read occurs when a transaction reads the same row twice but gets different values because another transaction modified and committed that row between the reads.

Example:

Transaction A:
Reads balance → ₹5,000

Transaction B:
Changes balance → ₹4,000
COMMIT

Transaction A:
Reads balance again → ₹4,000

Transaction A read the same row twice but got different values.

Problem: The row's committed value changed during the transaction.

Prevented by: REPEATABLE READ and stronger isolation levels.

3. Phantom Read

A phantom read occurs when a transaction executes the same query twice but gets a different set of rows because another transaction inserted, deleted, or otherwise changed rows that match the query between the two executions.

Example:

Suppose Transaction A runs:

SELECT *
FROM employees
WHERE salary > 50000;

It gets 10 rows.

Then Transaction B inserts an employee with salary ₹60,000 and commits.

Transaction A runs the same query again:

SELECT *
FROM employees
WHERE salary > 50000;

Now it gets 11 rows.

The extra row is a phantom row.

Problem: The result set changed between repeated executions of the same query.

Prevented by: SERIALIZABLE; behavior under REPEATABLE READ can depend on the database implementation.

Quick comparison
Anomaly	What changes?	Simple example
Dirty read	Uncommitted value is read	A changes → B reads → A rolls back
Non-repeatable read	Same row's value changes	A reads ₹5k → B commits ₹4k → A reads ₹4k
Phantom read	Set of matching rows changes	A gets 10 rows → B inserts matching row → A gets 11
Easy way to remember
Dirty → reading uncommitted data.
Non-repeatable → same row, different value.
Phantom → same query, different set of rows.
Interview takeaway

Dirty reads concern uncommitted data, non-repeatable reads concern changes to an already-read row, and phantom reads concern changes to the set of rows matching a query.
