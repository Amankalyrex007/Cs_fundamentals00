17.What is a deadlock in a database?
A deadlock occurs when two or more transactions are waiting for each other to release resources/locks, so none of them can proceed.

Example

Suppose we have two rows: A and B.

Transaction 1              Transaction 2
-------------              -------------
Locks A                    Locks B
   ↓                          ↓
Requests B                 Requests A
   ↓                          ↓
Waits for T2               Waits for T1

Now:

T1 cannot continue until T2 releases B.
T2 cannot continue until T1 releases A.

This creates a circular wait, and the transactions are deadlocked.

Simple real-world analogy

Imagine:

Person A has key 1 and needs key 2.
Person B has key 2 and needs key 1.

Neither person can proceed because each is waiting for the other.

Why do deadlocks happen?

Common causes include:

Transactions acquiring locks in different orders.
Transactions holding locks for too long.
High concurrency.
Large or inefficient database operations.
Certain combinations of queries and isolation/locking behavior.
How are deadlocks handled?

Databases commonly use deadlock detection. Once a deadlock is detected, the database typically:

Chooses one transaction as the victim.
Rolls that transaction back.
Releases its locks.
Allows the other transaction to proceed.

The application can then retry the failed transaction, usually with a bounded retry count and backoff.

Interview takeaway

A database deadlock occurs when transactions form a circular wait for resources held by one another. The database detects the cycle and typically rolls back one transaction to break the deadlock.
