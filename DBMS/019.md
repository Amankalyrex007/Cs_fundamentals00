19.What is an index?
A database index is a data structure that helps the database find rows faster without scanning the entire table.

Think of it like the index of a book: instead of reading every page to find a topic, you use the index to locate the relevant pages directly.

Example

Suppose we have:

Users
--------------------------------
id | name   | email
1  | Aaman  | aaman@example.com
2  | Rahul  | rahul@example.com
3  | Priya  | priya@example.com
...

Without an index:

SELECT *
FROM users
WHERE email = 'aaman@example.com';

The database may need to examine many rows to find the matching email.

With an index:

CREATE INDEX idx_users_email
ON users(email);

The database can use the index to locate the matching row much more efficiently.

How does an index work?

A common index implementation is a B-tree/B+ tree, although databases can support other index types as well.

Conceptually:

              Index
             /     \
         A-M         N-Z
        /   \       /   \
      ...   ...   ...   ...

The index stores organized information that helps the database navigate toward the required rows rather than scanning every row.

Advantages
Faster SELECT queries.
Faster searches using indexed columns.
Can improve joins.
Can improve ORDER BY and range queries when the index is suitable.
Can enforce uniqueness when implemented as a unique index.
Disadvantages

Indexes are not free.

Require additional storage.
INSERT, UPDATE, and DELETE can become more expensive because indexes may need to be updated.
Too many indexes increase maintenance overhead.
An index isn't automatically useful for every query.

For example, creating indexes on every column is usually not a good strategy.

Primary key and indexes

A primary key is commonly backed by an index, but the exact implementation depends on the database.

For example:

CREATE TABLE users (
    id INT PRIMARY KEY,
    email VARCHAR(255)
);

The database typically creates or uses an index to efficiently enforce the primary-key uniqueness requirement.

Composite index

An index can contain multiple columns:

CREATE INDEX idx_orders_customer_date
ON orders(customer_id, order_date);

This can be useful for queries such as:

SELECT *
FROM orders
WHERE customer_id = 101
ORDER BY order_date;

Column order matters in a composite index. An index on (customer_id, order_date) is not equivalent to an index on (order_date, customer_id) for all query patterns.

Interview takeaway

An index is a database data structure that improves query performance by allowing the database to locate relevant rows more efficiently than a full table scan. The trade-off is additional storage and overhead when data is inserted, updated, or deleted.
