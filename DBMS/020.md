20.How does an index improve query performance?
An index improves query performance by allowing the database to locate matching rows without scanning every row in the table.

Without an index

Suppose we have 10 million users:

SELECT *
FROM users
WHERE email = 'aaman@example.com';

Without a suitable index, the database may perform a full table scan:

Row 1 → check email
Row 2 → check email
Row 3 → check email
...
Row 10,000,000 → check email

This can require examining a large number of rows.

With an index

Create an index:

CREATE INDEX idx_users_email
ON users(email);

Now the database can search the index structure to find the relevant entry:

             Index
               ↓
      aaman@example.com
               ↓
          Row location
               ↓
          Required row

For a B-tree-style index, searching is roughly O(log N) for the index traversal rather than scanning O(N) table rows, although actual query cost depends on the database, index type, data distribution, and whether the optimizer chooses the index.

What happens internally?

Conceptually, the database:

Receives the query.
Checks available indexes and estimates possible execution plans.
Determines whether an index is beneficial.
Traverses the index to find matching keys.
Uses the associated row locations to retrieve the required table rows.

This is why indexes are particularly useful for:

WHERE
JOIN
ORDER BY
GROUP BY

when the index matches the query pattern appropriately.

Example: range query

An index can also help with ranges:

SELECT *
FROM orders
WHERE order_date >= '2026-01-01';

A suitable index on order_date can help the database locate the relevant range rather than checking every order.

Important trade-off

Indexes improve read performance, but they have costs:

Faster reads
     ↑
     │
Index
     │
     ↓
More storage + maintenance during INSERT/UPDATE/DELETE

Also, an index is not guaranteed to make every query faster. If a query returns a very large percentage of the table, a sequential/full-table scan may be cheaper than using the index.

Interview takeaway

An index improves query performance by providing an efficient path to locate matching rows, reducing the amount of data the database needs to scan. However, indexes consume storage and add write/maintenance overhead, so they should be created based on actual query patterns and workload.
