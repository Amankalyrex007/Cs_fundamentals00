21.What are the disadvantages of indexes?
Indexes improve read performance, but they introduce several storage, write, and maintenance costs.

1. Additional storage

Indexes require extra disk space because the database must store the indexed keys and associated information.

For large tables with multiple indexes, this can become significant.

2. Slower INSERT operations

When a new row is inserted, the database may need to update every relevant index.

INSERT row
   ↓
Update table
   ↓
Update Index 1
Update Index 2
Update Index 3

Therefore, having many indexes can increase insert cost.

3. Slower UPDATE operations

If an indexed column changes, the corresponding index must also be updated.

For example:

UPDATE users
SET email = 'new@example.com'
WHERE id = 101;

If email is indexed, the database must update the index entry as well.

4. Slower DELETE operations

Deleting a row also requires removing its entries from relevant indexes.

Therefore:

Indexes can speed up reads but increase the cost of writes.

5. Maintenance overhead

Indexes need to be maintained as data changes. Depending on the database and index type, this can involve additional CPU, I/O, memory, and potentially maintenance operations.

6. Too many indexes can hurt performance

Creating an index on every column is generally a bad strategy.

For example:

Table
 ├── Index on name
 ├── Index on email
 ├── Index on age
 ├── Index on city
 ├── Index on phone
 └── ...

Every additional index can increase:

Storage requirements
Write overhead
Maintenance cost
Query-planning complexity

Indexes should therefore be created based on actual query patterns and workload, not simply because a column exists.

7. An index may not always be used

The database optimizer decides whether an index is beneficial.

For example, if a query returns a very large percentage of the table, scanning the table sequentially may be cheaper than using an index and then fetching many rows.

So:

Having an index does not guarantee that a query will use it or become faster.

Quick summary
Disadvantage	Effect
Extra storage	Requires additional disk space
INSERT overhead	Indexes must be updated
UPDATE overhead	Indexed values may need index updates
DELETE overhead	Index entries must be removed
Maintenance cost	Requires additional database resources
Too many indexes	Can increase overall workload
Not always useful	Optimizer may choose a table scan
Interview takeaway

The main disadvantage of indexes is the read-performance vs write-cost trade-off: indexes can make queries faster, but they consume storage and add overhead to INSERT, UPDATE, DELETE, and index maintenance. Therefore, indexes should be created selectively based on real query patterns.
