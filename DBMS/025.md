25.Why can adding more indexes make writes slower?
Indexes improve read performance, but they also have to be maintained whenever the underlying table changes.

Example

Suppose we have:

users
---------------------------
id | name | email | city

And we create three indexes:

Index 1 → id
Index 2 → email
Index 3 → city

Now when we insert a new row:

INSERT INTO users
VALUES (101, 'Aaman', 'aaman@example.com', 'Gorakhpur');

The database must:

Insert the row into the table.
Add the corresponding entry to the id index.
Add an entry to the email index.
Add an entry to the city index.

Conceptually:

INSERT
  │
  ├── Update table
  ├── Update index 1
  ├── Update index 2
  └── Update index 3

So, the more indexes that are affected by a write, the more index-maintenance work the database may have to perform.

UPDATE can be even more expensive

Consider:

UPDATE users
SET email = 'new@example.com'
WHERE id = 101;

If email is indexed, the database has to maintain the index entry corresponding to the changed value.

For an update that changes multiple indexed columns, multiple indexes may need maintenance.

DELETE also requires maintenance

When a row is deleted:

DELETE FROM users
WHERE id = 101;

the database must remove the corresponding entries from the relevant indexes as well.

What costs are involved?

Additional indexes can increase:

CPU work — maintaining index structures.
Disk I/O — writing index changes.
Memory/cache pressure — indexes consume buffer/cache space.
Storage — each index requires additional space.
Locking/contention — depending on the DBMS and workload.
Important nuance

It doesn't mean:

"Every additional index makes every write slower by the same amount."

The actual impact depends on:

Which indexes are affected
Index type and structure
Number of indexes
Table size
Write frequency
Database engine
Hardware and workload
Interview example

If a table has 8 indexes, an insert may require maintaining the table plus several index structures. If only 2 indexes are actually useful for the application's queries, the other 6 may provide little read benefit while still imposing maintenance cost.

That's why production systems generally aim for useful indexes rather than maximum indexes.

Interview takeaway

Adding indexes can make writes slower because every INSERT, UPDATE, or DELETE may need to update the affected index structures. More indexes therefore mean more maintenance work, storage, CPU, and potentially I/O, creating a read-performance vs write-performance trade-off.
