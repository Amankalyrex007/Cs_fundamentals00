1.What is Object-Oriented Programming and why is it used?
Answer

Object-Oriented Programming (OOP) is a programming paradigm that organizes software around objects, rather than only around functions and procedures.

An object represents an entity that contains:

State → data/attributes of the object
Behavior → functions/methods that operate on that data

For example, in a banking application, a BankAccount object might contain:

State:
    accountNumber
    balance
    accountHolder

Behavior:
    deposit()
    withdraw()
    checkBalance()

So instead of keeping data and the functions that operate on it completely separate, OOP groups related data and behavior together.

Why is OOP used?

OOP is mainly used to make large software systems easier to design, understand, maintain, reuse, and extend.

Consider a large application such as an e-commerce system. It may contain:

Customer
Product
ShoppingCart
Order
Payment
Delivery

Each can be represented as an object with its own data and behavior. This makes the system easier to divide into manageable components.

The major reasons for using OOP are:

Encapsulation
Keeps related data and methods together and can restrict direct access to internal data.
Abstraction
Exposes the important functionality while hiding unnecessary implementation details.
Inheritance
Allows a class to reuse or extend the properties and behavior of another class.
Polymorphism
Allows the same interface or method call to behave differently depending on the object.

These are commonly called the four fundamental principles of OOP.

Simple Example
class BankAccount:
    def __init__(self, balance):
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def get_balance(self):
        return self.balance


account = BankAccount(1000)

account.deposit(500)

print(account.get_balance())

Here:

BankAccount is a class.
account is an object of that class.
balance represents the object's state.
deposit() and get_balance() represent its behavior.

The class provides a reusable blueprint for creating multiple bank-account objects.

What problem does OOP solve?

Without a suitable organizational approach, a large program can become difficult to maintain because data and operations become scattered throughout the code.

OOP helps create modular components with clearly defined responsibilities.

For example:

Order
 ├── order_id
 ├── items
 ├── calculate_total()
 └── cancel()

Payment
 ├── amount
 ├── payment_method
 └── process_payment()

A change in payment-related logic can generally be isolated within the payment-related component rather than being spread throughout the entire application.

When is OOP useful?

OOP is particularly useful when:

The application is large or complex.
The system contains many interacting entities.
Code needs to be reused.
Multiple developers work on the same codebase.
The software is expected to evolve over time.
The domain can naturally be modeled using objects and their relationships.

However, OOP is not automatically the best approach for every problem. Simple scripts or problems that are naturally expressed as a sequence of transformations may not need elaborate class hierarchies.

Common Mistakes

1. "OOP means everything must be a class."
Not necessarily. The usefulness of classes and objects depends on the problem and programming language.

2. "Inheritance is the main purpose of OOP."
No. Encapsulation, abstraction, polymorphism, and object-based organization are also important.

3. "OOP always makes code better."
No. Poorly designed class hierarchies can make software more complicated. OOP should be used where its abstraction and modularity provide value.

Interview Takeaway

OOP is a programming paradigm that organizes software around objects containing state and behavior. It is used to improve modularity, maintainability, reuse, and extensibility through concepts such as encapsulation, abstraction, inheritance, and polymorphism.
