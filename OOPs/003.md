# Q3. What Is a Class and What Is an Object?

## What Is a Class?

A **class** is a blueprint or template that defines the **data (attributes)** and **behavior (methods)** that objects of that type can have.

In simple terms:

> **A class describes what an object should contain and what it should be able to do.**

For example, a `Student` class might define:

```text
Student
│
├── Attributes
│   ├── name
│   └── age
│
└── Methods
    └── introduce()
```

The class itself represents the general concept of a student. It does not represent one particular student.

---

# What Is an Object?

An **object** is a specific **instance of a class**.

An object has:

* Its own **state** — actual values of its attributes
* Access to the **behavior** defined by its class

For example:

```text
Student class
      │
      ├──────────────┬──────────────┐
      ▼              ▼              ▼
  student1       student2       student3
   Aman            Rahul           Priya
    20              21              19
```

All three objects are created from the same `Student` class, but each object has its own state.

---

# Simple Way to Remember

The easiest way to remember the difference is:

```text
Class  = Blueprint
Object = Actual instance created from the blueprint
```

### Real-World Analogy

Think about a **house blueprint**.

The blueprint specifies:

```text
Number of rooms
Doors
Windows
Structure
```

But the blueprint itself is not a particular house.

Using the blueprint, we can construct multiple houses:

```text
                 Blueprint
                    │
              ┌─────┼─────┐
              ▼     ▼     ▼
           House 1 House 2 House 3
```

Therefore:

```text
Blueprint → Class

House 1 → Object
House 2 → Object
House 3 → Object
```

Each house follows the same general design but can have different properties, such as:

* Wall color
* Furniture
* Owner
* Interior design

The same idea applies to classes and objects.

---

# Example in Python

Consider a `Student` class:

```python
class Student:

    def __init__(self, name, age):
        self.name = name
        self.age = age

    def introduce(self):
        print(f"My name is {self.name}")
```

Here:

```text
Student → Class
```

The class defines:

```text
Attributes:
    name
    age

Behavior:
    introduce()
```

---

# Creating Objects

We can create objects from the `Student` class:

```python
student1 = Student("Aman", 20)
student2 = Student("Rahul", 21)
```

Here:

```text
Student
   │
   ├── student1
   │
   └── student2
```

`student1` and `student2` are **two different objects** created from the same class.

---

# Calling Methods on Objects

We can call the `introduce()` method using each object:

```python
student1.introduce()
student2.introduce()
```

### Output

```text
My name is Aman
My name is Rahul
```

The same method exists in the class, but each object operates using its own state.

---

# Understanding the Example

Let's break down the code.

## Class

```python
class Student:
```

`Student` is the **class**.

It defines the structure and behavior that Student objects can have.

---

## Constructor

```python
def __init__(self, name, age):
```

`__init__()` is a special method in Python that is commonly used to initialize an object's state when the object is created.

For example:

```python
student1 = Student("Aman", 20)
```

The values:

```text
name = "Aman"
age  = 20
```

are used to initialize the new object's attributes.

---

## Attributes

```python
self.name = name
self.age = age
```

These represent the object's **state**.

For example:

```text
student1
├── name = "Aman"
└── age  = 20
```

While:

```text
student2
├── name = "Rahul"
└── age  = 21
```

The objects have the same structure but different values.

---

## Method

```python
def introduce(self):
    print(f"My name is {self.name}")
```

`introduce()` is a **method**.

A method represents behavior that an object can perform.

---

# Class vs Object

| Aspect       | Class                               | Object                              |
| ------------ | ----------------------------------- | ----------------------------------- |
| **Meaning**  | Blueprint/template                  | Instance of a class                 |
| **Purpose**  | Defines structure and behavior      | Represents a concrete entity        |
| **Contains** | Attribute definitions and methods   | Actual state and access to behavior |
| **Example**  | `Student`                           | `student1`                          |
| **Number**   | One class can create many objects   | Each object is a separate instance  |
| **State**    | Defines what state objects can have | Contains actual state values        |

# Class and Object Relationship

The relationship can be visualized as:

```text
                    Class
                  Student
                     │
          ┌──────────┼──────────┐
          │          │          │
          ▼          ▼          ▼
      student1   student2   student3
        │           │           │
        ▼           ▼           ▼
      Aman        Rahul       Priya
       20           21          19
```

The class defines the common structure.

Each object stores its own values.

---

# One Class Can Create Many Objects

One of the important advantages of classes is that we can create many objects from the same class.

For example:

```python
student1 = Student("Aman", 20)
student2 = Student("Rahul", 21)
student3 = Student("Priya", 19)
student4 = Student("Neha", 22)
```

All of them belong to the same class:

```text
Student
   │
   ├── student1
   ├── student2
   ├── student3
   └── student4
```

But each object has its own state:

```text
student1 → Aman, 20
student2 → Rahul, 21
student3 → Priya, 19
student4 → Neha, 22
```

This allows the same design to be reused for many entities.

# Real-World Example: E-Commerce

Consider an e-commerce application.

We could define a `Product` class:

```python
class Product:

    def __init__(self, name, price):
        self.name = name
        self.price = price
```

Then create many product objects:

```python
product1 = Product("Laptop", 50000)
product2 = Product("Phone", 30000)
product3 = Product("Headphones", 5000)
```

The relationship looks like:

```text
                 Product
                   │
          ┌────────┼────────┐
          ▼        ▼        ▼
       product1 product2 product3
          │        │        │
       Laptop     Phone   Headphones
       ₹50,000    ₹30,000   ₹5,000
```

The class provides a reusable structure for representing products.

An actual application could create thousands or millions of product objects depending on its architecture and data model.

# Class as a Blueprint

A class can be thought of as a **design specification**.

For example:

```text
Student Class
│
├── name
├── age
└── introduce()
```

It tells us:

> A Student object should have a name, an age, and the ability to introduce itself.

But it does not represent a particular student.

The actual objects contain concrete values:

```text
student1
├── name = "Aman"
└── age = 20

student2
├── name = "Rahul"
└── age = 21
```

---

# Object Has Its Own State

Objects created from the same class can have different states.

For example:

```python
student1 = Student("Aman", 20)
student2 = Student("Rahul", 21)
```

Both are `Student` objects:

```text
type(student1) → Student
type(student2) → Student
```

But their states are different:

```text
student1.name → "Aman"
student1.age  → 20

student2.name → "Rahul"
student2.age  → 21
```

This distinction is important:

> **The class defines the structure; each object contains its own actual state.**

---

# Why Is the Class-Object Distinction Important?

Classes allow us to define a concept **once** and then create many objects from that definition.

Without this approach, we might have to repeatedly write the same structure for every entity.

For example, an e-commerce application may have:

```text
Product
   │
   ├── P1
   ├── P2
   ├── P3
   ├── P4
   └── ...
```

The `Product` class provides the common structure, while each product object contains its own data.

This supports:

* **Reusability**
* **Organization**
* **Modularity**
* **Consistency**

# Common Mistakes

## Mistake 1: "A class and an object are the same thing."

No.

A **class** is a blueprint/template.

An **object** is an actual instance created from that blueprint.

```text
Class  → Student
Object → student1
```

---

## Mistake 2: "One class can create only one object."

No.

A single class can be used to create many objects.

```python
student1 = Student("Aman", 20)
student2 = Student("Rahul", 21)
student3 = Student("Priya", 19)
```

All three are instances of `Student`.

---

## Mistake 3: "All objects of a class have the same values."

No.

Objects created from the same class generally share the same **structure and behavior**, but they can have different state.

```text
student1 → Aman, 20
student2 → Rahul, 21
```

---

## Mistake 4: "A class always means memory is allocated for one object."

This depends on the programming language and implementation.

A class defines a type/structure, while object creation creates instances. Details such as memory allocation and object representation are language-specific.

Therefore, memory-related explanations should be given in the context of the particular programming language.

# Important Terms

| Term          | Meaning                                         |
| ------------- | ----------------------------------------------- |
| **Class**     | Blueprint/template for creating objects         |
| **Object**    | Concrete instance of a class                    |
| **Attribute** | Data associated with an object                  |
| **Method**    | Function defined as part of a class             |
| **State**     | Current values of an object's attributes        |
| **Behavior**  | Operations an object can perform                |
| **Instance**  | Another term for an object created from a class |

# Interview Takeaway

> **A class is a blueprint or template that defines the attributes and methods that objects of that type can have. An object is a concrete instance of a class with its own state. One class can be used to create many objects, and each object can have different attribute values while sharing the behavior defined by the class.**
