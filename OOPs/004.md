4.What is encapsulation?
Answer

Encapsulation is the OOP concept of bundling data and the methods that operate on that data into a single unit, usually a class, while controlling access to the internal state.

The main idea is:

Keep an object's internal state protected and provide controlled ways to interact with it.

Why do we need encapsulation?

Without encapsulation, other parts of a program could directly modify an object's internal data in invalid ways.

For example, suppose a bank account has a balance:

class BankAccount:
    def __init__(self, balance):
        self.balance = balance

Anyone could potentially do:

account.balance = -50000

This may violate the rules of a bank account.

With encapsulation, we can control how the balance changes:

class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount

    def get_balance(self):
        return self.__balance

Now the balance is intended to be accessed and modified through controlled methods such as deposit() and withdraw().

How does encapsulation work?

Encapsulation generally involves two ideas:

Bundling — keeping related data and behavior together inside a class.
Access control — controlling how outside code can access or modify the internal data.

Different programming languages provide different mechanisms for access control.

For example, Python uses naming conventions and mechanisms such as:

self.name       # public
self._name      # conventionally internal/protected
self.__name     # name-mangled attribute

Languages such as Java and C++ also provide explicit access modifiers such as private, protected, and public.

Real-world analogy

Think of an ATM.

You can perform operations such as:

Withdraw money
Deposit money
Check balance

But you don't directly manipulate the bank's internal database.

The ATM provides a controlled interface to the underlying system.

Similarly, an object can expose specific methods while keeping its internal implementation and state controlled.

Benefits of Encapsulation
Data protection — prevents uncontrolled modification of internal state.
Maintainability — internal implementation can change without necessarily changing how users interact with the class.
Validation — methods can validate input before modifying state.
Modularity — related data and operations stay together.
Reduced coupling — other parts of the program depend on the object's interface rather than its internal implementation.
Common Mistake

Encapsulation is not simply "making variables private."

Private/protected access is one mechanism for achieving encapsulation. The broader idea is controlling access to an object's state and exposing a well-defined interface.

Also, encapsulation and abstraction are related but different:

Encapsulation → controls/bundles data and behavior.
Abstraction → hides unnecessary implementation complexity and exposes the essential interface.
Interview Takeaway

Encapsulation is the OOP principle of bundling data and the methods that operate on it inside a class and controlling access to the object's internal state. It helps protect data, enforce valid state changes, reduce coupling, and make code easier to maintain.
