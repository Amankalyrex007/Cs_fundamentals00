# Q6. What Is Inheritance?

## Definition

**Inheritance** is an OOP mechanism in which a new class, called a **child/subclass**, derives properties and behaviors from an existing class, called a **parent/superclass**.

The main idea is:

> **Create a new class by reusing and extending the functionality of an existing class.**

Inheritance is useful when multiple classes share common characteristics or behavior.

---

## Simple Example

```python
class Animal:

    def eat(self):
        print("Animal is eating")


class Dog(Animal):

    def bark(self):
        print("Dog is barking")


dog = Dog()

dog.eat()    # inherited from Animal
dog.bark()  # defined in Dog
```

### What is happening here?

```text
Animal
   │
   └── Dog
```

* `Animal` → **Parent/Base/Superclass**
* `Dog` → **Child/Derived/Subclass**
* `eat()` → inherited by `Dog`
* `bark()` → specifically defined inside `Dog`

The `Dog` class can use `eat()` without redefining it.

This is one of the main benefits of inheritance: **reuse of existing functionality**.

---

# Why Is Inheritance Used?

Inheritance is mainly used for the following reasons:

### 1. Code Reuse

Common functionality can be implemented once in the parent class.

```python
class Animal:

    def eat(self):
        print("Eating")

    def sleep(self):
        print("Sleeping")


class Dog(Animal):
    pass


dog = Dog()

dog.eat()
dog.sleep()
```

The `Dog` class automatically receives the behavior defined in `Animal`.

---

### 2. Extensibility

A child class can add its own attributes and methods.

```python
class Animal:

    def eat(self):
        print("Eating")


class Dog(Animal):

    def bark(self):
        print("Barking")
```

Here:

* `Animal` provides common behavior.
* `Dog` adds specialized behavior.

```text
Animal
  │
  └── Dog
       └── bark()
```

---

### 3. Hierarchical Modeling

Inheritance can represent an **"is-a" relationship** between classes.

For example:

```text
             Animal
            /   |   \
           /    |    \
        Dog    Cat   Bird
```

The relationship can be described as:

```text
Dog is an Animal
Cat is an Animal
Bird is an Animal
```

This makes inheritance a natural choice when the relationship between types genuinely represents specialization.

---

# Method Overriding

A child class can provide its own implementation of a method that it inherits from the parent class.

This is called **method overriding**.

### Example

```python
class Animal:

    def speak(self):
        print("Some sound")


class Dog(Animal):

    def speak(self):
        print("Bark")


class Cat(Animal):

    def speak(self):
        print("Meow")
```

Now:

```python
Dog().speak()  # Bark
Cat().speak()  # Meow
```

Both `Dog` and `Cat` inherit from `Animal`, but each provides its own implementation of `speak()`.

```text
             Animal
                │
          speak() method
             /     \
            /       \
         Dog         Cat
          │           │
       "Bark"       "Meow"
```

This is closely related to **polymorphism**, another major concept in OOP.

---

# Inheritance and Polymorphism

Inheritance and polymorphism are related, but they are **not the same thing**.

### Inheritance

Describes a relationship between classes.

```text
Dog → Animal
```

It answers:

> **"What type of relationship exists between these classes?"**

### Polymorphism

Allows objects of different types to be used through a common interface.

For example:

```python
animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()
```

Output:

```text
Bark
Meow
```

The same method call:

```python
animal.speak()
```

produces different behavior depending on the actual object.

---

# Types of Inheritance

Common forms of inheritance include:

| Type                         | Meaning                                                               |
| ---------------------------- | --------------------------------------------------------------------- |
| **Single Inheritance**       | One child inherits from one parent                                    |
| **Multilevel Inheritance**   | A class inherits from a class that itself inherits from another class |
| **Hierarchical Inheritance** | Multiple child classes inherit from the same parent                   |
| **Multiple Inheritance**     | One child class inherits from multiple parents                        |
| **Hybrid Inheritance**       | Combination of multiple inheritance patterns                          |

The availability and implementation of these forms depend on the programming language.

---

## 1. Single Inheritance

One child class inherits from one parent class.

```text
Animal
   │
   ↓
  Dog
```

Example:

```python
class Animal:
    def eat(self):
        print("Eating")


class Dog(Animal):
    pass
```

---

## 2. Multilevel Inheritance

A class inherits from another class, which itself inherits from another class.

```text
Animal
   │
   ↓
 Mammal
   │
   ↓
  Dog
```

Example:

```python
class Animal:
    def eat(self):
        print("Eating")


class Mammal(Animal):
    def walk(self):
        print("Walking")


class Dog(Mammal):
    def bark(self):
        print("Barking")
```

Now `Dog` can access behavior from both `Mammal` and `Animal`.

```python
dog = Dog()

dog.eat()
dog.walk()
dog.bark()
```

---

## 3. Hierarchical Inheritance

Multiple child classes inherit from the same parent.

```text
          Animal
         /      \
        ↓        ↓
      Dog       Cat
```

Example:

```python
class Animal:
    def eat(self):
        print("Eating")


class Dog(Animal):
    def bark(self):
        print("Barking")


class Cat(Animal):
    def meow(self):
        print("Meowing")
```

Both `Dog` and `Cat` reuse the common behavior from `Animal`.

---

## 4. Multiple Inheritance

One child class inherits from multiple parent classes.

```text
    A       B
     \     /
      \   /
        C
```

Python supports multiple inheritance.

```python
class A:
    pass


class B:
    pass


class C(A, B):
    pass
```

Here, `C` inherits from both `A` and `B`.

> **Note:** Multiple inheritance can introduce complexity, especially when parent classes provide methods with the same names. Languages handle this differently.

---

## 5. Hybrid Inheritance

Hybrid inheritance is a combination of multiple inheritance patterns.

For example:

```text
          A
         / \
        B   C
         \ /
          D
```

The exact implementation and behavior depend on the programming language.

---

# Using `super()`

In Python, `super()` can be used to access functionality from a parent class.

### Example

```python
class Animal:

    def __init__(self, name):
        self.name = name


class Dog(Animal):

    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed


dog = Dog("Buddy", "Labrador")

print(dog.name)
print(dog.breed)
```

Output:

```text
Buddy
Labrador
```

Here:

```python
super().__init__(name)
```

calls the parent class's initializer.

This allows the child class to **reuse parent initialization logic** instead of duplicating it.

---

# Inheritance vs Composition

Inheritance should **not** automatically be used whenever code needs reuse.

Consider this relationship:

```text
Car → Engine
```

A car **has an engine**.

A car is **not an engine**.

Therefore, composition is generally a more natural model:

```python
class Engine:

    def start(self):
        print("Engine started")


class Car:

    def __init__(self):
        self.engine = Engine()
```

Now:

```python
car = Car()

car.engine.start()
```

The `Car` object contains an `Engine` object.

---

## "Is-A" vs "Has-A"

A useful design guideline is:

```text
"is-a"   → potentially inheritance

"has-a"  → potentially composition
```

### Example

```text
Dog is an Animal
        ↓
   Inheritance
```

```text
Car has an Engine
        ↓
   Composition
```

However, this is a **design guideline, not an absolute rule**. The best choice depends on the relationship, responsibilities, coupling, and how the system is expected to evolve.

---

# Inheritance vs Composition

| Feature         | Inheritance                          | Composition                            |
| --------------- | ------------------------------------ | -------------------------------------- |
| Relationship    | **Is-a**                             | **Has-a**                              |
| Main idea       | Derive one type from another         | Build objects using other objects      |
| Code reuse      | Through parent class                 | Through contained objects              |
| Coupling        | Often tighter                        | Often more flexible                    |
| Example         | `Dog → Animal`                       | `Car → Engine`                         |
| Best suited for | Genuine specialization relationships | Components that can vary independently |

A common software-design principle is:

> **Prefer composition over inheritance when inheritance does not represent a strong, meaningful type relationship.**

---

# Common Mistakes

## 1. Thinking Inheritance Is Only About Code Reuse

Inheritance can provide code reuse, but it does more than that.

It also establishes a relationship between types and can affect:

* Substitutability
* Coupling
* Class hierarchy
* Method overriding
* Overall system design

Therefore, inheritance should be chosen because the relationship makes sense, not merely because it avoids duplicated code.

---

## 2. Using Inheritance Everywhere

Large or deeply nested inheritance hierarchies can make software difficult to understand and modify.

For example:

```text
A
│
└── B
    │
    └── C
        │
        └── D
            │
            └── E
                │
                └── F
```

A change in a parent class may affect many subclasses.

Composition can sometimes provide a simpler and more flexible alternative.

---

## 3. Confusing Inheritance with Polymorphism

Remember:

```text
Inheritance  → relationship between classes

Polymorphism → common interface with different behavior
```

Inheritance can support polymorphism, but they are separate concepts.

---

## 4. Creating Inheritance Just Because Classes Share Code

Suppose two classes both need a logging function.

That does not automatically mean:

```text
Class A
   ↑
Class B
```

Inheritance should represent a meaningful relationship, not simply shared implementation.

A shared utility or composition may be more appropriate.

---

# Real-World Example: Payment System

Consider an online payment application.

A general payment class might define common behavior:

```python
class Payment:

    def process(self):
        print("Processing payment")
```

Specialized payment classes can inherit from it:

```python
class CreditCardPayment(Payment):

    def pay(self):
        print("Paid using credit card")


class UPIPayment(Payment):

    def pay(self):
        print("Paid using UPI")
```

The hierarchy can be represented as:

```text
             Payment
             /     \
            /       \
           ↓         ↓
    CreditCard      UPI
      Payment      Payment
```

The child classes can reuse common functionality while adding specialized behavior.

---

# Advantages of Inheritance

Inheritance can provide several benefits when used appropriately:

### 1. Code Reuse

Common behavior can be implemented once.

### 2. Extensibility

Child classes can add specialized functionality.

### 3. Maintainability

Shared behavior can be maintained in a common parent class.

### 4. Hierarchical Modeling

It can naturally represent relationships between related types.

### 5. Polymorphism Support

Inheritance can allow different subclasses to be handled through a common parent type or interface.

---

# Disadvantages of Inheritance

Inheritance also introduces potential problems.

### 1. Tight Coupling

Child classes depend on the parent class.

### 2. Fragile Hierarchies

Changes to a parent class can affect many subclasses.

### 3. Deep Hierarchies

Very large inheritance trees can become difficult to understand.

### 4. Reduced Flexibility

A class may be forced into a hierarchy that does not fit its actual responsibilities.

This is why **composition is often considered as an alternative to inheritance**.

              Child 1  Child 2  Child 3
                 │        │        │

The general idea is:

```text
Parent
  │
  ├── Common behavior
  │
  └── Child
        │
        ├── Inherited behavior
        │
        └── New/overridden behavior
```

# Key Terms

| Term                     | Meaning                                               |
| ------------------------ | ----------------------------------------------------- |
| **Inheritance**          | Mechanism for deriving a class from another class     |
| **Parent Class**         | Class whose members are inherited                     |
| **Child Class**          | Class that inherits from another class                |
| **Base Class**           | Another name for parent class                         |
| **Derived Class**        | Another name for child class                          |
| **Method Overriding**    | Providing a new implementation of an inherited method |
| **`super()`**            | Python mechanism for accessing parent-class behavior  |
| **Single Inheritance**   | One child inherits from one parent                    |
| **Multiple Inheritance** | One child inherits from multiple parents              |
| **Composition**          | Building objects using other objects                  |
| **Is-a Relationship**    | Relationship commonly modeled using inheritance       |
| **Has-a Relationship**   | Relationship commonly modeled using composition       |

# Interview Takeaway

> **Inheritance is an OOP mechanism in which a child class derives attributes and methods from a parent class. It promotes reuse and extensibility, supports appropriate "is-a" relationships, and can enable polymorphism through method overriding. However, inheritance should be used carefully because deep or inappropriate hierarchies can create tight coupling, and composition may provide a more flexible design.**

### Common Interview Follow-Up

**Q: What is the difference between inheritance and composition?**

**Answer:**

> **Inheritance represents an "is-a" relationship, while composition represents a "has-a" relationship.** Inheritance derives one class from another, whereas composition builds an object by containing other objects. Composition is often preferred when the relationship does not represent genuine specialization.
