7.What is polymorphism?
Answer

Polymorphism means "many forms." In OOP, it refers to the ability to use a common interface or method name while allowing different types of objects to provide different behavior.

A simple way to remember it:

Same interface → different behavior

Polymorphism is particularly useful when different objects share a common operation but implement that operation differently.

Simple Example

Consider different animals:

class Dog:
    def speak(self):
        print("Bark")


class Cat:
    def speak(self):
        print("Meow")

Both classes provide a speak() method, but the behavior is different.

We can use them through the same interface:

animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()

Output:

Bark
Meow

The code calls:

animal.speak()

without needing to know whether animal is a Dog or a Cat.

That's the key idea behind polymorphism.

Why is polymorphism useful?

Suppose an application supports multiple payment methods:

Payment
 ├── CreditCardPayment
 ├── UPIPayment
 └── PayPalPayment

Each payment type can implement:

pay(amount)

The application can then work with a common interface:

for payment in payments:
    payment.pay(amount)

The calling code doesn't need separate logic such as:

if payment_type == "UPI":
    ...
elif payment_type == "card":
    ...
elif payment_type == "paypal":
    ...

This can make systems more extensible and easier to maintain.

Polymorphism through Method Overriding

A common form of polymorphism occurs when a subclass overrides a method inherited from a parent class.

class Animal:
    def speak(self):
        print("Some sound")


class Dog(Animal):
    def speak(self):
        print("Bark")


class Cat(Animal):
    def speak(self):
        print("Meow")

Now:

animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()

Each object responds to the same method call according to its own implementation.

This is often described as runtime polymorphism.

Common Forms of Polymorphism

The exact terminology varies by programming language, but commonly discussed forms include:

1. Runtime polymorphism

The behavior is determined based on the actual object at runtime.

Example:

animal.speak()

A Dog and a Cat can provide different implementations of speak().

2. Compile-time polymorphism

In languages that support it, methods can have the same name but different parameter lists. This is commonly called method overloading.

For example, in a language such as Java:

add(int a, int b)
add(int a, int b, int c)

The compiler determines which method to call based on the arguments.

Important: Python does not support traditional method overloading in the same way Java or C++ does. Therefore, explanations of polymorphism should be made in the context of the language being discussed.

Polymorphism vs Inheritance

These concepts are related but different:

Concept	Meaning
Inheritance	Allows a class to derive behavior/data from another class
Polymorphism	Allows different objects to respond differently to a common interface

Inheritance can be used to establish a common type hierarchy, after which polymorphism can allow different subclasses to provide different implementations.

However, polymorphism does not necessarily require classical inheritance. Interfaces, protocols, or duck typing can also provide polymorphic behavior depending on the language.

Real-World Example

Imagine a Notification system:

Notification
 ├── EmailNotification
 ├── SMSNotification
 └── PushNotification

Each type provides:

send(message)

The application can simply do:

notification.send(message)

The actual implementation depends on the object:

EmailNotification → Send email
SMSNotification   → Send SMS
PushNotification  → Send push notification

The application therefore depends on the common interface, rather than hard-coding the details of every notification type.

Common Mistake

Polymorphism does not simply mean "one method with many names."

The important idea is that different objects can be treated through a common interface while providing type-specific behavior.

Also, method overloading and method overriding are not the same:

Overloading → same method name, different parameter signatures (where the language supports it).
Overriding → a subclass provides a different implementation of an inherited method.
Interview Takeaway

Polymorphism is the ability to use a common interface for different types of objects while allowing each object to provide its own behavior. A common example is method overriding, where different subclasses implement the same method differently.
