# Q7. What Is Polymorphism?

## Definition

**Polymorphism** means **"many forms."**

In OOP, polymorphism refers to the ability to use a **common interface or method name** while allowing different types of objects to provide **different behavior**.

A simple way to remember it:

> **Same interface → Different behavior**

Polymorphism is particularly useful when different objects support the same operation but implement that operation differently.

---

# Simple Example

Consider different animals.

```python
class Dog:

    def speak(self):
        print("Bark")


class Cat:

    def speak(self):
        print("Meow")
```

Both classes provide the same method:

```python
speak()
```

But their behavior is different.

We can use both objects through the same interface:

```python
animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()
```

### Output

```text
Bark
Meow
```

The code simply calls:

```python
animal.speak()
```

without needing to know whether `animal` is a `Dog` or a `Cat`.

That is the key idea behind polymorphism.

---

# How Polymorphism Works

The basic concept can be visualized as:

```text
                 Common Interface
                  speak()
                     │
             ┌───────┴───────┐
             ↓               ↓
           Dog              Cat
             │               │
             ↓               ↓
           Bark             Meow
```

The caller uses:

```python
animal.speak()
```

The actual behavior depends on the object.

```text
Dog object → speak() → Bark
Cat object → speak() → Meow
```

The calling code does not need separate logic for every type.

---

# Why Is Polymorphism Useful?

Polymorphism helps make software more:

* **Flexible**
* **Extensible**
* **Maintainable**
* **Modular**
* **Less dependent on concrete implementations**

The main advantage is that code can work with a **common interface** instead of being tightly coupled to specific object types.

---

# Real-World Example: Payment System

Suppose an application supports several payment methods.

```text
                    Payment
                  /    |     \
                 /     |      \
                ↓      ↓       ↓
        Credit Card   UPI    PayPal
```

Each payment type provides:

```python
pay(amount)
```

For example:

```python
class CreditCardPayment:

    def pay(self, amount):
        print(f"Paid ₹{amount} using Credit Card")


class UPIPayment:

    def pay(self, amount):
        print(f"Paid ₹{amount} using UPI")


class PayPalPayment:

    def pay(self, amount):
        print(f"Paid ₹{amount} using PayPal")
```

The application can work with all of them through the same method:

```python
payments = [
    CreditCardPayment(),
    UPIPayment(),
    PayPalPayment()
]

for payment in payments:
    payment.pay(1000)
```

The calling code does not need to write:

```python
if payment_type == "UPI":
    ...

elif payment_type == "card":
    ...

elif payment_type == "paypal":
    ...
```

Instead, it simply uses:

```python
payment.pay(amount)
```

This makes the system easier to extend.

For example, adding:

```text
BitcoinPayment
```

or another supported payment implementation can be done without changing the basic calling logic, provided it follows the expected interface.

# Polymorphism Through Method Overriding

A common form of polymorphism occurs when a subclass **overrides** a method inherited from a parent class.

Consider:

```python
class Animal:

    def speak(self):
        print("Some sound")


class Dog(Animal):

    def speak(self):
        print("Bark")


class Cat(Animal):

    def speak(self):
        print("Meow")
```

Now:

```python
animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()
```

Output:

```text
Bark
Meow
```

Each object responds to the same method call:

```python
animal.speak()
```

but provides its own implementation.

This is commonly described as **runtime polymorphism**.

---

# Runtime Polymorphism

In runtime polymorphism, the behavior is determined based on the **actual object at runtime**.

For example:

```python
animal.speak()
```

The variable `animal` could refer to:

```text
Dog object
     ↓
speak() → Bark
```

or:

```text
Cat object
     ↓
speak() → Meow
```

The actual implementation is selected according to the object being used.

---

# Compile-Time Polymorphism

In languages that support it, methods can have the same name but different parameter lists.

This is commonly called **method overloading**.

For example, in Java:

```java
add(int a, int b)

add(int a, int b, int c)
```

The compiler can determine which method to call based on the arguments.

Conceptually:

```text
add(10, 20)
   ↓
add(int, int)
```

while:

```text
add(10, 20, 30)
   ↓
add(int, int, int)
```

### Important Language Difference

The exact meaning of compile-time and runtime polymorphism depends on the programming language.

For example:

* **Java/C++** commonly support method overloading.
* **Python** does not support traditional method overloading in the same way.
* Python can instead use techniques such as default arguments, `*args`, `**kwargs`, or other forms of dynamic dispatch.

Therefore, polymorphism should always be explained in the context of the language being discussed.

---

# Method Overloading vs Method Overriding

These two concepts are often confused.

| Concept                     | Meaning                                                                          |
| --------------------------- | -------------------------------------------------------------------------------- |
| **Method Overloading**      | Same method name with different parameter lists, where supported by the language |
| **Method Overriding**       | A subclass provides a different implementation of an inherited method            |
| **Usually associated with** | Overloading → compile-time mechanisms; overriding → runtime polymorphism         |

### Example of Overloading

```text
add(int, int)
add(int, int, int)
```

Same method name, different parameters.

### Example of Overriding

```text
Animal.speak()
       ↓
Dog.speak()
```

The child class provides its own implementation.

---

# Polymorphism vs Inheritance

Inheritance and polymorphism are closely related, but they are **not the same concept**.

| Concept          | Meaning                                                               |
| ---------------- | --------------------------------------------------------------------- |
| **Inheritance**  | Allows a class to derive behavior/data from another class             |
| **Polymorphism** | Allows different objects to respond differently to a common interface |

### Inheritance

Establishes a relationship:

```text
Dog → Animal
```

It answers:

> **"What relationship exists between these classes?"**

### Polymorphism

Allows different objects to respond differently:

```text
Dog.speak() → Bark
Cat.speak() → Meow
```

It answers:

> **"What behavior should occur when the common operation is used?"**

---

# Does Polymorphism Require Inheritance?

**Not necessarily.**

Polymorphic behavior can be achieved through different mechanisms depending on the programming language.

These can include:

* Classical inheritance
* Interfaces
* Protocols
* Duck typing
* Generic programming
* Function or operator overloading

For example, Python supports **duck typing**.

Consider:

```python
class Dog:

    def speak(self):
        print("Bark")


class Cat:

    def speak(self):
        print("Meow")


def make_sound(animal):
    animal.speak()
```

We can pass either object:

```python
make_sound(Dog())
make_sound(Cat())
```

Output:

```text
Bark
Meow
```

The function does not require both classes to inherit from the same parent.

It only requires that the object provide the expected operation:

```python
speak()
```

This demonstrates how polymorphism can exist without classical inheritance.

# Real-World Example: Notification System

Imagine an application that supports multiple notification methods.

```text
                 Notification
                /      |       \
               /       |        \
              ↓        ↓         ↓
           Email       SMS       Push
```

Each notification type provides:

```python
send(message)
```

For example:

```python
class EmailNotification:

    def send(self, message):
        print(f"Sending email: {message}")


class SMSNotification:

    def send(self, message):
        print(f"Sending SMS: {message}")


class PushNotification:

    def send(self, message):
        print(f"Sending push notification: {message}")
```

The application can use them through the same interface:

```python
notifications = [
    EmailNotification(),
    SMSNotification(),
    PushNotification()
]

for notification in notifications:
    notification.send("Hello!")
```

The application does not need to know the internal implementation of each notification type.

It only needs to know:

```python
notification.send(message)
```

---

# Polymorphism and Extensibility

One of the biggest benefits of polymorphism is that new implementations can often be added without changing the code that uses the common interface.

Suppose we already have:

```text
EmailNotification
SMSNotification
PushNotification
```

Later, we add:

```text
WhatsAppNotification
```

If it implements:

```python
send(message)
```

the existing loop can continue to work:

```python
for notification in notifications:
    notification.send(message)
```

This follows an important design idea:

> **Code should depend on abstractions/interfaces rather than unnecessary implementation details.**

---

# Operator Polymorphism

Polymorphism can also appear through operators.

For example, in Python:

```python
print(2 + 3)
```

produces:

```text
5
```

while:

```python
print("Hello " + "World")
```

produces:

```text
Hello World
```

The `+` operator behaves differently depending on the types of its operands.

Conceptually:

```text
2 + 3
  ↓
Numeric addition

"Hello " + "World"
  ↓
String concatenation
```

This is another example of the broader idea of **one operation having different behavior depending on the types involved**.

# Polymorphism in a Simple Diagram

```text
                  Common Interface
                       │
                  perform_action()
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
        Object A     Object B     Object C
          │            │            │
          ↓            ↓            ↓
      Behavior A    Behavior B    Behavior C
```

The caller uses the same operation:

```text
perform_action()
```

but each object can respond differently.

# Common Mistakes

## 1. Thinking Polymorphism Means "One Method With Many Names"

This is not the main idea.

Polymorphism is about:

> **Different objects being usable through a common interface while providing type-specific behavior.**

---

## 2. Confusing Overloading and Overriding

Remember:

```text
Overloading
    ↓
Same method name
Different parameter lists
```

while:

```text
Overriding
    ↓
Subclass replaces inherited implementation
```

They are different mechanisms.

---

## 3. Thinking Polymorphism Always Requires Inheritance

Inheritance is one way to establish a common relationship, but polymorphism can also be achieved through:

* Interfaces
* Protocols
* Duck typing
* Generic mechanisms
* Other language-specific features

---

## 4. Thinking Polymorphism Means the Same Method Must Do Exactly the Same Thing

The whole point is that the same interface can result in **different appropriate behavior**.

For example:

```text
Dog.speak() → Bark
Cat.speak() → Meow
```

The method name is the same, but the implementation differs.

---

# Benefits of Polymorphism

### 1. Flexibility

The same code can work with different object types.

### 2. Extensibility

New implementations can often be added without changing existing calling code.

### 3. Maintainability

The calling code does not need to contain many type-specific conditions.

### 4. Reduced Coupling

Code can depend on a common interface rather than concrete implementations.

### 5. Cleaner Design

Polymorphism can replace large chains of conditional logic.

Instead of:

```python
if type == "email":
    ...
elif type == "sms":
    ...
elif type == "push":
    ...
```

we can use:

```python
notification.send(message)
```

# Polymorphism vs Inheritance vs Encapsulation vs Abstraction

| OOP Concept       | Main Idea                                  | Simple Question                                          |
| ----------------- | ------------------------------------------ | -------------------------------------------------------- |
| **Encapsulation** | Bundle and control access to data/behavior | How is internal state managed?                           |
| **Abstraction**   | Hide unnecessary implementation details    | What does the object expose?                             |
| **Inheritance**   | Derive one class from another              | What type relationship exists?                           |
| **Polymorphism**  | Same interface, different behavior         | How can different objects respond to the same operation? |

### Easy Memory Trick

```text
Encapsulation → Protect
Abstraction   → Hide
Inheritance   → Reuse/Extend
Polymorphism  → Many Forms
```

# Key Terms

| Term                          | Meaning                                                                                                  |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| **Polymorphism**              | Ability to represent the same operation through different behaviors                                      |
| **Runtime Polymorphism**      | Behavior is determined based on the actual object at runtime                                             |
| **Compile-Time Polymorphism** | Polymorphic behavior determined by compile-time mechanisms, such as overloading where supported          |
| **Method Overriding**         | Subclass provides its own implementation of an inherited method                                          |
| **Method Overloading**        | Same method name with different parameter lists, where supported                                         |
| **Common Interface**          | Set of operations through which different objects can be used                                            |
| **Duck Typing**               | Python-style approach where compatibility depends on supported behavior rather than explicit inheritance |
| **Dynamic Dispatch**          | Selecting the appropriate implementation based on the object being used                                  |

---

# Interview Takeaway

> **Polymorphism is the ability to use a common interface for different types of objects while allowing each object to provide its own behavior. A common example is method overriding, where different subclasses implement the same method differently. Polymorphism improves flexibility, extensibility, and maintainability by reducing dependence on concrete implementations.**

### Common Interview Follow-Up

**Q: What is the difference between inheritance and polymorphism?**

**Answer:**

> **Inheritance establishes a relationship between classes by allowing a child class to derive from a parent class, whereas polymorphism allows different objects to respond differently to a common interface. Inheritance can be used to support polymorphism, but polymorphism can also be achieved through interfaces, protocols, duck typing, and other language-specific mechanisms.**
