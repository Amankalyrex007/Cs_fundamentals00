8.Compile-time vs runtime polymorphism?
Answer

Compile-time polymorphism and runtime polymorphism are two commonly discussed forms of polymorphism.

The key difference is when the method to execute is determined:

Compile-time polymorphism → decision is made at compile time
Runtime polymorphism → decision is made at runtime

The repository guide recommends adapting the answer structure to the question and using comparisons where useful.

Comparison
Aspect	Compile-time polymorphism	Runtime polymorphism
Also commonly called	Static polymorphism	Dynamic polymorphism
Decision time	Compile time	Runtime
Common mechanism	Method/function overloading	Method overriding
Typical languages	Java, C++, C#	Java, C++, Python, etc.
Flexibility	More fixed	More dynamic
Example	Same method name with different parameters	Same method overridden by different subclasses
1. Compile-time Polymorphism

In compile-time polymorphism, the compiler determines which implementation should be used based on information available during compilation.

A common example is method overloading.

For example, in Java:

class Calculator {
    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}

The method name is the same:

add()

but the parameter lists are different.

The compiler can determine which method is intended from the arguments.

add(2, 3);       // two parameters
add(2, 3, 4);    // three parameters
Important: Python

Python does not support traditional method overloading in the same way Java or C++ does.

For example, defining:

class Calculator:
    def add(self, a, b):
        ...

    def add(self, a, b, c):
        ...

does not create two overloaded methods. The second definition replaces the first.

Python can achieve similar behavior using techniques such as default arguments, *args, or other dispatch mechanisms, but this is not traditional compile-time method overloading.

2. Runtime Polymorphism

In runtime polymorphism, the appropriate implementation is determined when the program is running.

A common mechanism is method overriding.

class Animal:
    def speak(self):
        print("Some sound")


class Dog(Animal):
    def speak(self):
        print("Bark")


class Cat(Animal):
    def speak(self):
        print("Meow")

Now:

animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()

Output:

Bark
Meow

The same method call:

animal.speak()

produces different behavior depending on the actual object.

animal → Dog → Dog.speak()
animal → Cat → Cat.speak()

This is runtime polymorphic behavior.

Why is runtime polymorphism useful?

Suppose an application supports different payment methods:

class Payment:
    def pay(self, amount):
        raise NotImplementedError


class UPI(Payment):
    def pay(self, amount):
        print("Paying using UPI")


class CreditCard(Payment):
    def pay(self, amount):
        print("Paying using credit card")

The application can work with the common interface:

def process_payment(payment):
    payment.pay(500)

It doesn't need separate logic for every payment type.

process_payment(UPI())
process_payment(CreditCard())

This makes it easier to add another implementation later, such as PayPal, without changing the calling code.

Key Difference

Think about when the decision happens:

Compile-time polymorphism
        ↓
Compiler determines method
        ↓
Program runs


Runtime polymorphism
        ↓
Program runs
        ↓
Actual object determines method
Common Mistake

Don't say:

"Compile-time polymorphism is always method overloading and runtime polymorphism is always method overriding."

These are common mechanisms, not universal definitions across every programming language. The exact terminology and mechanisms vary by language.

Also, Python's dynamic nature means it should not be explained using the same method-overloading model as Java or C++.

Interview Takeaway

Compile-time polymorphism is resolved during compilation, commonly through method overloading in languages that support it. Runtime polymorphism is resolved during execution, commonly through method overriding, where different objects provide different implementations of a common interface.

One-line memory trick:

Overloading → usually compile time
Overriding → usually runtime
