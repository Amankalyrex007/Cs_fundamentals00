# Q9. Method Overloading vs Method Overriding

## Definition

**Method overloading** and **method overriding** both allow the same method name to be associated with different behavior, but they work in different ways.

The simplest distinction is:

> **Overloading → Same method name, different parameter list**
> **Overriding → Child class provides a new implementation of a parent method**

---

# Comparison

| Aspect                      | Method Overloading                                           | Method Overriding                                                |
| --------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------- |
| **Meaning**                 | Multiple methods with the same name but different parameters | Child class provides a new implementation of an inherited method |
| **Usually associated with** | Compile-time polymorphism                                    | Runtime polymorphism                                             |
| **Requires inheritance?**   | No                                                           | Usually yes                                                      |
| **Parameters**              | Must differ in languages supporting traditional overloading  | Typically same or compatible method signature                    |
| **Purpose**                 | Provide multiple ways to perform an operation                | Provide specialized behavior in a child class                    |
| **Decision**                | Commonly determined at compile time                          | Commonly determined at runtime                                   |
| **Typical example**         | `add(int, int)` and `add(int, int, int)`                     | `Dog.speak()` overriding `Animal.speak()`                        |

---

# 1. Method Overloading

## Definition

**Method overloading** means defining multiple methods with the **same name but different parameter lists**.

The parameter lists may differ in:

* Number of parameters
* Parameter types
* Parameter order

The exact rules depend on the programming language.

---

## Example in Java

Java supports traditional method overloading.

```java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

Both methods are named:

```text
add()
```

But their parameter lists are different:

```text
add(int, int)
add(int, int, int)
```

Now we can call:

```java
Calculator c = new Calculator();

c.add(2, 3);       // calls first method
c.add(2, 3, 4);    // calls second method
```

The compiler can determine which method is appropriate based on the arguments.

```text
add(2, 3)
    ↓
add(int, int)

add(2, 3, 4)
    ↓
add(int, int, int)
```

This is commonly associated with **compile-time polymorphism**.

---

# Why Is Method Overloading Useful?

Suppose we need to perform the same general operation with different inputs.

Without overloading, we might need unrelated method names:

```text
addTwoNumbers()
addThreeNumbers()
```

With overloading:

```text
add(a, b)
add(a, b, c)
```

The same method name represents the same general operation.

This can make an API easier to understand and use.

---

# Important: Python Does Not Support Traditional Method Overloading

Python does **not** support traditional method overloading in the same way Java or C++ does.

For example:

```python
class Calculator:

    def add(self, a, b):
        return a + b

    def add(self, a, b, c):
        return a + b + c
```

This does **not** create two overloaded `add()` methods.

The second definition replaces the first one.

Conceptually:

```text
First add()
     ↓
Defined

Second add()
     ↓
Replaces the first add()
```

Therefore, this would not work as traditional overloading:

```python
calculator = Calculator()

calculator.add(2, 3)
```

because the remaining `add()` method expects three arguments.

---

## How Can Python Provide Similar Flexibility?

Python can use techniques such as:

### Default Arguments

```python
class Calculator:

    def add(self, a, b, c=0):
        return a + b + c


calculator = Calculator()

print(calculator.add(2, 3))
print(calculator.add(2, 3, 4))
```

Output:

```text
5
9
```

### `*args`

Another approach is:

```python
class Calculator:

    def add(self, *numbers):
        return sum(numbers)


calculator = Calculator()

print(calculator.add(2, 3))
print(calculator.add(2, 3, 4))
print(calculator.add(1, 2, 3, 4))
```

Output:

```text
5
9
10
```

These approaches provide similar flexibility, but they are **not traditional compile-time method overloading** like the Java example.

# 2. Method Overriding

## Definition

**Method overriding** occurs when a child class provides its own implementation of a method inherited from the parent class.

It generally involves:

```text
Parent Class
     ↓
Child Class
     ↓
Same method
     ↓
Different implementation
```

---

## Example

```python
class Animal:

    def speak(self):
        print("Some sound")


class Dog(Animal):

    def speak(self):
        print("Bark")


class Cat(Animal):

    def speak(self):
        print("Meow")
```

Here:

```text
Animal.speak()
     ↓
Inherited by Dog and Cat
     ↓
Dog overrides speak()
Cat overrides speak()
```

Now:

```python
Dog().speak()
Cat().speak()
```

Output:

```text
Bark
Meow
```

The subclasses provide their own implementations of the inherited `speak()` method.

---

# How Method Overriding Works

The relationship can be visualized as:

```text
                 Animal
                   │
                speak()
                   │
          ┌────────┴────────┐
          ↓                 ↓
         Dog               Cat
          │                 │
     speak()             speak()
       "Bark"             "Meow"
```

The calling code can use:

```python
animal.speak()
```

and the behavior depends on the actual object.

This is why method overriding is commonly associated with **runtime polymorphism**.

---

# Runtime Example

Consider:

```python
animals = [Dog(), Cat()]

for animal in animals:
    animal.speak()
```

Output:

```text
Bark
Meow
```

The same method call:

```python
animal.speak()
```

produces different results.

```text
Dog object
    ↓
speak()
    ↓
Bark


Cat object
    ↓
speak()
    ↓
Meow
```

---

# Real-World Example: Notification System

Imagine a notification system with different notification methods.

```text
                 Notification
                  /        \
                 ↓          ↓
               Email       SMS
```

The parent class could define a common operation:

```text
send(message)
```

The subclasses can override it:

```text
Email.send() → Send email

SMS.send()   → Send SMS
```

For example:

```python
class Notification:

    def send(self, message):
        print("Sending notification")


class Email(Notification):

    def send(self, message):
        print(f"Sending email: {message}")


class SMS(Notification):

    def send(self, message):
        print(f"Sending SMS: {message}")
```

Now:

```python
notifications = [
    Email(),
    SMS()
]

for notification in notifications:
    notification.send("Hello!")
```

Output:

```text
Sending email: Hello!
Sending SMS: Hello!
```

The application can call:

```python
notification.send(message)
```

without needing to know the exact notification type.

# Overloading vs Overriding: Visual Difference

## Method Overloading

```text
Same Class
    │
    ├── add(a, b)
    │
    └── add(a, b, c)
```

### Main idea

```text
Same name
    +
Different parameters
```

---

## Method Overriding

```text
Parent Class
    │
    └── speak()
          ↑
          │
     Child Class
          │
       speak()
```

### Main idea

```text
Inherited method
       +
Child provides new implementation
```

---

# Key Differences

### 1. Class Relationship

**Overloading:**

```text
Usually within the same class
```

**Overriding:**

```text
Parent class
     ↓
Child class
```

---

### 2. Parameters

**Overloading:**

The parameter list must differ in languages that support traditional overloading.

```text
add(int, int)
add(int, int, int)
```

**Overriding:**

The child generally provides an implementation compatible with the inherited method's signature. The exact rules depend on the language.

---

### 3. Inheritance

**Overloading:**

Inheritance is not required.

**Overriding:**

Usually requires inheritance or another form of subtyping/interface implementation.

---

### 4. Polymorphism

**Overloading:**

Commonly associated with **compile-time polymorphism**.

**Overriding:**

Commonly associated with **runtime polymorphism**.

---

### 5. Purpose

**Overloading:**

> Provide multiple ways to call the same general operation.

**Overriding:**

> Allow a child type to provide specialized behavior.

# Common Mistakes

## 1. Confusing Overloading With Overriding

Remember:

```text
Overloading
    ↓
Same name
Different parameters
```

while:

```text
Overriding
    ↓
Parent method
       ↓
Child provides new implementation
```

### Memory Trick

> **Overloading = Same name, different inputs**
> **Overriding = Parent behavior replaced/specialized by child**

---

## 2. Saying Python Supports Traditional Method Overloading

This is a common interview mistake.

Do not claim that this:

```python
class Calculator:

    def add(self, a, b):
        ...

    def add(self, a, b, c):
        ...
```

creates two overloaded methods.

The second `add()` definition replaces the first.

Python instead commonly uses:

```python
*args
```

or default arguments to support different calling patterns.

---

## 3. Assuming Overriding Rules Are Identical in Every Language

The precise rules for overriding depend on the programming language.

They may involve rules concerning:

* Method signatures
* Return types
* Access modifiers
* Exceptions
* `virtual` / `override` keywords
* Interfaces
* Inheritance rules

Therefore, when discussing overriding in an interview, it is useful to mention the language being used.

---

# Common Interview Example

### Question:

**Can a method be both overloaded and overridden?**

Yes, depending on the language and class design, a class can have overloaded methods while also overriding an inherited method.

For example:

```text
Parent
  │
  └── display(int)

Child
  │
  ├── display(int)       ← overrides parent method
  │
  └── display(String)    ← overloads display()
```

The exact legality and behavior depends on the programming language.

The important distinction remains:

```text
Overloading → Different parameter lists

Overriding → Child changes inherited behavior
```

# Interview Takeaway

> **Method overloading means using the same method name with different parameter lists, commonly providing compile-time polymorphism in languages such as Java and C++. Method overriding means a child class provides its own implementation of an inherited method, commonly providing runtime polymorphism.**
