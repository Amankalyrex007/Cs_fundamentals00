9.Method overloading vs method overriding?
Answer

Method overloading and method overriding both allow the same method name to be associated with different behavior, but they work differently.

The simplest distinction is:

Overloading → same method name, different parameter list
Overriding → child class provides a new implementation of a parent method

Comparison
Aspect	Method Overloading	Method Overriding
Meaning	Multiple methods with the same name but different parameters	Child class redefines an inherited method
Usually associated with	Compile-time polymorphism	Runtime polymorphism
Requires inheritance?	No	Usually yes
Parameters	Must differ in languages supporting traditional overloading	Typically same/similar method signature
Purpose	Provide multiple ways to call an operation	Provide specialized behavior
Decision	Commonly compile time	Commonly runtime
1. Method Overloading

Method overloading means defining multiple methods with the same name but different parameter lists.

For example, Java supports traditional method overloading:

class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}

Both methods are named add(), but they accept different numbers of arguments.

Calculator c = new Calculator();

c.add(2, 3);       // calls first method
c.add(2, 3, 4);    // calls second method

The compiler can determine which method is appropriate from the arguments.

Important: Python

Python does not support traditional method overloading like Java or C++.

For example:

class Calculator:
    def add(self, a, b):
        return a + b

    def add(self, a, b, c):
        return a + b + c

The second add() definition replaces the first one.

Python can achieve similar flexibility using default arguments or *args:

class Calculator:
    def add(self, *numbers):
        return sum(numbers)

So, in an interview, don't claim that Python has traditional compile-time method overloading.

2. Method Overriding

Method overriding occurs when a child class provides its own implementation of a method inherited from the parent class.

Example:

class Animal:
    def speak(self):
        print("Some sound")


class Dog(Animal):
    def speak(self):
        print("Bark")


class Cat(Animal):
    def speak(self):
        print("Meow")

Now:

Dog().speak()  # Bark
Cat().speak()  # Meow

Both Dog and Cat override the speak() method of Animal.

The method called can depend on the actual object at runtime, which is why overriding is commonly associated with runtime polymorphism.

Real-World Example

Imagine a notification system:

Notification
     |
 ┌───┴────────────┐
Email           SMS

The parent class could define:

send(message)

The subclasses could override it:

Email.send() → Send email
SMS.send()   → Send SMS

The application can call:

notification.send(message)

and the appropriate implementation is used for the actual object.

Common Mistakes
1. Confusing overloading with overriding

Remember:

Overloading  → same class, different parameters
Overriding   → child class, new implementation
2. Saying Python supports traditional method overloading

It doesn't. Python uses other mechanisms, such as default arguments and *args, to provide similar flexibility.

3. Assuming overriding requires completely identical signatures in every language

The precise rules for overriding—such as return types, visibility, and allowed parameter variations—depend on the programming language.

Interview Takeaway

Method overloading means using the same method name with different parameter lists, commonly providing compile-time polymorphism in languages such as Java and C++. Method overriding means a child class provides its own implementation of an inherited method, commonly providing runtime polymorphism.

Memory trick:

Overloading = same name, different inputs
Overriding = parent behavior replaced/specialized by child
