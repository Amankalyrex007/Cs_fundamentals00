10.What is dynamic method dispatch?
Answer

Dynamic method dispatch is the mechanism by which a call to an overridden method is resolved at runtime based on the actual object, rather than the reference type.

It is a key mechanism behind runtime polymorphism.

A simple way to remember it:

The reference tells us what interface is available; the actual object determines which overridden method runs.

Simple Example

Consider a parent class and two child classes:

class Animal:
    def speak(self):
        print("Some sound")


class Dog(Animal):
    def speak(self):
        print("Bark")


class Cat(Animal):
    def speak(self):
        print("Meow")

Now:

animal1 = Dog()
animal2 = Cat()

animal1.speak()
animal2.speak()

Output:

Bark
Meow

Even though both variables can be treated as Animal objects, the actual objects are different:

animal1 → Dog → Dog.speak()
animal2 → Cat → Cat.speak()

The method implementation is therefore selected according to the actual object's type at runtime.

How Dynamic Method Dispatch Works

Consider:

animal = Dog()
animal.speak()

Conceptually, the process is:

1. animal refers to a Dog object
             ↓
2. Program encounters animal.speak()
             ↓
3. Runtime determines the actual object
             ↓
4. Dog's overridden speak() is selected
             ↓
5. "Bark" is printed

If the object were a Cat:

animal = Cat()
animal.speak()

the runtime would select Cat.speak() instead.

Why is it useful?

Dynamic method dispatch allows code to depend on a common parent type or interface instead of knowing the exact implementation.

For example:

def make_animal_speak(animal):
    animal.speak()

We can pass different objects:

make_animal_speak(Dog())
make_animal_speak(Cat())

The function doesn't need separate if/else logic for every animal type.

This makes systems easier to extend and maintain.

For example, adding:

class Cow(Animal):
    def speak(self):
        print("Moo")

allows:

make_animal_speak(Cow())

without changing make_animal_speak().

Dynamic Method Dispatch vs Method Overriding

These concepts are closely related but not identical.

Method overriding → a subclass provides a different implementation of an inherited method.
Dynamic method dispatch → at runtime, the appropriate overridden implementation is selected based on the actual object.

So:

Overriding provides the different implementations; dynamic dispatch selects the appropriate implementation at runtime.

Relation to Runtime Polymorphism

The relationship can be visualized as:

Inheritance
     ↓
Method Overriding
     ↓
Dynamic Method Dispatch
     ↓
Runtime Polymorphism

These concepts are related, although the exact terminology and implementation details vary across programming languages.

Common Mistake

Don't confuse dynamic method dispatch with simply calling a method.

The important part is that the method implementation is determined dynamically based on the actual object, particularly when a subclass has overridden a method.

Also, dynamic dispatch is primarily associated with instance methods. Static methods generally do not participate in runtime dispatch in the same way.

Interview Takeaway

Dynamic method dispatch is the runtime mechanism that selects the appropriate overridden method based on the actual object. It enables runtime polymorphism, allowing the same method call to produce different behavior for different objects.

Memory trick:

Same method call + different actual object → different implementation at runtime.
