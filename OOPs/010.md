# Q10. What is Dynamic Method Dispatch?

## Definition

**Dynamic Method Dispatch** is the mechanism by which a call to an **overridden method is resolved at runtime based on the actual object**, rather than the reference type.

It is one of the key mechanisms behind **runtime polymorphism**.

### Simple Definition

> **The reference determines what methods are available, while the actual object determines which overridden method runs.**

---

## Simple Example

Consider a parent class `Animal` and two child classes, `Dog` and `Cat`:

```python
class Animal:
    def speak(self):
        print("Some sound")


class Dog(Animal):
    def speak(self):
        print("Bark")


class Cat(Animal):
    def speak(self):
        print("Meow")
```

Now create objects:

```python
animal1 = Dog()
animal2 = Cat()

animal1.speak()
animal2.speak()
```

### Output

```text
Bark
Meow
```

Although both variables are used through the same method name, `speak()`, the actual objects are different:

```text
animal1 → Dog → Dog.speak()
animal2 → Cat → Cat.speak()
```

The appropriate implementation is therefore selected according to the **actual object's type at runtime**.

---

## How Dynamic Method Dispatch Works

Consider:

```python
animal = Dog()
animal.speak()
```

Conceptually, the process is:

```text
animal refers to a Dog object
          ↓
Program encounters animal.speak()
          ↓
Runtime determines the actual object
          ↓
Dog's overridden speak() is selected
          ↓
"Bark" is printed
```

If the object were a `Cat`:

```python
animal = Cat()
animal.speak()
```

the runtime would select:

```text
Cat.speak()
```

and the output would be:

```text
Meow
```

---

## Reference Type vs Actual Object

This distinction is important for understanding dynamic dispatch.

Suppose a language allows a parent-type reference to refer to a child object:

```text
Animal animal = new Dog();
```

Here:

```text
Reference type → Animal
Actual object  → Dog
```

When the following is called:

```text
animal.speak()
```

dynamic method dispatch selects:

```text
Dog.speak()
```

because the actual object is a `Dog`.

### Key Idea

```text
Reference Type
     ↓
Determines accessible interface

Actual Object
     ↓
Determines overridden implementation
```

The exact syntax differs between programming languages, but this distinction is central to runtime polymorphism.

---

## Why is Dynamic Method Dispatch Useful?

Dynamic method dispatch allows code to depend on a **common parent type or interface** instead of knowing the exact implementation.

For example:

```python
def make_animal_speak(animal):
    animal.speak()
```

We can pass different objects:

```python
make_animal_speak(Dog())
make_animal_speak(Cat())
```

Output:

```text
Bark
Meow
```

The function does not need separate `if/else` logic for every animal type.

---

## Extending the System

Suppose we add another animal:

```python
class Cow(Animal):
    def speak(self):
        print("Moo")
```

We can immediately use it:

```python
make_animal_speak(Cow())
```

Output:

```text
Moo
```

We did **not** need to modify:

```python
def make_animal_speak(animal):
    animal.speak()
```

This demonstrates an important benefit of polymorphic design:

> **New implementations can often be added without changing existing code that works with the common interface.**

---

## Real-World Example: Payment System

Dynamic dispatch is commonly useful in systems where different objects provide different implementations of the same operation.

For example:

```python
class Payment:
    def pay(self):
        print("Processing payment")


class CreditCardPayment(Payment):
    def pay(self):
        print("Processing credit card payment")


class UPIPayment(Payment):
    def pay(self):
        print("Processing UPI payment")
```

Now:

```python
def process_payment(payment):
    payment.pay()
```

Different objects can be passed:

```python
process_payment(CreditCardPayment())
process_payment(UPIPayment())
```

Output:

```text
Processing credit card payment
Processing UPI payment
```

The `process_payment()` function does not need to know how each payment method works internally.

## Dynamic Method Dispatch vs Method Overriding

These concepts are closely related, but they are **not the same thing**.

### Method Overriding

**Method overriding** occurs when a subclass provides a different implementation of a method inherited from its parent class.

```python
class Dog(Animal):
    def speak(self):
        print("Bark")
```

Here, `Dog` overrides `Animal.speak()`.

### Dynamic Method Dispatch

**Dynamic method dispatch** is the runtime mechanism that determines which overridden implementation should execute.

```python
animal = Dog()
animal.speak()
```

The runtime selects:

```text
Dog.speak()
```

### Relationship

```text
Method Overriding
        ↓
Provides different implementations
        ↓
Dynamic Method Dispatch
        ↓
Selects the appropriate implementation at runtime
```

### Easy Way to Remember

> **Overriding creates the alternatives; dynamic dispatch chooses the appropriate one at runtime.**

---

## Relation to Runtime Polymorphism

Dynamic method dispatch is closely connected to **runtime polymorphism**.

A simplified relationship is:

```text
Inheritance
     ↓
Method Overriding
     ↓
Dynamic Method Dispatch
     ↓
Runtime Polymorphism
```

For example:

```python
class Animal:
    def speak(self):
        print("Animal sound")


class Dog(Animal):
    def speak(self):
        print("Bark")


class Cat(Animal):
    def speak(self):
        print("Meow")
```

Now:

```python
def make_sound(animal):
    animal.speak()
```

The same method call:

```python
animal.speak()
```

can produce different behavior:

```text
Dog object → Bark
Cat object → Meow
```

This is **runtime polymorphism**.

> The exact terminology and implementation details can vary between programming languages.

---

## Dynamic Dispatch Flow

```text
                  Common Interface
                        │
                        ▼
                  animal.speak()
                        │
             ┌──────────┴──────────┐
             │                     │
        Actual Object         Actual Object
             │                     │
             ▼                     ▼
            Dog                   Cat
             │                     │
             ▼                     ▼
       Dog.speak()           Cat.speak()
             │                     │
             ▼                     ▼
           "Bark"                "Meow"
```

The method call remains the same, but the implementation changes according to the actual object.

## Dynamic Dispatch vs Static Binding

| Feature                       | Dynamic Method Dispatch     | Static Binding                                 |
| ----------------------------- | --------------------------- | ---------------------------------------------- |
| Decision time                 | Runtime                     | Compile time                                   |
| Based on                      | Actual object               | Known/static type or context                   |
| Commonly associated with      | Overridden instance methods | Static/private/final methods in some languages |
| Supports runtime polymorphism | Yes                         | Generally no                                   |
| Behavior can vary by object   | Yes                         | Generally determined earlier                   |

> Exact binding rules depend on the programming language.

---

## Important Note About Static Methods

Dynamic method dispatch is primarily associated with **instance methods**.

Static methods generally do not participate in runtime dispatch in the same way because they are associated with the class rather than a particular object.

For example, in languages such as Java, static methods are resolved using **static binding** rather than normal runtime method dispatch.

---

## Common Mistakes

### 1. Confusing overriding with dynamic dispatch

❌ Incorrect:

> Dynamic dispatch means a child class overrides a method.

✅ Correct:

> Overriding creates a different implementation, while dynamic dispatch selects the appropriate overridden implementation at runtime.

---

### 2. Thinking the reference type determines the implementation

The reference type determines what interface or members are available, but for an overridden instance method, the **actual object** determines which implementation executes.

```text
Reference → What can be called
Object    → Which overridden implementation runs
```

---

### 3. Thinking dynamic dispatch happens only because of inheritance

Inheritance is a common way to achieve this behavior, but modern languages can also provide dynamic dispatch through mechanisms such as **interfaces, protocols, virtual methods, or duck typing**.

Therefore, the exact implementation mechanism depends on the language.

---

### 4. Assuming every method participates in dynamic dispatch

Not every method is dynamically dispatched.

For example, depending on the language, `static`, `private`, or `final` methods may have different binding rules.

---

## Benefits of Dynamic Method Dispatch

### 1. Supports Runtime Polymorphism

Different objects can respond differently to the same method call.

### 2. Reduces Conditional Logic

You often don't need code such as:

```python
if type == "dog":
    ...
elif type == "cat":
    ...
elif type == "cow":
    ...
```

Instead, each object provides its own implementation.

### 3. Improves Extensibility

New subclasses can often be added without modifying code that uses the common interface.

### 4. Reduces Coupling

The calling code does not need to know the concrete implementation.

### 5. Improves Maintainability

Behavior remains encapsulated within the appropriate class.

---

## Key Difference: Overriding vs Dynamic Dispatch

```text
              METHOD OVERRIDING
                     │
                     ▼
       Different implementations exist
                     │
                     ▼
        DYNAMIC METHOD DISPATCH
                     │
                     ▼
 Runtime selects the correct implementation
                     │
                     ▼
         RUNTIME POLYMORPHISM
```

## Quick Revision

* **Dynamic Method Dispatch** → selecting an overridden method implementation at runtime.
* The selection is based on the **actual object**.
* It is a key mechanism behind **runtime polymorphism**.
* **Method overriding** provides different implementations.
* **Dynamic dispatch** selects the appropriate implementation.
* The same method call can produce different behavior for different objects.
* It reduces the need for explicit type-checking and conditional logic.
* It is primarily associated with dynamically dispatched instance methods.
* Static methods generally follow different binding rules.

## Key Terms

| Term                        | Meaning                                                           |
| --------------------------- | ----------------------------------------------------------------- |
| **Dynamic Method Dispatch** | Runtime selection of an overridden method                         |
| **Method Overriding**       | Subclass provides a new implementation of an inherited method     |
| **Runtime Polymorphism**    | Same interface/method call produces different behavior at runtime |
| **Actual Object**           | The concrete object that a reference points to                    |
| **Reference Type**          | The type through which an object is accessed                      |
| **Dynamic Binding**         | Resolving a method call at runtime                                |
| **Static Binding**          | Resolving a method call earlier, typically at compile time        |

---

## One-Line Memory Trick

> **Same method call + different actual object → different implementation at runtime.**

---

## Interview Takeaway

**Dynamic Method Dispatch is the runtime mechanism that selects the appropriate overridden method based on the actual object rather than simply the reference type. It enables runtime polymorphism, allowing the same method call to produce different behavior for different objects.**

### Short Interview Answer

> Dynamic method dispatch is the runtime mechanism used to determine which overridden method should execute based on the actual object. It is a key mechanism behind runtime polymorphism. For example, if an `Animal` reference refers to a `Dog` object, calling `speak()` executes `Dog.speak()` rather than `Animal.speak()`.
