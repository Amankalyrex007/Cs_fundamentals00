# Q13. What is the Difference Between an Interface and an Abstract Class?

Both **interfaces** and **abstract classes** are used to define a common structure or contract for other classes.

The main difference is:

```text
Interface
    ↓
Contract

Abstract Class
    ↓
Contract + Shared Implementation + State
```

> **Interface → What a class must do**
> **Abstract Class → What a class must do + some shared implementation**

The exact rules differ between programming languages. The examples below mainly use **Java**, with a Python example at the end.

---

## 1. Interface Example

Suppose we are creating a payment system.

Every payment method should provide a `pay()` method.

```java
interface Payment {

    void pay(double amount);
}
```

The interface defines the contract:

```text
Payment
   │
   └── pay()
```

Different classes can implement this contract.

### Credit Card Payment

```java
class CreditCardPayment implements Payment {

    public void pay(double amount) {
        System.out.println("Paid using credit card");
    }
}
```

### UPI Payment

```java
class UpiPayment implements Payment {

    public void pay(double amount) {
        System.out.println("Paid using UPI");
    }
}
```

Both classes provide their own implementation of `pay()`.

```text
                 Payment
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
 CreditCardPayment       UpiPayment
          │                   │
          ↓                   ↓
        pay()               pay()
          │                   │
          ↓                   ↓
    Credit Card              UPI
```

The interface only requires:

```text
Every Payment must have pay()
```

## 2. Abstract Class Example

Suppose all payment methods share some common information, such as currency.

An abstract class can provide that shared state and behavior.

```java
abstract class Payment {

    String currency;

    Payment(String currency) {
        this.currency = currency;
    }

    abstract void pay(double amount);

    void printCurrency() {
        System.out.println("Currency: " + currency);
    }
}
```

Now subclasses can reuse the common implementation.

```java
class UpiPayment extends Payment {

    UpiPayment(String currency) {
        super(currency);
    }

    void pay(double amount) {
        System.out.println("Paid using UPI");
    }
}
```

Another subclass:

```java
class CreditCardPayment extends Payment {

    CreditCardPayment(String currency) {
        super(currency);
    }

    void pay(double amount) {
        System.out.println("Paid using credit card");
    }
}
```

The structure becomes:

```text
                    Payment
                 <<abstract>>
                      │
          ┌───────────┴───────────┐
          ↓                       ↓
     UpiPayment          CreditCardPayment
          │                       │
          ├── currency            ├── currency
          ├── printCurrency()     ├── printCurrency()
          └── pay()              └── pay()
```

Here:

```text
Abstract class
      ↓
Shared state
      +
Shared implementation
      +
Abstract behavior
```

## 3. Interface Example with Different Types

An interface is useful when different types of objects need to support the same capability.

For example:

```java
interface Flyable {

    void fly();
}
```

A bird can implement it:

```java
class Bird implements Flyable {

    public void fly() {
        System.out.println("Bird is flying");
    }
}
```

An airplane can also implement it:

```java
class Airplane implements Flyable {

    public void fly() {
        System.out.println("Airplane is flying");
    }
}
```

The relationship is:

```text
             Flyable
                │
        ┌───────┴───────┐
        ↓               ↓
      Bird           Airplane
        │               │
        ↓               ↓
      fly()           fly()
```

A bird and an airplane are very different objects, but both provide the `fly()` capability.

## 4. Abstract Class Example with Related Objects

An abstract class is useful when classes have a strong common relationship.

For example:

```java
abstract class Vehicle {

    String brand;

    Vehicle(String brand) {
        this.brand = brand;
    }

    void start() {
        System.out.println("Vehicle started");
    }

    abstract void move();
}
```

A car can extend it:

```java
class Car extends Vehicle {

    Car(String brand) {
        super(brand);
    }

    void move() {
        System.out.println("Car is moving");
    }
}
```

A bike can also extend it:

```java
class Bike extends Vehicle {

    Bike(String brand) {
        super(brand);
    }

    void move() {
        System.out.println("Bike is moving");
    }
}
```

The relationship is:

```text
                Vehicle
             <<abstract>>
                  │
          ┌───────┴───────┐
          ↓               ↓
         Car             Bike
          │               │
          ├── brand       ├── brand
          ├── start()     ├── start()
          └── move()      └── move()
```

Here `Car` and `Bike` share the common `Vehicle` functionality.

## 5. Interface with Multiple Capabilities

A class can implement multiple interfaces in languages such as Java.

For example:

```java
interface Flyable {

    void fly();
}
```

Another interface:

```java
interface Swimmable {

    void swim();
}
```

A duck can implement both:

```java
class Duck implements Flyable, Swimmable {

    public void fly() {
        System.out.println("Duck is flying");
    }

    public void swim() {
        System.out.println("Duck is swimming");
    }
}
```

Diagram:

```text
        Flyable          Swimmable
           │                │
           └───────┬────────┘
                   ↓
                 Duck
                   │
              ┌────┴────┐
              ↓         ↓
            fly()      swim()
```

This shows how interfaces can represent different capabilities.

## 6. Abstract Class with Shared State

An abstract class can contain instance variables.

```java
abstract class Employee {

    String name;
    double salary;

    Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }

    abstract void work();
}
```

A developer can extend it:

```java
class Developer extends Employee {

    Developer(String name, double salary) {
        super(name, salary);
    }

    void work() {
        System.out.println(name + " writes code");
    }
}
```

A manager can also extend it:

```java
class Manager extends Employee {

    Manager(String name, double salary) {
        super(name, salary);
    }

    void work() {
        System.out.println(name + " manages the team");
    }
}
```

Both classes inherit:

```text
name
salary
```

and provide their own:

```text
work()
```

implementation.

## 8. Interface Example: Payment Contract

```java
interface Payment {

    void pay(double amount);
}
```

Implementations:

```java
class UpiPayment implements Payment {

    public void pay(double amount) {
        System.out.println("Paid using UPI");
    }
}
```

```java
class CardPayment implements Payment {

    public void pay(double amount) {
        System.out.println("Paid using Card");
    }
}
```

Usage:

```java
Payment payment1 = new UpiPayment();

Payment payment2 = new CardPayment();

payment1.pay(1000);
payment2.pay(2000);
```

Output:

```text
Paid using UPI
Paid using Card
```

The caller works with the common `Payment` contract.

## 9. Abstract Class Example: Shared Implementation

```java
abstract class Animal {

    void eat() {
        System.out.println("Animal is eating");
    }

    abstract void speak();
}
```

A `Dog` can extend it:

```java
class Dog extends Animal {

    void speak() {
        System.out.println("Dog says Bark");
    }
}
```

A `Cat` can also extend it:

```java
class Cat extends Animal {

    void speak() {
        System.out.println("Cat says Meow");
    }
}
```

Usage:

```java
Dog dog = new Dog();

dog.eat();
dog.speak();
```

Output:

```text
Animal is eating
Dog says Bark
```

Here:

```text
eat()
   ↓
Shared implementation

speak()
   ↓
Subclass-specific implementation
```

## 10. Python Example

Python does not have a separate `interface` keyword like Java.

Python commonly uses **Abstract Base Classes (ABCs)** for interface-like contracts.

```python
from abc import ABC, abstractmethod


class Payment(ABC):

    @abstractmethod
    def pay(self, amount):
        pass
```

A concrete class can implement it:

```python
class UpiPayment(Payment):

    def pay(self, amount):
        print(f"Paid {amount} using UPI")
```

Usage:

```python
payment = UpiPayment()

payment.pay(1000)
```

Output:

```text
Paid 1000 using UPI
```

---

## 11. Python Abstract Class with Shared Implementation

Python's abstract base classes can also contain normal methods and state.

```python
from abc import ABC, abstractmethod


class Payment(ABC):

    def __init__(self, currency):
        self.currency = currency

    @abstractmethod
    def pay(self, amount):
        pass

    def print_currency(self):
        print(self.currency)
```

A subclass can provide the required implementation:

```python
class UpiPayment(Payment):

    def pay(self, amount):
        print(f"Paid {amount} using UPI")
```

Usage:

```python
payment = UpiPayment("INR")

payment.print_currency()
payment.pay(1000)
```

Output:

```text
INR
Paid 1000 using UPI
```

Here:

```text
Payment
   │
   ├── currency
   ├── print_currency()
   └── pay() → abstract
          ↓
      UpiPayment
          ↓
       pay() → implementation
```

        Contract /             Contract +

## Short Answer

> **An interface primarily defines a contract or capability that a class must follow, while an abstract class can define a contract along with shared state and implementation.**

```text
Interface
    → Contract / Capability

Abstract Class
    → Contract + Shared State + Shared Implementation
```
