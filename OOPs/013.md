13.What is the difference between an interface and an abstract class?
Answer

Both interfaces and abstract classes are used to define a common structure or contract for other classes. The main difference is that an interface primarily defines what a class must do, while an abstract class can define both what a class must do and how some of it should work.

Interface → contract
Abstract class → contract + shared implementation/state

The exact rules differ between languages, so the following comparison is mainly based on common Java/C++-style OOP concepts.

Key differences
Feature	Interface	Abstract Class
Main purpose	Defines a contract	Provides a common base with shared behavior
Methods	Primarily abstract methods; modern languages may allow some implemented methods	Can contain abstract and concrete methods
Instance variables/state	Usually limited or language-dependent	Can have instance variables/state
Constructor	Generally does not have a normal instance constructor	Can have a constructor
Object creation	Cannot normally be instantiated directly	Cannot normally be instantiated if abstract
Multiple inheritance	A class can generally implement multiple interfaces	A class generally extends one abstract class
Code reuse	Less focused on implementation reuse	Strong support for implementation reuse
Relationship	Often represents a capability/contract	Often represents a common base/type
Example

Suppose we are building a payment system.

An interface can define what every payment method must provide:

interface Payment {
    void pay(double amount);
}

Different classes can implement it:

class CreditCardPayment implements Payment {
    public void pay(double amount) {
        System.out.println("Paid using credit card");
    }
}

class UpiPayment implements Payment {
    public void pay(double amount) {
        System.out.println("Paid using UPI");
    }
}

The interface says:

"Any payment implementation must provide pay()."

An abstract class, on the other hand, can provide shared functionality:

abstract class Payment {
    String currency;

    Payment(String currency) {
        this.currency = currency;
    }

    abstract void pay(double amount);

    void printCurrency() {
        System.out.println(currency);
    }
}

Here, subclasses can inherit the common currency state and printCurrency() implementation while providing their own pay() behavior.

When should you use each?

Use an interface when:

You primarily want to define a common contract.
Unrelated classes should support the same behavior.
Multiple classes may need to implement the same capability.

Example:

Flyable
  ├── Bird
  └── Airplane

Both can be "flyable" even though they don't share the same underlying implementation.

Use an abstract class when:

Classes have a strong is-a relationship.
They share common state or implementation.
You want to provide some default behavior while forcing subclasses to implement specific methods.

Example:

Vehicle
  ├── Car
  └── Bike
Important language difference

In Python, the distinction is less rigid than in Java. Python commonly uses the abc module to create abstract base classes:

from abc import ABC, abstractmethod

class Payment(ABC):

    @abstractmethod
    def pay(self, amount):
        pass

Python does not have a separate interface keyword like Java. An interface-like contract can be represented using abstract base classes, protocols, or duck typing, depending on the design.

Interview takeaway

An interface primarily defines a contract that implementing classes must follow, while an abstract class can provide a contract plus shared state and implementation.
