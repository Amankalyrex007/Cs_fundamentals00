14.Composition vs inheritance?
Answer

Composition and inheritance are two ways of establishing relationships between classes.

The key distinction is:

Inheritance represents an “is-a” relationship, while composition represents a “has-a” relationship.

Inheritance: A class derives from another class and inherits its behavior.
Composition: A class contains an object of another class and uses its functionality.
Example
Inheritance — “is-a”
class Animal:
    def eat(self):
        print("Eating")


class Dog(Animal):
    def bark(self):
        print("Barking")


dog = Dog()
dog.eat()
dog.bark()

Here:

Dog IS-A Animal

Dog inherits the behavior of Animal.

Composition — “has-a”
class Engine:
    def start(self):
        print("Engine started")


class Car:
    def __init__(self):
        self.engine = Engine()

    def start(self):
        self.engine.start()


car = Car()
car.start()

Here:

Car HAS-A Engine

The Car class contains an Engine object and delegates work to it.

Comparison
Feature	Inheritance	Composition
Relationship	Is-a	Has-a
Mechanism	Extends/inherits another class	Contains objects of other classes
Code reuse	Through inheritance	Through object delegation
Coupling	Usually tighter	Usually looser
Flexibility	Can be less flexible when hierarchy grows	Usually easier to change components
Runtime behavior	More tied to class hierarchy	Components can often be replaced
Best suited for	Genuine subtype relationships	Building objects from reusable components
Why is composition often preferred?

Composition can reduce tight coupling between classes.

Suppose a Car inherits from Engine:

Car → Engine

This would imply that:

A Car is an Engine

which is conceptually incorrect.

Instead:

Car
 └── Engine

means:

A Car has an Engine.

Composition also makes it easier to replace components:

class PetrolEngine:
    def start(self):
        print("Petrol engine started")


class ElectricMotor:
    def start(self):
        print("Electric motor started")


class Car:
    def __init__(self, power_unit):
        self.power_unit = power_unit

    def start(self):
        self.power_unit.start()

Now the same Car can work with different power units:

car1 = Car(PetrolEngine())
car2 = Car(ElectricMotor())

This is an example of composition + polymorphism.

When should you use inheritance?

Use inheritance when there is a genuine is-a relationship and the subclass should naturally conform to the parent type.

For example:

Vehicle
 ├── Car
 └── Bike

A Car is a Vehicle, so inheritance can make sense.

When should you use composition?

Use composition when one object uses or contains another object.

Examples:

Car → Engine
Computer → CPU
House → Rooms
MLPipeline → Model + Preprocessor + Evaluator
Common mistake

Don't choose inheritance merely because you want to reuse code.

For example, if two classes happen to share some functionality, that alone doesn't mean one should inherit from the other. First ask:

Is it really an “is-a” relationship, or is one object simply using another?

Interview takeaway

Inheritance models “is-a” relationships and promotes reuse through a class hierarchy. Composition models “has-a” relationships and promotes reuse by combining independent objects. When both are reasonable, composition often provides greater flexibility and lower coupling, but the correct choice depends on the domain and design requirements.
