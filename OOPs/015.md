# Q15. Association, Aggregation, and Composition?

Association, aggregation, and composition describe relationships between objects or classes.

A simple way to remember them is:

```text
Association   → knows / uses
Aggregation   → has, but independently
Composition   → has and owns
```

## 1. Association

**Association** is a general relationship where two objects interact with or use each other.

There is no strong ownership between them.

### Example

```python
class Teacher:
    def teach(self):
        print("Teacher is teaching")


class Student:
    def learn(self):
        print("Student is learning")


teacher = Teacher()
student = Student()

teacher.teach()
student.learn()
```

Here, the `Teacher` and `Student` are associated because they interact.

```text
Teacher ───────── Student
          Association
```

If the `Teacher` object is removed, the `Student` can still exist independently.

---

## 2. Aggregation

**Aggregation** is a weak `has-a` relationship.

The container has other objects, but those objects can exist independently.

### Example

```python
class Player:
    def __init__(self, name):
        self.name = name

    def show(self):
        print(f"Player: {self.name}")


class Team:
    def __init__(self, players):
        self.players = players

    def show_players(self):
        for player in self.players:
            player.show()


p1 = Player("Rahul")
p2 = Player("Aman")

team = Team([p1, p2])

team.show_players()
```

Output:

```text
Player: Rahul
Player: Aman
```

Here:

```text
Team ◇──── Player
      Aggregation
```

The `Team` has `Player` objects, but the players can exist without the team.

For example:

```python
del team

p1.show()
p2.show()
```

The players can still be used after the `Team` object is removed.

---

## 3. Composition

**Composition** is a strong `has-a` relationship.

The container creates and owns its contained objects.

### Example

```python
class Engine:
    def start(self):
        print("Engine started")


class Car:
    def __init__(self):
        self.engine = Engine()

    def start(self):
        print("Car is starting...")
        self.engine.start()


car = Car()
car.start()
```

Output:

```text
Car is starting...
Engine started
```

Here:

```text
Car ◆──── Engine
      Composition
```

The `Car` creates its own `Engine`.

The `Engine` is modeled as a part of that particular `Car`.

---

## 4. Main Difference

| Feature      | Association           | Aggregation    | Composition        |
| ------------ | --------------------- | -------------- | ------------------ |
| Relationship | General connection    | Weak has-a     | Strong has-a       |
| Ownership    | No required ownership | Weak ownership | Strong ownership   |
| Lifetime     | Independent           | Independent    | Strongly connected |
| Coupling     | Loose                 | Loose          | Stronger           |
| Example      | Teacher ↔ Student     | Team → Player  | Car → Engine       |
| UML          | `────`                | `◇────`        | `◆────`            |

---

## 5. Easy Example

Consider a company:

### Association

```text
Company ───── Employee
```

The company and employee are related.

### Aggregation

```text
Department ◇──── Employee
```

A department has employees, but an employee can exist even if the department is removed.

### Composition

```text
House ◆──── Room
```

A room is modeled as a constituent part of a particular house.

---

## 6. Object Lifetime

The main difference can be understood through object lifetime.

### Association

```text
Teacher ───── Student

Teacher and Student
can exist independently.
```

### Aggregation

```text
Team ◇──── Player

Team has Players,
but Players can exist independently.
```

### Composition

```text
Car ◆──── Engine

Car owns its Engine
as part of its structure.
```

---

## 7. Simple Rule

```text
Association
    ↓
Objects are related

Aggregation
    ↓
Object has other objects
but they can exist independently

Composition
    ↓
Object owns its constituent objects
and their lifetimes are strongly connected
```

> **Association = related, Aggregation = has independently, Composition = has and owns.**
