# Q20. What is the difference between Class Variables and Instance Variables?

## Answer

The main difference is **where the variable belongs** and **whether its value is shared**.

* **Class variable** → belongs to the class and is generally shared by all objects.
* **Instance variable** → belongs to a particular object and can have a different value for each object.

A simple way to remember it:

```text
Class Variable    → One shared value at class level
Instance Variable → Separate value for each object
```

---

## Example in Python

```python
class Student:
    school = "ABC School"      # class variable

    def __init__(self, name, age):
        self.name = name        # instance variable
        self.age = age          # instance variable


s1 = Student("Rahul", 21)
s2 = Student("Aman", 22)
```

Here:

* `school` → class variable
* `name` → instance variable
* `age` → instance variable

Both objects generally access the same class variable:

```python
print(s1.school)  # ABC School
print(s2.school)  # ABC School
```

But each object has its own instance variables:

```python
print(s1.name)  # Rahul
print(s2.name)  # Aman

print(s1.age)   # 21
print(s2.age)   # 22
```

The values of `name` and `age` are stored separately for each object.

---

## Conceptually

```text
                 Student class
                      │
                      │
              school = "ABC School"
                ← shared value →
                  ↑          ↑
                 s1          s2

        ┌──────────────┐   ┌──────────────┐
        │      s1      │   │      s2      │
        │              │   │              │
        │ name = Rahul │   │ name = Aman  │
        │ age  = 21    │   │ age  = 22    │
        └──────────────┘   └──────────────┘
```

So, conceptually:

```text
Student class
│
└── school = "ABC School"     ← shared class variable
       ↑              ↑
      s1              s2

s1
├── name = "Rahul"             ← instance variable
└── age = 21

s2
├── name = "Aman"              ← instance variable
└── age = 22
```

## Another Example

Consider an `Employee` class.

The company name may be common for all employees, while each employee has their own name and salary.

```python
class Employee:
    company = "TechCorp"       # class variable

    def __init__(self, name, salary):
        self.name = name       # instance variable
        self.salary = salary   # instance variable


e1 = Employee("Rahul", 50000)
e2 = Employee("Aman", 60000)

print(e1.company)  # TechCorp
print(e2.company)  # TechCorp

print(e1.name)     # Rahul
print(e2.name)     # Aman
```

Here:

```text
company → common to employees
name    → different for each employee
salary  → different for each employee
```

This is a good example of deciding **what should be shared** and **what should belong to an individual object**.

# Comparison

| Feature    | Class Variable                                 | Instance Variable              |
| ---------- | ---------------------------------------------- | ------------------------------ |
| Belongs to | Class                                          | Individual object              |
| Shared?    | Generally shared among instances               | No, each object has its own    |
| Defined    | Usually inside class, outside instance methods | Usually using `self` in Python |
| Access     | `ClassName.variable` or through an object      | Through an object              |
| Example    | `Student.school`                               | `student.name`                 |
| Use        | Data common to objects                         | Object-specific data           |

## Class Variable Example: Shared Data

Suppose every student belongs to the same school.

```python
class Student:
    school = "ABC School"

    def __init__(self, name):
        self.name = name


s1 = Student("Rahul")
s2 = Student("Aman")
s3 = Student("Priya")

print(s1.school)  # ABC School
print(s2.school)  # ABC School
print(s3.school)  # ABC School
```

There is no need to store `"ABC School"` separately as an instance attribute for every student if the value is intended to be common.

Conceptually:

```text
              Student
                 │
       school = "ABC School"
          /       |       \
        s1       s2       s3
       Rahul    Aman     Priya
```

## Instance Variable Example: Object-Specific Data

Suppose each bank account has a different balance.

```python
class BankAccount:
    bank_name = "ABC Bank"     # class variable

    def __init__(self, holder, balance):
        self.holder = holder   # instance variable
        self.balance = balance # instance variable


a1 = BankAccount("Rahul", 5000)
a2 = BankAccount("Aman", 8000)

print(a1.bank_name)  # ABC Bank
print(a2.bank_name)  # ABC Bank

print(a1.balance)    # 5000
print(a2.balance)    # 8000
```

Here:

```text
bank_name → shared by accounts
holder    → specific to each account
balance   → specific to each account
```

This is one of the most important practical distinctions between class and instance variables.

# Example with Modification

```python
class Employee:
    company = "TechCorp"

    def __init__(self, name):
        self.name = name


e1 = Employee("Rahul")
e2 = Employee("Aman")

Employee.company = "NewTech"

print(e1.company)  # NewTech
print(e2.company)  # NewTech
```

Because `company` is a class variable, changing the class-level value affects what both instances see **unless an instance has its own attribute with that name**.

In contrast:

```python
e1.name = "Rohit"

print(e1.name)  # Rohit
print(e2.name)  # Aman
```

Changing `e1.name` does not change `e2.name`, because `name` is an instance variable.

Conceptually:

```text
Before:

Employee.company
       │
       ├── e1 → TechCorp
       └── e2 → TechCorp


After:

Employee.company = "NewTech"
       │
       ├── e1 → NewTech
       └── e2 → NewTech
```

But:

```text
e1.name = "Rohit"

e1 → Rohit
e2 → Aman
```

The two `name` values are independent.

# Important Python Nuance

If you assign an attribute through an instance:

```python
e1.company = "ABC"
```

Python creates an **instance attribute** named `company` for `e1`, which can **shadow** the class variable:

```python
print(e1.company)  # ABC
print(e2.company)  # NewTech
```

Why?

Initially:

```text
Employee.company → "NewTech"
```

After:

```python
e1.company = "ABC"
```

the object `e1` now has its own `company` attribute:

```text
Employee
└── company = "NewTech"       ← class variable

e1
├── name = "Rahul"
└── company = "ABC"           ← instance attribute

e2
└── name = "Aman"
```

When Python evaluates:

```python
e1.company
```

it finds `company` on `e1` first, so `"ABC"` is returned.

For `e2`:

```python
e2.company
```

there is no instance-level `company`, so Python can find the class variable and returns `"NewTech"`.

So class and instance attributes with the same name can **coexist**.

## Important Interview Point

A class variable is not necessarily copied into every object.

For example:

```python
class Student:
    school = "ABC School"
```

The class owns `school`. Instances can access it through attribute lookup:

```python
s1.school
```

But unless an instance assigns its own `school`, it does not need to maintain a separate instance-level value.

This distinction becomes especially important when working with mutable class variables.

For example:

```python
class Student:
    subjects = []

s1 = Student()
s2 = Student()

s1.subjects.append("Python")

print(s2.subjects)
```

Output:

```text
['Python']
```

Why?

Because `subjects` is a **class-level list**, so both objects can access the same list.

Therefore, mutable class variables should be used carefully.

A safer approach for object-specific data is:

```python
class Student:
    def __init__(self):
        self.subjects = []


s1 = Student()
s2 = Student()

s1.subjects.append("Python")

print(s1.subjects)  # ['Python']
print(s2.subjects)  # []
```

Now each object has its own separate list.

# When Should You Use Each?

### Use a Class Variable When:

* The data is common to all objects.
* The value represents class-level information.
* You intentionally want the value to be shared.
* Examples:

  * Company name
  * School name
  * Tax rate
  * Configuration shared by instances
  * Object counter

Example:

```python
class Employee:
    company = "TechCorp"
```

### Use an Instance Variable When:

* The data is different for each object.
* The data represents the object's state.
* Each object needs an independent value.

Example:

```python
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary
```

Here `name` and `salary` belong to individual employees.

# Easy Way to Remember

```text
Class Variable
     ↓
"What is common to all objects?"

Instance Variable
     ↓
"What is different for each object?"
```

For example:

```text
Employee
│
├── company = "TechCorp"    ← Class variable
│
├── Rahul
│   ├── name = "Rahul"       ← Instance variable
│   └── salary = 50000
│
└── Aman
    ├── name = "Aman"        ← Instance variable
    └── salary = 60000
```

# Interview Takeaway

> **Class variables represent data shared at the class level, while instance variables represent data specific to individual objects.**

In Python:

* Class variables are typically defined directly inside the class.
* Instance variables are usually created through `self`.
* Class variables are generally shared among instances.
* Instance variables have separate values for individual objects.
* Assigning an attribute through an instance can create an instance attribute that **shadows** a class variable with the same name.
* Mutable class variables should be used carefully because the same mutable object may be shared by multiple instances.
