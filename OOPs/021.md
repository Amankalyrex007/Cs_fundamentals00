Why is composition often preferred over inheritance?
Answer

Composition is often preferred over inheritance because it generally provides greater flexibility, lower coupling, and easier maintenance.

The basic idea is:

Inheritance = “is-a” relationship
Composition = “has-a” relationship

With inheritance, a child class becomes tightly connected to the parent class. With composition, a class uses other objects as components, which can often be replaced or modified independently.

Example

Suppose we have different notification methods.

Using inheritance:

class EmailNotification:
    def send(self, message):
        print("Sending email")


class SMSNotification:
    def send(self, message):
        print("Sending SMS")

Now imagine a service that needs to support different notification mechanisms. Composition allows the notification behavior to be injected:

class EmailNotification:
    def send(self, message):
        print("Sending email:", message)


class SMSNotification:
    def send(self, message):
        print("Sending SMS:", message)


class NotificationService:
    def __init__(self, notification):
        self.notification = notification

    def send(self, message):
        self.notification.send(message)

Now we can use either implementation:

service1 = NotificationService(EmailNotification())
service2 = NotificationService(SMSNotification())

service1.send("Hello")
service2.send("Hello")

The NotificationService doesn't need to inherit from EmailNotification or SMSNotification. It simply has a notification object.

Why composition is often preferred
1. Lower coupling

Inheritance creates a strong dependency between child and parent.

Child ──inherits──> Parent

Changes to the parent can potentially affect many subclasses.

With composition:

Service ──has-a──> Component

The components can be developed and changed more independently.

2. Greater flexibility

A composed object can often be given a different component at runtime.

service = NotificationService(EmailNotification())

# Later:
service.notification = SMSNotification()

The behavior can change without changing the class hierarchy.

3. Easier testing

Dependencies can be replaced with simple mock or test objects.

class FakeNotification:
    def send(self, message):
        print("Test notification")

Then:

service = NotificationService(FakeNotification())

This makes unit testing easier.

4. Avoids deep inheritance hierarchies

Large inheritance trees can become difficult to understand and maintain:

Object
  ↓
Vehicle
  ↓
Car
  ↓
ElectricCar
  ↓
LuxuryElectricCar

Composition can instead build behavior from smaller components:

Car
 ├── Engine
 ├── Battery
 ├── Navigation
 └── PaymentSystem

Each component can have a focused responsibility.

5. Supports the principle of programming to abstractions

Composition works especially well with interfaces, abstract classes, or protocols.

For example:

NotificationService
        │
        ▼
   Notification
    /       \
 Email      SMS

NotificationService depends on the expected behavior rather than a specific implementation.

Composition vs inheritance
Aspect	Composition	Inheritance
Relationship	Has-a	Is-a
Coupling	Generally lower	Generally higher
Flexibility	Usually higher	More constrained by hierarchy
Code reuse	Through contained objects	Through parent classes
Runtime replacement	Easier	Usually harder
Testing	Dependencies can be substituted easily	Can be more tightly coupled
Best use	Combining behaviors/components	Genuine subtype relationships
Important point

Composition is not always better.

Inheritance is appropriate when there is a genuine subtype relationship:

Dog IS-A Animal
Car IS-A Vehicle

If the subclass truly represents a specialized form of the parent and should conform to its contract, inheritance can be a good design.

But using inheritance only to reuse code can create unnecessary coupling. In such situations, composition is often a cleaner alternative.

Interview takeaway

Composition is often preferred over inheritance because it reduces coupling, improves flexibility and testability, and avoids rigid inheritance hierarchies. However, inheritance remains appropriate when there is a genuine “is-a” relationship and substitutability makes sense.
