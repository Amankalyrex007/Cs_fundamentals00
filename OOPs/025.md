25.What is coupling and cohesion?
Answer

Coupling and cohesion are important software design concepts used to evaluate how well a system is structured.

A simple rule to remember is:

Low coupling + High cohesion = generally better modular design

Coupling → how much one module/class depends on other modules/classes.
Cohesion → how closely the responsibilities inside a module/class belong together.
1. Coupling

Coupling measures the dependency between different components.

High coupling

If one class heavily depends on the internal details of another class, they are tightly coupled.

class EmailService:
    def send_email(self, message):
        print("Email sent")


class OrderService:
    def __init__(self):
        self.email = EmailService()

    def place_order(self):
        # order logic
        self.email.send_email("Order placed")

Here, OrderService directly creates and depends on EmailService.

If the notification mechanism changes significantly, OrderService may need to change too.

Low coupling

We can reduce coupling by depending on an abstraction and injecting the dependency:

class NotificationService:
    def send(self, message):
        pass


class OrderService:
    def __init__(self, notification):
        self.notification = notification

    def place_order(self):
        self.notification.send("Order placed")

Now OrderService doesn't need to know whether the notification is sent through email, SMS, or another mechanism.

Why low coupling is useful

Low coupling generally makes a system:

Easier to modify
Easier to test
Easier to extend
Less affected by changes in other components
Easier to maintain
2. Cohesion

Cohesion measures how closely related the responsibilities within a single module or class are.

High cohesion

A class has high cohesion when its methods and data are focused on one closely related responsibility.

class UserValidator:
    def validate_email(self, email):
        pass

    def validate_password(self, password):
        pass

    def validate_username(self, username):
        pass

All these methods are related to user validation, so the class has a focused responsibility.

Low cohesion

A class with unrelated responsibilities has low cohesion:

class UserManager:
    def validate_user(self):
        pass

    def generate_report(self):
        pass

    def send_email(self):
        pass

    def calculate_salary(self):
        pass

User validation, reporting, email delivery, and salary calculation are unrelated responsibilities.

This class becomes difficult to understand and maintain.

A better design could separate them:

UserValidator
ReportGenerator
EmailService
SalaryCalculator

Each component then has a more focused purpose.

Coupling vs cohesion
Aspect	Coupling	Cohesion
Measures	Dependency between components	Relatedness within a component
Desired level	Low	High
Focus	Relationships between modules	Responsibilities inside a module
Example	OrderService depends on EmailService	OrderValidator contains validation logic
Benefit	Easier changes and testing	Clearer, focused components
Easy way to remember

Think about a team:

Low coupling:

Team A ←→ Team B

Teams can work relatively independently.

High cohesion:

Team A
├── Task 1
├── Task 2
└── Task 3

All tasks are closely related to the team's purpose.

So:

Coupling asks: "How dependent are these components on each other?"

Cohesion asks: "How closely related are the responsibilities inside this component?"

Connection with SOLID

These concepts appear throughout good OOP design:

SRP encourages focused responsibilities → high cohesion
DIP helps reduce dependencies → low coupling
Composition can often help reduce unnecessary coupling
Interfaces/abstractions can separate components cleanly
Interview takeaway

Coupling measures how strongly different modules depend on each other, while cohesion measures how closely related the responsibilities within a module are. Good software design generally aims for low coupling and high cohesion.
