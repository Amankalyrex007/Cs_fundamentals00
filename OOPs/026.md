# Q26. What is Shallow Copy vs Deep Copy?

## Answer

**Shallow copy** and **deep copy** describe how an object is copied, especially when the object contains **nested or mutable objects**.

The key difference is:

> **Shallow copy copies the outer object but shares references to nested objects.**
> **Deep copy recursively copies the nested objects as well.**

A simple way to remember:

```text
Shallow Copy
    ↓
New outer object
    ↓
Shared nested objects

Deep Copy
    ↓
New outer object
    ↓
New nested objects
```

This distinction becomes especially important when working with mutable objects such as:

* Lists
* Dictionaries
* Sets
* Custom objects
* Objects containing other mutable objects

---

# 1. Shallow Copy

## Definition

A **shallow copy** creates a new outer object, but the objects inside it are still shared with the original.

In Python, it can be created using `copy.copy()`:

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)

shallow[0][0] = 100

print(original)
print(shallow)
```

### Output

```text
[[100, 2], [3, 4]]
[[100, 2], [3, 4]]
```

## Why did `original` change?

Because both lists contain a reference to the **same inner list**.

The outer list was copied, but the nested lists were not.

Conceptually:

```text
original ──→ [ ──→ [1, 2]
              └──→ [3, 4] ]

shallow  ──→ [ ──→ [1, 2]  ← same inner object
              └──→ [3, 4]  ← same inner object
            ]
```

More precisely:

```text
                 ┌──────────────┐
original ───────→│  outer list  │
                 └──────┬───────┘
                        │
                  ┌─────┴─────┐
                  ▼           ▼
              [1, 2]        [3, 4]
                 ▲             ▲
                 │             │
                 └─────┬───────┘
                       │
                 shallow list
```

The **outer list is different**, but the nested lists are shared.

---

# Shallow Copy Example with a Dictionary

The same concept applies to dictionaries.

```python
import copy

original = {
    "name": "Rahul",
    "skills": ["Python", "Java"]
}

shallow = copy.copy(original)

shallow["skills"].append("C++")

print(original)
print(shallow)
```

### Output

```text
{'name': 'Rahul', 'skills': ['Python', 'Java', 'C++']}
{'name': 'Rahul', 'skills': ['Python', 'Java', 'C++']}
```

Why?

Because:

```text
original["skills"]
        │
        ▼
["Python", "Java"]

shallow["skills"]
        │
        └──────→ same list
```

The dictionary itself is copied, but its nested list is shared.

---

# Important Shallow Copy Point

If you modify a **top-level value**, the behavior can be different.

For example:

```python
import copy

original = [1, 2, 3]
shallow = copy.copy(original)

shallow[0] = 100

print(original)
print(shallow)
```

Output:

```text
[1, 2, 3]
[100, 2, 3]
```

Here the original does not change because the top-level list itself was copied.

Therefore, the important issue with shallow copy is usually **nested mutable objects**.

---

# 2. Deep Copy

## Definition

A **deep copy** creates a new outer object and recursively creates copies of nested objects.

In Python:

```python
import copy

original = [[1, 2], [3, 4]]
deep = copy.deepcopy(original)

deep[0][0] = 100

print(original)
print(deep)
```

### Output

```text
[[1, 2], [3, 4]]
[[100, 2], [3, 4]]
```

Here, modifying the nested list in `deep` does not affect `original`.

Conceptually:

```text
original ──→ [ ──→ [1, 2]
              └──→ [3, 4] ]

deep ──────→ [ ──→ [100, 2]  ← separate object
              └──→ [3, 4]    ← separate object
            ]
```

The important point is:

```text
original inner list
        │
        X
        │
deep inner list
```

They are separate objects.

---

# Deep Copy Example with Nested Dictionaries

Consider:

```python
import copy

original = {
    "user": {
        "name": "Aman",
        "skills": ["Python", "SQL"]
    }
}

deep = copy.deepcopy(original)

deep["user"]["skills"].append("Docker")

print(original)
print(deep)
```

Output:

```text
{
    'user': {
        'name': 'Aman',
        'skills': ['Python', 'SQL']
    }
}

{
    'user': {
        'name': 'Aman',
        'skills': ['Python', 'SQL', 'Docker']
    }
}
```

The nested dictionary and nested list were independently copied.

---

# Shallow vs Deep Copy

| Feature                           | Shallow Copy      | Deep Copy          |
| --------------------------------- | ----------------- | ------------------ |
| Outer object                      | New copy          | New copy           |
| Nested objects                    | Shared references | Recursively copied |
| Nested mutation affects original? | Usually yes       | Usually no         |
| Python function                   | `copy.copy()`     | `copy.deepcopy()`  |
| Memory usage                      | Generally lower   | Generally higher   |
| Copying cost                      | Generally lower   | Generally higher   |
| Object independence               | Partial           | Greater/recursive  |

# Simple Example to Remember

Consider:

```python
original = [1, [2, 3]]
```

## With a Shallow Copy

```text
New outer list
      ↓
Same inner list
```

Conceptually:

```text
original ──→ [1, ─────→ [2, 3]]
                          ▲
shallow  ──→ [1, ────────┘
```

Therefore:

```python
shallow[1].append(4)
```

can also affect:

```python
original
```

because both refer to the same inner list.

---

## With a Deep Copy

```text
New outer list
      ↓
New inner list
```

Conceptually:

```text
original ──→ [1, ──→ [2, 3]]

deep ──────→ [1, ──→ [2, 3]]
                      ↑
                 different object
```

Therefore:

```python
deep[1].append(4)
```

does not modify the inner list inside `original`.

---

# How to Verify This Using `id()`

Python's `id()` can help demonstrate whether two variables refer to the same object.

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

print(original is shallow)
print(original[0] is shallow[0])

print(original is deep)
print(original[0] is deep[0])
```

Output:

```text
False
True
False
False
```

This tells us:

```text
original is shallow
        ↓
      False
```

The outer objects are different.

But:

```text
original[0] is shallow[0]
        ↓
      True
```

The first nested list is shared.

For deep copy:

```text
original is deep
        ↓
      False

original[0] is deep[0]
        ↓
      False
```

Both the outer and nested objects are separate.

# Important Distinction: Assignment Is Neither

This is another common interview mistake:

```python
a = [[1, 2], [3, 4]]
b = a
```

This does **not** create a copy.

Both variables refer to the same object:

```text
a ──┐
    │
    ├──→ [[1, 2], [3, 4]]
    │
b ──┘
```

Therefore:

```python
b[0][0] = 100

print(a)
```

Output:

```text
[[100, 2], [3, 4]]
```

Because `a` and `b` refer to exactly the same list.

---

# Three Different Situations

It is useful to compare all three:

```python
import copy

a = [[1, 2], [3, 4]]

b = a
c = copy.copy(a)
d = copy.deepcopy(a)
```

Conceptually:

```text
Assignment
───────────

a ──┐
    └──→ Outer ──→ Inner
b ──┘


Shallow Copy
────────────

c ──→ New Outer ──→ Same Inner
                     ▲
a ──→ Original ──────┘


Deep Copy
─────────

d ──→ New Outer ──→ New Inner

a ──→ Original  ──→ Original Inner
```

Therefore:

| Operation          | Outer Object | Nested Object   |
| ------------------ | ------------ | --------------- |
| `b = a`            | Same         | Same            |
| `copy.copy(a)`     | New          | Usually shared  |
| `copy.deepcopy(a)` | New          | New recursively |

# When Should You Use Each?

## Use Shallow Copy When

Use shallow copy when:

* Sharing nested objects is acceptable.
* You only need an independent outer container.
* Nested objects are immutable.
* You want a cheaper copy operation.
* You intentionally want some nested objects to remain shared.

For example:

```python
original = ["Python", "Java", "C++"]
```

A shallow copy is often sufficient because strings are immutable.

---

## Use Deep Copy When

Use deep copy when:

* You need an independent object graph.
* Nested mutable objects must not be shared.
* Changes to nested objects should not affect the original.
* You are creating an independent snapshot of a nested data structure.

For example:

```python
import copy

configuration = {
    "database": {
        "host": "localhost",
        "port": 5432
    }
}

backup = copy.deepcopy(configuration)
```

Now modifying the nested configuration in `backup` will not modify the original configuration.

---

# But Don't Automatically Use `deepcopy()`

`deepcopy()` can be expensive and can have special behavior with custom objects, recursive structures, and resources.

Therefore, it should not be used automatically.

Often, explicitly constructing the required data structure is clearer and more efficient.

For example, instead of blindly copying an entire object:

```python
backup = copy.deepcopy(configuration)
```

you might only copy the fields that actually need independence:

```python
backup = {
    "database": {
        "host": configuration["database"]["host"],
        "port": configuration["database"]["port"]
    }
}
```

The appropriate approach depends on the structure and requirements of the application.

# Mutable vs Immutable Objects

Understanding mutability makes shallow vs deep copy much easier.

### Immutable objects

Examples include:

```text
int
float
str
tuple (when it contains only immutable elements)
bool
```

They cannot be changed in place.

### Mutable objects

Examples include:

```text
list
dict
set
many custom objects
```

They can be changed after creation.

This is why shallow/deep copy becomes especially important with nested mutable objects.

For example:

```python
original = [1, [2, 3]]
```

The outer list is mutable, and the inner list is also mutable.

Therefore, sharing the inner list matters.

---

# Copying Custom Objects

The same concept applies to custom classes.

```python
import copy

class Student:
    def __init__(self, name, subjects):
        self.name = name
        self.subjects = subjects


student1 = Student("Rahul", ["Python", "SQL"])

student2 = copy.copy(student1)

student2.subjects.append("Java")

print(student1.subjects)
print(student2.subjects)
```

Output:

```text
['Python', 'SQL', 'Java']
['Python', 'SQL', 'Java']
```

Why?

Because the `Student` object was shallow-copied, but the `subjects` list is still shared.

With deep copy:

```python
student3 = copy.deepcopy(student1)

student3.subjects.append("Docker")

print(student1.subjects)
print(student3.subjects)
```

The nested list is independently copied.

# Common Interview Traps

### Trap 1: `b = a` is a copy

Incorrect.

```python
b = a
```

creates another reference to the same object.

---

### Trap 2: Shallow copy means no copying

Incorrect.

A shallow copy **does create a new outer object**.

The nested objects are the ones that may remain shared.

---

### Trap 3: Deep copy means every value is duplicated

Not necessarily in a simplistic byte-for-byte sense.

Deep copying recursively creates independent copies of objects where Python's copy mechanism considers them copyable. Immutable objects may safely be reused, and custom objects can define special copying behavior.

---

### Trap 4: Deep copy is always better

Incorrect.

Deep copy generally costs more memory and processing time.

If nested objects do not need to be independent, shallow copying or explicit construction may be preferable.

# Interview Takeaway

> **Shallow copy creates a new outer object but keeps references to nested objects, while deep copy recursively creates independent copies of nested objects.**

In Python:

```python
copy.copy()
```

performs a **shallow copy**.

```python
copy.deepcopy()
```

performs a **deep copy**.

And remember the important distinction:

```text
a = b
    ↓
No copy — same object

copy.copy()
    ↓
New outer object
Shared nested objects

copy.deepcopy()
    ↓
New outer object
Independent nested objects
```

The core interview rule is:

```text
Shallow Copy → Copy the container, share nested references

Deep Copy    → Copy the container and recursively copy nested objects
```
