## Definition

A **process** is a **program that is currently executing**.

A **program** is a passive set of instructions stored on disk, while a **process** is the active execution of those instructions, together with the **state and resources required to run them**.

```text
Program (Passive)
Stored on Disk
      ↓
   Execution
      ↓
Process (Active)
Memory + CPU + Execution State + Resources
```

---

## Example

Suppose you have a Python program:

```python
print("Hello")
```

The `.py` file stored on your computer is a **program**.

When you execute it:

```text
Python Program
      ↓
Operating System
      ↓
Running Process
```

The OS creates and manages a process, providing resources such as **memory, CPU time, and access to required files/devices**.

---

## What Does a Process Contain?

A process typically has:

| Component                | Purpose                                                 |
| ------------------------ | ------------------------------------------------------- |
| **Program Code (Text)**  | Instructions being executed                             |
| **Data**                 | Global and static variables                             |
| **Heap**                 | Dynamically allocated memory                            |
| **Stack**                | Function calls, parameters, and local variables         |
| **Program Counter (PC)** | Address of the next instruction to execute              |
| **CPU Registers**        | Current CPU execution information                       |
| **Process State**        | Current state such as Ready or Running                  |
| **Open Files/Resources** | Files, sockets, and other resources used by the process |

The OS maintains information about a process in a data structure commonly called a **Process Control Block (PCB)**.

### Process Control Block (PCB)

Conceptually:

```text
PCB
├── Process ID (PID)
├── Process State
├── Program Counter
├── CPU Registers
├── Scheduling Information
├── Memory Management Information
└── Open Resources / File Information
```

The PCB allows the OS to keep track of and manage the process, including during a **context switch**.

## Process States

A process can move through different states during its lifetime:

```text
              +---------+
              |   New   |
              +----+----+
                   |
                   v
              +---------+
        +---->|  Ready  |<---------+
        |     +----+----+          |
        |          |               |
        |     CPU assigned         |
        |          v               |
        |     +---------+          |
        +-----| Running |----------+
       Preemption +----+----+       |
                     |              |
                I/O Request         |
                     v              |
                +---------+         |
                | Waiting |         |
                +----+----+         |
                     |              |
                I/O Complete        |
                     |              |
                     +------------> Ready
                     
                     Running
                       |
                       v
                 +-----------+
                 | Terminated|
                 +-----------+
```

Common process states are:

* **New** → Process is being created.
* **Ready** → Process is ready to execute but waiting for CPU time.
* **Running** → Process is currently executing on the CPU.
* **Waiting / Blocked** → Process is waiting for an event, such as I/O completion.
* **Terminated** → Process has finished execution.

> **Note:** Actual operating systems may use additional or more detailed states internally.

## Process vs Program

| Program                                      | Process                                          |
| -------------------------------------------- | ------------------------------------------------ |
| **Passive**                                  | **Active**                                       |
| Stored instructions                          | Instructions currently executing                 |
| Usually stored on disk                       | Uses memory and CPU resources                    |
| Doesn't have execution state                 | Has execution state                              |
| Does not require an active execution context | Has an execution context and allocated resources |
| One program can create multiple processes    | Each process has its own execution context       |

### Example

If you open two instances of an application, the OS may create **multiple processes**, depending on how the application is designed and how the OS manages it.

```text
Program
   │
   ├── Process 1
   │
   └── Process 2
```

---

## Process vs Thread

A **process** is generally a **resource and protection boundary**, while a **thread** is an **execution unit within a process**.

```text
Process
├── Code
├── Data
├── Heap
├── Resources
├── Thread 1
├── Thread 2
└── Thread 3
```

Multiple threads within the same process generally **share the process's address space and resources**, while separate processes normally have **isolated address spaces**.

For example, a web browser may use multiple threads within a process to perform different tasks concurrently.

---

## Important Concept: Process Is More Than Just Code

A process is not simply a program copied into RAM.

It includes:

```text
Process
   │
   ├── Program Code
   ├── Data
   ├── Heap
   ├── Stack
   ├── CPU Registers
   ├── Program Counter
   ├── Process State
   └── OS-managed Resources
```

This complete execution context is what allows the OS to **schedule, suspend, resume, and terminate** the process.

---

## Interview Takeaway

> **A process is a program in execution, together with its execution state, memory, and allocated resources. The OS manages processes by creating, scheduling, suspending, and terminating them.**
