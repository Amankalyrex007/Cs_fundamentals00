3.What is a thread?
Definition

A thread is the smallest unit of CPU execution within a process.

A process can contain one or more threads. Threads within the same process generally share the process's memory and resources, but each thread has its own execution state, stack, and CPU registers.

Example

Imagine a web server handling multiple requests:

Web Server Process
│
├── Thread 1 → handles Request A
├── Thread 2 → handles Request B
└── Thread 3 → handles Request C

Instead of creating a separate process for every request, the server can use multiple threads within the same process.

What does a thread have?

Each thread typically has its own:

Program counter — next instruction to execute
CPU registers
Stack — function calls and local variables
Thread state

Threads within the same process generally share:

Code
Heap
Global/static data
Open resources such as files/sockets
Process
├── Shared Code
├── Shared Heap
├── Shared Data
│
├── Thread 1
│   └── Own Stack + Registers
│
├── Thread 2
│   └── Own Stack + Registers
│
└── Thread 3
    └── Own Stack + Registers
Why are threads used?

Threads are useful when a program needs to perform multiple activities concurrently.

Common examples:

Web servers handling multiple requests
Background tasks
GUI applications
Parallel computation
I/O operations

For example, a GUI application could have:

Main Thread       → handles user interface
Worker Thread     → performs a long computation
Network Thread    → handles network communication

This can prevent a long-running operation from blocking the user interface.

Process vs Thread
Process	Thread
Program in execution	Execution unit within a process
Has its own address space	Usually shares address space with other threads in the process
More expensive to create/switch	Generally cheaper to create/switch
Communication often requires IPC mechanisms	Communication can use shared memory
Stronger isolation	Less isolation
Failure is generally isolated from other processes	An unsafe thread can affect the entire process

The exact performance and implementation details depend on the operating system and runtime.

Important challenge: synchronization

Because threads can share memory, multiple threads can access the same data concurrently.

For example:

counter = counter + 1

If multiple threads modify counter at the same time, a race condition can occur.

Synchronization mechanisms such as:

Mutex/locks
Semaphores
Condition variables
Atomic operations

can be used when required.

Thread vs Process — simple intuition

Think of a process as a house and threads as people working inside that house.

The house has its own resources and boundaries.
People inside can share the house's resources.
Each person has their own current activity and workspace.
Because they share resources, they need coordination to avoid conflicts.
Interview takeaway

A thread is the smallest unit of execution within a process. Multiple threads can run concurrently while sharing the process's memory and resources, but each thread maintains its own execution state, stack, and registers.
