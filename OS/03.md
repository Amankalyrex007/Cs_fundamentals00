# Q3. What is a Thread?

## Definition

A **thread** is the **smallest unit of execution that can be scheduled by the OS within a process**.

A process can contain one or more threads. Threads within the same process generally **share the process's memory and resources**, but each thread has its own **execution state, stack, and CPU registers**.

```text
Process
│
├── Shared Memory & Resources
│
├── Thread 1
├── Thread 2
└── Thread 3
```

---

## Example

Imagine a web server handling multiple requests:

```text
Web Server Process
│
├── Thread 1 → handles Request A
├── Thread 2 → handles Request B
└── Thread 3 → handles Request C
```

Instead of creating a separate process for every request, the server can use multiple threads within the same process.

This can reduce the overhead associated with creating and managing separate processes.

---

## What Does a Thread Have?

Each thread typically has its own:

| Component           | Purpose                                         |
| ------------------- | ----------------------------------------------- |
| **Program Counter** | Address of the next instruction to execute      |
| **CPU Registers**   | Current CPU execution state                     |
| **Stack**           | Function calls, parameters, and local variables |
| **Thread State**    | Current state such as Running or Waiting        |

Threads within the same process generally share:

* Code
* Heap
* Global/static data
* Open resources such as files and sockets

```text
Process
├── Shared Code
├── Shared Heap
├── Shared Data
│
├── Thread 1
│   └── Own Stack + Registers
│
├── Thread 2
│   └── Own Stack + Registers
│
└── Thread 3
    └── Own Stack + Registers
```

### Key Idea

```text
Same Process
     │
     ├── Shared → Code, Heap, Global Data, Resources
     │
     └── Private → Stack, Registers, Execution State
```

---

## Why Are Threads Used?

Threads are useful when a program needs to perform multiple activities concurrently.

Common examples include:

* Web servers handling multiple requests
* Background tasks
* GUI applications
* Parallel computation
* I/O operations

### Example: GUI Application

A GUI application could use:

```text
Main Thread       → Handles user interface
Worker Thread     → Performs a long computation
Network Thread    → Handles network communication
```

This can prevent a long-running computation or network operation from blocking the user interface.

## Process vs Thread

| Process                                            | Thread                                                         |
| -------------------------------------------------- | -------------------------------------------------------------- |
| Program in execution                               | Execution unit within a process                                |
| Has its own address space                          | Usually shares address space with other threads in the process |
| Generally more expensive to create/manage          | Generally cheaper to create/manage                             |
| Communication often requires IPC mechanisms        | Can communicate through shared memory                          |
| Stronger isolation                                 | Less isolation                                                 |
| Failure is generally isolated from other processes | An unsafe thread can affect the entire process                 |

> The exact performance and implementation details depend on the **operating system, runtime, and thread implementation**.

## Important Challenge: Synchronization

Because threads can share memory, multiple threads may access the same data concurrently.

For example:

```python
counter = counter + 1
```

This looks like one operation, but conceptually it involves:

```text
Read counter
     ↓
Add 1
     ↓
Write counter
```

If two threads perform this operation simultaneously, their operations can interleave and cause a **race condition**.

### Example

Suppose:

```text
counter = 5
```

Two threads execute `counter = counter + 1`:

```text
Thread 1 → Reads 5
Thread 2 → Reads 5
Thread 1 → Writes 6
Thread 2 → Writes 6
```

Expected result:

```text
7
```

Actual result:

```text
6
```

This is a classic **lost update** caused by concurrent access without proper synchronization.

### Common Synchronization Mechanisms

* **Mutex / Locks** → Allow only one thread at a time to enter a critical section.
* **Semaphores** → Control access to shared resources using permits/counters.
* **Condition Variables** → Allow threads to wait until a particular condition becomes true.
* **Atomic Operations** → Perform certain operations indivisibly.

## Thread vs Process — Simple Intuition

Think of a **process as a house** and **threads as people working inside that house**.

```text
House = Process
│
├── Person 1 = Thread
├── Person 2 = Thread
└── Person 3 = Thread
```

The house has its own resources and boundaries.

The people inside can share the house's resources, but each person has their own current activity and workspace.

Because they share resources, they need **coordination** to avoid conflicts.

---

## Important Relationship

A process can contain:

```text
Process
│
├── Thread 1
├── Thread 2
├── Thread 3
└── Thread 4
```

A **single-threaded process** has one thread, while a **multithreaded process** has multiple threads.

```text
Single-threaded
Process
└── Thread 1

Multithreaded
Process
├── Thread 1
├── Thread 2
└── Thread 3
```

## Interview Takeaway

> **A thread is the smallest unit of execution that can be scheduled by the OS within a process. Multiple threads can execute concurrently while sharing the process's memory and resources, but each thread maintains its own execution state, stack, and registers.**

### Quick Memory Trick

**Process = Resource & Protection Boundary**

**Thread = Execution Unit**

**Threads share → Memory & Resources**

**Threads own → Stack, Registers & Execution State**
