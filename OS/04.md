# Q4. Process vs Thread?

A **process** is a program in execution, while a **thread** is an execution unit within a process.

The key difference is that a process generally provides an **isolated address space and resource boundary**, whereas threads within the same process generally **share that process's resources and address space**.

---

## Key Differences

| Process                                                 | Thread                                                |
| ------------------------------------------------------- | ----------------------------------------------------- |
| Independent program in execution                        | Execution unit within a process                       |
| Has its own virtual address space                       | Shares the process's address space                    |
| Has its own process-level resources and execution state | Shares many resources with other threads              |
| Relatively expensive to create/manage                   | Generally cheaper to create/manage                    |
| Context switching is generally more expensive           | Context switching is generally lighter                |
| Communication often requires IPC                        | Can communicate through shared memory                 |
| Provides stronger isolation                             | Less isolated from other threads                      |
| Failure is generally isolated to that process           | A serious thread failure can affect the whole process |
| Has at least one thread                                 | A process can contain multiple threads                |

> Exact creation and context-switching costs depend on the operating system and runtime, so "more expensive" and "lighter" are general comparisons.

---

## Memory Model

Consider a process with three threads:

```text
Process
│
├── Code             ← Shared
├── Heap             ← Shared
├── Global Data      ← Shared
│
├── Thread 1
│   └── Stack + Registers    ← Private
│
├── Thread 2
│   └── Stack + Registers    ← Private
│
└── Thread 3
    └── Stack + Registers    ← Private
```

### What is Shared?

Threads within the same process generally share:

* Code
* Heap
* Global/static data
* Open files and other process-level resources

### What is Private?

Each thread generally has its own:

* Stack
* Program counter
* CPU registers
* Thread execution state

This shared memory makes threads efficient for communication, but it also introduces problems such as **race conditions**, so synchronization may be required.

---

## Example: Web Server

A web server could use multiple threads within one process:

```text
Process
│
├── Thread 1 → Request A
├── Thread 2 → Request B
├── Thread 3 → Request C
└── Thread 4 → Request D
```

These threads can share resources such as:

* Application data
* In-memory caches
* Configuration
* Database connection pools

This can make communication between tasks efficient.

### Using Multiple Processes Instead

The server could alternatively use separate processes:

```text
Process 1 → Request A
Process 2 → Request B
Process 3 → Request C
```

Each process normally has its own address space, providing stronger isolation.

However, communication between them generally requires **Inter-Process Communication (IPC)** mechanisms such as pipes, sockets, or shared memory.

---

## Process vs Thread: Communication

One major difference is how they share data.

### Processes

```text
Process A                 Process B
   │                         │
   └────── IPC ──────────────┘
```

Processes normally have separate address spaces, so communication requires explicit mechanisms.

### Threads

```text
Thread 1 ──┐
Thread 2 ──┼── Shared Memory
Thread 3 ──┘
```

Threads can directly access shared memory within their process.

This is efficient, but unsafe concurrent access can cause **race conditions**.

---

## Simple Analogy

Think of a **process as a house** and **threads as people working inside the house**.

| Analogy                                    | OS Concept                                      |
| ------------------------------------------ | ----------------------------------------------- |
| House has its own resources and boundaries | Process has its own address space/resources     |
| People work inside the same house          | Threads share process resources                 |
| Each person has their own workspace        | Each thread has its own stack/execution state   |
| People must coordinate when sharing things | Threads require synchronization for shared data |

## When Would You Use Each?

### Multiple Processes Are Useful When You Need:

* **Strong isolation**
* **Fault containment**
* **Separate security boundaries**
* **Independent applications or services**

For example, separate processes can help prevent a failure in one application component from directly corrupting another process's memory.

### Multiple Threads Are Useful When You Need:

* Concurrent tasks within the same application
* Shared-memory communication
* Efficient handling of I/O
* Multiple activities executing concurrently
* Parallel computation when the workload and runtime support it

For example:

```text
Application Process
│
├── UI Thread
├── Network Thread
└── Worker Thread
```

## Quick Comparison

```text
Process
│
├── Own Address Space
├── Strong Isolation
├── Higher Resource Overhead
└── Contains One or More Threads

Thread
│
├── Shares Process Address Space
├── Lower Isolation
├── Generally Lower Overhead
└── Has Its Own Stack + Registers + Execution State
```

---

## Interview Takeaway

> **A process provides an isolated execution environment with its own address space, while a thread is an execution unit inside a process that shares the process's resources. Processes provide stronger isolation; threads generally provide lighter-weight concurrency but require careful synchronization when sharing data.**

### Quick Memory Trick

**Process → Isolation + Resources**

**Thread → Execution + Sharing**
