# Q6. What is a Process Control Block (PCB)?

## Definition

A **Process Control Block (PCB)** is a **data structure maintained by the operating system to store important information about a process**.

The OS uses the PCB to **manage, schedule, suspend, resume, and track** a process throughout its lifetime.

You can think of the PCB as the process's **official record maintained by the OS**.

```text id="f0p8gc"
Operating System
       │
       ├── PCB → Process 1
       ├── PCB → Process 2
       ├── PCB → Process 3
       └── PCB → Process 4
```

Every process needs information that allows the OS to know **what the process is, what it is doing, where it stopped, what resources it uses, and how it should be scheduled**.

---

## What Does a PCB Contain?

A PCB typically contains information such as:

| Information                       | Purpose                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------ |
| **Process ID (PID)**              | Uniquely identifies the process                                                            |
| **Process State**                 | Indicates whether the process is Ready, Running, Waiting, Terminated, etc.                 |
| **Program Counter**               | Stores the address of the next instruction to execute                                      |
| **CPU Registers**                 | Stores the saved CPU execution state                                                       |
| **CPU Scheduling Information**    | Contains priority and other scheduling-related information                                 |
| **Memory-Management Information** | Contains information about the process's address space, page tables, memory mappings, etc. |
| **Accounting Information**        | Stores CPU usage, execution statistics, and other accounting data                          |
| **I/O Status Information**        | Tracks open files and allocated I/O resources                                              |

> The exact fields and organization of a PCB **vary between operating systems**.

---

## Understanding the PCB

Suppose three processes are running:

```text id="p4qg7f"
Operating System
│
├── PCB ──→ Process A
├── PCB ──→ Process B
└── PCB ──→ Process C
```

The OS can use these records to determine:

```text id="0dyg3u"
Process A → Running
Process B → Ready
Process C → Waiting for I/O
```

The PCB therefore allows the OS to maintain the information needed to manage each process independently.

---

## Why Is the PCB Important?

Suppose the CPU is currently executing **Process A**:

```text id="t7df8x"
CPU
 ↓
Process A
```

The OS decides that another process, **Process B**, should run.

The OS must preserve Process A's current execution state so that Process A can continue correctly later.

Conceptually:

```text id="w9rj1k"
Process A
    ↓
Save CPU / Execution State
    ↓
PCB of Process A
    ↓
Load State of Process B
    ↓
CPU
 ↓
Process B
```

Later, when Process A gets the CPU again, the OS restores its saved state.

```text id="k9q1sa"
PCB of Process A
      ↓
Restore Saved State
      ↓
CPU
      ↓
Process A continues
```

This is a fundamental part of **context switching**.

---

# PCB and Context Switching

A **context switch** occurs when the CPU stops executing one process/thread and starts executing another.

Consider:

```text id="z9m3xw"
        CPU
         │
         ▼
    ┌─────────┐
    │Process A│
    └────┬────┘
         │
   Context Switch
         │
         ▼
    ┌─────────┐
    │Process B│
    └─────────┘
```

During the switch, the OS roughly performs these steps:

### 1. Save Process A's State

The OS saves relevant CPU execution information, such as:

* Program counter
* CPU registers
* Process state
* Other scheduling/context information

into the PCB associated with Process A.

```text id="4wz6gq"
CPU State
    ↓
PCB of Process A
```

### 2. Update Process A

The OS changes Process A's state as appropriate.

For example:

```text id="1c5e4u"
Running → Ready
```

or:

```text id="8p7x8s"
Running → Waiting
```

depending on why the process stopped running.

### 3. Select Process B

The scheduler chooses another process that should execute.

```text id="9r2s9n"
Ready Queue
   │
   ├── Process B ← Selected
   ├── Process C
   └── Process D
```

### 4. Restore Process B's State

The OS loads Process B's saved execution state.

```text id="x4qj8w"
PCB of Process B
       ↓
Restore CPU State
       ↓
CPU
       ↓
Process B
```

### 5. Resume Process B

Process B continues execution from the point where it previously stopped.

This is why the PCB is essential for process management.

## PCB and Process State

The PCB also stores information about the current state of the process.

For example:

```text id="s6f4vz"
Process A
    │
    └── PCB
         ├── PID: 101
         ├── State: Ready
         ├── Program Counter
         ├── CPU Registers
         ├── Memory Information
         └── I/O Information
```

The OS can update the PCB as the process moves between states:

```text id="4av1pj"
New
 ↓
Ready
 ↓
Running
 ↓
Waiting
 ↓
Ready
 ↓
Running
 ↓
Terminated
```

---

## PCB and Scheduling

The scheduler needs information from the PCB to make scheduling decisions.

For example, a PCB may contain scheduling-related information such as:

* Process priority
* Scheduling parameters
* Queue-related information
* CPU usage information

Conceptually:

```text id="0s1f8n"
Ready Queue
│
├── Process A → Priority 3
├── Process B → Priority 1
└── Process C → Priority 2
```

The scheduler can use such information according to the scheduling algorithm being used.

---

## PCB and Memory Management

The PCB also contains or references information that helps the OS manage the process's memory.

For example:

```text id="g4h2xj"
PCB
│
└── Memory Information
     ├── Address-space information
     ├── Page-table information
     └── Memory mappings
```

This allows the OS to associate the process with the correct virtual address space and memory-management structures.

---

## PCB and I/O Resources

A process may have resources such as:

* Open files
* Sockets
* Devices
* Other I/O-related resources

The OS needs to track these resources as part of process management.

For example:

```text id="4z3c8v"
Process A
   │
   └── PCB
        └── I/O Information
             ├── File 1
             ├── File 2
             └── Network Socket
```

The exact representation is operating-system dependent.

---

# Simple Analogy

Think of the **PCB as a file maintained by the OS for each process**.

The file answers questions such as:

> **"Who is this process?"**

→ PID

> **"What state is it in?"**

→ Process state

> **"Where did it stop?"**

→ Program counter

> **"What was the CPU doing?"**

→ CPU registers

> **"How should it be scheduled?"**

→ Scheduling information

> **"What memory does it use?"**

→ Memory-management information

> **"What resources does it have?"**

→ I/O/resource information

```text id="k0eq1s"
             PCB
              │
    ┌─────────┼─────────┐
    ↓         ↓         ↓
   PID      State      CPU State
    │         │         │
    └─────────┼─────────┘
              │
       Memory / I/O /
       Scheduling Info
```

## Important Interview Point

A PCB is **not the process itself**.

It is an **OS-maintained data structure containing information about the process**.

```text id="k4x5pr"
Process
   │
   ├── Code
   ├── Data
   ├── Heap
   ├── Stack
   └── Resources

PCB
   │
   ├── PID
   ├── State
   ├── Program Counter
   ├── Registers
   ├── Scheduling Info
   ├── Memory Info
   └── I/O Info
```

The PCB allows the OS to manage the actual process effectively.

---

## Interview Takeaway

> **A Process Control Block (PCB) is an OS-maintained data structure containing the information required to manage and execute a process, including its PID, process state, program counter, CPU registers, scheduling information, memory information, and I/O resources. It is especially important during context switching.**

### Quick Memory Trick

**PCB = Process's OS Record**

Remember:

**PID + State + CPU Context + Scheduling + Memory + I/O**
