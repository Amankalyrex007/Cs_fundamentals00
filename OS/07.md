7.What is context switching?
Context switching is the process by which the operating system saves the execution state of one process or thread and restores the saved state of another, allowing the CPU to switch between them.

The saved state is maintained using information such as the program counter, CPU registers, stack information, and scheduling state.

Simple example

Suppose the CPU is executing Process A:

CPU → Process A

The OS decides to run Process B:

Process A
    ↓
Save its context
    ↓
PCB / thread context
    ↓
Load Process B's context
    ↓
CPU → Process B

Later, the OS can switch back:

Process B
    ↓
Save context
    ↓
Restore Process A
    ↓
CPU → Process A

This allows multiple processes or threads to share the CPU.

What happens during a context switch?

Conceptually:

Interrupt or scheduling event occurs
OS stops the currently running process/thread.
Its CPU state is saved.
The OS updates its state and scheduling information.
Another runnable process/thread is selected.
The selected process/thread's saved state is restored.
CPU resumes execution from the restored program counter.
Why is context switching needed?

A CPU may have many runnable processes but only a limited number of CPU cores.

For example, on a single-core CPU:

Time →
─────────────────────────────────>

Process A | Process B | Process A | Process C
          ↑           ↑
       Switch       Switch

The rapid switching creates the appearance that multiple processes are running simultaneously.

On multi-core systems, some processes/threads can actually execute in parallel, while context switching is still used when the scheduler changes which work runs on a particular core.

Context switching overhead

A context switch is not free.

The OS may need to:

Save and restore CPU registers
Update scheduling state
Switch execution contexts/address spaces when required
Interact with CPU caches and memory-management mechanisms

Therefore, excessive context switching can reduce performance because CPU time is spent managing switches rather than doing application work.

Process vs thread context switching

Both processes and threads can be context-switched.

Process switching may involve changing address-space-related state and can therefore involve more overhead.

Thread switching between threads of the same process can be lighter because they generally share the same address space, although the exact cost depends on the OS and hardware.

Context switching vs concurrency

Context switching enables multiple tasks to make progress over time, but it does not necessarily mean they execute at exactly the same instant.

Single core:
A → B → A → C

This is concurrent execution through scheduling.

With multiple cores:

Core 1 → Thread A
Core 2 → Thread B

the threads can execute in parallel.

Interview takeaway

Context switching is the process of saving the state of a running process or thread and restoring the state of another so the CPU can switch execution between them. It enables multitasking but introduces overhead.

Common follow-up: Why is context switching generally expensive?
Because saving/restoring execution state and potentially changing memory-management and cache-related state consumes CPU and system resources.
