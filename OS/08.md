8.Why is context switching expensive?
Context switching is expensive because the CPU and operating system must save the current execution state and restore another execution state. During this time, useful application work is interrupted.

Main reasons
1. Saving and restoring CPU state

The OS needs to save information such as:

CPU registers
Program counter
Stack pointer
Process/thread state

and then restore the corresponding state of the next process or thread.

Process A
   ↓
Save CPU state
   ↓
Load CPU state of B
   ↓
Process B

This consumes CPU cycles.

2. Memory-management overhead

When switching between processes, the CPU may need to switch to a different address-space context.

Modern processors use mechanisms such as TLBs (Translation Lookaside Buffers) to cache virtual-to-physical address translations. Changes in address-space context can reduce the usefulness of these cached translations, depending on the architecture and OS.

This can result in additional memory-translation work.

3. CPU cache effects

Different processes or threads may work with different data and instructions.

After switching, the new task may not find its needed data in the CPU caches.

Before switch:
Cache → mostly useful for Process A

After switch:
Process B needs different data
        ↓
More cache misses
        ↓
Fetch data from lower-level cache / memory

This can hurt performance even after the actual context switch has completed.

4. Scheduler overhead

The OS scheduler has to decide which runnable process or thread should execute next.

Scheduling itself consumes CPU time.

5. More switches can mean less useful work

If context switches happen excessively:

Work → Switch → Work → Switch → Work → Switch

a significant amount of CPU time can be spent managing execution rather than performing application work.

Process vs thread switching

A thread switch within the same process can be relatively cheaper because threads generally share the same address space.

A process switch may involve changing address-space-related state as well.

However, the exact cost depends on the operating system, CPU architecture, workload, and implementation, so it is better not to assume a fixed cost.

Simple analogy

Imagine two workers sharing one desk.

Every time they switch:

Worker A puts away their documents.
Worker B takes out their documents.
Worker B arranges the workspace.
Work resumes.

The switching itself doesn't produce useful output—it is necessary management overhead.

Interview takeaway

Context switching is expensive because the OS must save and restore execution state, and switching between tasks can also cause scheduler overhead, address-space-related work, and CPU-cache/TLB disruption. Excessive context switching reduces the CPU time available for useful application work.

Common follow-up: How can excessive context switching be reduced?
Typical approaches include reducing unnecessary thread creation, using appropriate thread pools, batching work, avoiding excessive synchronization/contention, and choosing suitable concurrency levels.
