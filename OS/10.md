10.What is CPU scheduling?
Definition

CPU scheduling is the process by which the operating system selects which ready process or thread should get the CPU next.

Since multiple processes may be ready to run but a CPU core can execute only limited work at a time, the OS scheduler decides who runs, when, and for how long.

Basic flow
          Processes / Threads
                  |
                  v
             Ready Queue
                  |
                  v
           CPU Scheduler
                  |
                  v
                  CPU

For example:

Ready Queue:
┌─────────┬─────────┬─────────┐
│ Process A │ Process B │ Process C │
└─────────┴─────────┴─────────┘
                 |
                 v
          Scheduler chooses
                 |
                 v
             CPU → A

After A's time expires or it blocks, the scheduler may select B.

Why is CPU scheduling needed?

The scheduler tries to use CPU resources efficiently while providing desirable behavior such as:

High CPU utilization — keep the CPU busy
High throughput — complete more processes over time
Low waiting time — reduce time spent waiting in the ready queue
Low turnaround time — reduce total time from submission to completion
Low response time — respond quickly to interactive tasks
Fairness — avoid indefinitely ignoring some processes

These goals can conflict with one another, so scheduling is a tradeoff.

Preemptive vs non-preemptive scheduling
Non-preemptive

Once a process gets the CPU, it generally keeps it until it:

finishes, or
voluntarily blocks/waits.
A ──────────> finishes
               ↓
               B
Preemptive

The OS can interrupt a running process and give the CPU to another process.

A ──────┐
        │ preempt
        ↓
B ──────────
             ↓
             A resumes

Modern general-purpose operating systems commonly use preemptive scheduling.

Common CPU scheduling algorithms
Algorithm	Basic idea
FCFS	First process to arrive runs first
SJF	Run the process with the shortest expected CPU burst
SRTF	Preemptive version related to shortest remaining time
Round Robin	Give each process a fixed time quantum
Priority Scheduling	Prefer processes based on priority
Multilevel Queue	Separate processes into different scheduling queues
Multilevel Feedback Queue	Processes can move between queues based on behavior
Example: Round Robin

Suppose three processes are ready:

A    B    C

with a time quantum of 2 ms:

A → B → C → A → B → C ...

Each process gets a limited CPU time before the scheduler considers another runnable process.

This is particularly useful for interactive workloads because one process shouldn't normally monopolize the CPU.

Important scheduling metrics

Suppose:

Arrival Time = when process enters the ready queue
Completion Time = when process finishes

Then:

Turnaround Time

Turnaround Time = Completion Time − Arrival Time

Waiting Time

Waiting Time = Turnaround Time − CPU Burst Time

Response Time

Response Time = First CPU Start Time − Arrival Time

These metrics help evaluate a scheduling algorithm.

Interview takeaway

CPU scheduling is the OS mechanism for selecting which ready process or thread should execute on the CPU next. Its goal is to efficiently share CPU time while balancing utilization, throughput, response time, waiting time, turnaround time, and fairness.
