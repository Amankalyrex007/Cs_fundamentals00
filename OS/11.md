# Q11. Explain FCFS, SJF, Round Robin, and Priority Scheduling

**FCFS, SJF, Round Robin, and Priority Scheduling** are common CPU scheduling algorithms used by an operating system to decide **which ready process or thread should receive CPU time**.

Each algorithm makes the decision differently:

```text
FCFS
  ↓
Arrival order

SJF
  ↓
Shortest CPU burst

Round Robin
  ↓
Time quantum

Priority Scheduling
  ↓
Priority level
```

No single algorithm is ideal for every workload. The appropriate strategy depends on goals such as:

* Responsiveness
* Average waiting time
* Turnaround time
* Fairness
* Throughput
* Task importance
* Scheduling overhead

---

# 1. FCFS — First-Come, First-Served

## Idea

**First-Come, First-Served (FCFS)** schedules the process that arrives first before processes that arrive later.

It is generally **non-preemptive**.

```text
First arrival
     ↓
Gets CPU
     ↓
Runs until completion/blocking
     ↓
Next process
```

---

## Example

Suppose the processes arrive in this order:

```text
A → 5 ms
B → 3 ms
C → 2 ms
```

If A arrives first:

```text
A ─────── B ─── C ──>
```

More precisely:

```text
0         5        8       10
|---------|--------|--------|
     A         B        C
```

A runs for its CPU burst before B gets the CPU.

---

## Why is FCFS Non-Preemptive?

Once A starts running:

```text
A ─────────────────>
```

the scheduler generally does not forcibly remove A.

A gives up the CPU when it:

* Finishes, or
* Blocks/waits, such as for I/O.

Then the scheduler selects the next process.

---

## Advantages of FCFS

### 1. Very Simple

The basic idea is straightforward:

> **First process in → first process out.**

A simple queue can be used:

```text
Ready Queue

A → B → C → D
|
v
CPU
```

---

### 2. Easy to Implement

FCFS can be implemented using a basic FIFO-style queue.

```text
FIFO = First In, First Out
```

This makes the algorithm conceptually simple.

---

### 3. No Starvation in the Basic Algorithm

If processes continue to be admitted normally and the queue is finite, a process waiting in the queue will eventually reach the front.

For example:

```text
A → B → C → D
```

B does not continuously get pushed behind newer arrivals simply because newer processes arrive.

However, a process may still experience **very long waiting time** if earlier processes have long CPU bursts.

---

# 2. Disadvantages of FCFS

## 1. Can Produce High Waiting Time

Consider:

```text
A = 10 ms
B = 2 ms
C = 1 ms
```

If A arrives first:

```text
A → B → C
```

Gantt chart:

```text
0          10       12      13
|-----------|--------|-------|
      A         B       C
```

B and C have very short CPU bursts, but they must wait for the long process A.

---

## 2. Poor Response Time for Interactive Workloads

Suppose a long CPU-bound task is running:

```text
A ─────────────────────────────>
```

An interactive application B becomes ready:

```text
B → waiting...
```

Under basic non-preemptive FCFS, B cannot immediately interrupt A.

This can make interactive systems feel less responsive.

---

## 3. Convoy Effect

One of the most important disadvantages of FCFS is the **convoy effect**.

A long CPU-bound process can make many short processes wait behind it.

```text
Long process
A ─────────────────────────>

Short B → waiting
Short C → waiting
Short D → waiting
```

This is called a **convoy** because many shorter tasks effectively become stuck behind the long-running task.

---

## FCFS Memory Trick

> **FCFS = First Arrival → First CPU**

---

# 3. SJF — Shortest Job First

## Idea

**Shortest Job First (SJF)** chooses the process with the **shortest expected CPU burst**.

Basic SJF is **non-preemptive**.

```text
Ready Processes
      |
      v
Compare CPU burst estimates
      |
      v
Choose shortest
```

---

## Example

Suppose:

```text
A = 8 ms
B = 3 ms
C = 2 ms
```

SJF selects:

```text
C → B → A
```

Gantt chart:

```text
0    2       5              13
|----|-------|---------------|
 C       B          A
```

The shortest CPU burst executes first.

---

# 4. Why SJF Can Be Efficient

If CPU burst lengths are known accurately, SJF can minimize the **average waiting time** for a set of processes under the classic assumptions.

Consider:

```text
A = 8 ms
B = 3 ms
C = 2 ms
```

SJF:

```text
C → B → A
```

The short jobs finish early instead of waiting behind the long job.

This is particularly useful for some **batch-oriented workloads**.

---

# 5. Disadvantages of SJF

## 1. Future CPU Burst Length Is Not Known Exactly

This is the major practical difficulty.

The OS generally cannot simply know:

> “This process will need exactly 7.4 ms of CPU time.”

Instead, systems can estimate CPU burst behavior using historical information or other scheduling mechanisms.

So SJF is often discussed as an idealized algorithm in textbooks.

---

## 2. Long Processes Can Experience Starvation

Suppose short jobs continuously arrive:

```text
S1 → S2 → S3 → S4 → S5 → ...
```

and a long process L is waiting:

```text
L = 20 ms
```

If short processes keep being selected:

```text
S1 → S2 → S3 → S4 → S5 → ...
                         |
                         v
                     L waits...
```

L may wait for a very long time.

This is called **starvation**.

---

## 3. Requires Estimating CPU Burst Duration

The scheduler needs some way to determine or estimate which process is likely to have the shortest CPU burst.

That makes practical implementations more complicated than FCFS.

---

# 6. SRTF — Shortest Remaining Time First

The common **preemptive counterpart of SJF** is **Shortest Remaining Time First (SRTF)**.

Instead of looking only at the original CPU burst, the scheduler considers the **remaining CPU time**.

If a new process arrives with a shorter remaining burst than the currently running process, the current process can be preempted.

---

## Example

Suppose:

```text
A = 8 ms
```

A starts:

```text
A ─────────>
```

After A has executed for 3 ms:

```text
A has 5 ms remaining
```

Now B arrives:

```text
B = 2 ms
```

Since:

```text
B = 2 ms
A remaining = 5 ms
```

the scheduler may preempt A:

```text
A ─────┐
       |
       | B arrives
       v
B ─────>
       |
       v
A resumes
```

This is the key difference between:

```text
SJF  → non-preemptive
SRTF → preemptive
```

---

# 7. Round Robin (RR)

## Idea

**Round Robin** gives each runnable process a fixed amount of CPU time called a **time quantum** or **time slice**.

It is **preemptive**.

For example:

```text
Time quantum = 2 ms
```

Suppose:

```text
A
B
C
```

The scheduler may execute:

```text
A → B → C → A → B → C
```

until the processes finish.

---

# 8. Round Robin Example

Suppose:

```text
A = 5 ms
B = 3 ms
C = 2 ms

Quantum = 2 ms
```

Execution:

```text
A A | B B | C C | A A | B | A
```

Gantt chart:

```text
0    2    4    6    8    10   11   12
|----|----|----|----|----|----|----|
 A    B    C    A    B    A
```

Let's break it down:

### First round

```text
A → 2 ms
B → 2 ms
C → 2 ms
```

C finishes.

Remaining:

```text
A = 3 ms
B = 1 ms
```

### Second round

```text
A → 2 ms
B → 1 ms
A → 1 ms
```

A and B eventually finish.

---

# 9. Why Round Robin is Useful

Round Robin is particularly useful for **interactive and time-sharing workloads**.

Instead of allowing one process to run for a very long time:

```text
A ─────────────────────────>
```

the scheduler gives multiple runnable processes opportunities:

```text
A → B → C → A → B → C
```

This can provide better responsiveness and fairer CPU sharing.

---

# 10. Advantages of Round Robin

### 1. Good Responsiveness

Interactive processes get CPU opportunities regularly.

For example:

```text
Browser → Terminal → Editor → Browser → Terminal
```

Instead of waiting for a long CPU-bound process to finish completely.

---

### 2. Prevents One Process from Monopolizing the CPU

A process normally gets only one time quantum before the scheduler considers other runnable tasks.

```text
A → quantum expires
      ↓
B gets CPU
```

---

### 3. Generally Provides Fair CPU Sharing

If runnable processes have comparable scheduling conditions, each gets repeated opportunities to execute.

For example:

```text
A → B → C → A → B → C
```

This is a major reason Round Robin is associated with time-sharing systems.

---

# 11. Disadvantages of Round Robin

## 1. Very Small Quantum

Suppose:

```text
Quantum = extremely small
```

The system may switch frequently:

```text
A → B → C → A → B → C → A → ...
```

This can cause significant context-switch and scheduling overhead.

---

## 2. Very Large Quantum

If the quantum becomes very large, Round Robin starts behaving more like FCFS.

For example:

```text
Quantum = larger than most CPU bursts
```

Then many processes may finish before their quantum expires:

```text
A → B → C
```

rather than frequent rotation.

---

## 3. Performance Depends on Quantum Selection

The time quantum must balance:

```text
Responsiveness
      ↕
Context-switch overhead
```

Smaller quantum:

```text
Better responsiveness
+
More switching
```

Larger quantum:

```text
Less switching
+
Potentially worse responsiveness
```

---

# 12. Priority Scheduling

## Idea

**Priority Scheduling** chooses the process with the highest scheduling priority.

It can be:

* **Preemptive**, or
* **Non-preemptive**

depending on the implementation.

---

## Example

Suppose:

```text
A → Priority 3
B → Priority 1
C → Priority 2
```

If the system defines **smaller numerical value as higher priority**:

```text
1 = highest
2 = next
3 = lowest
```

then:

```text
B → C → A
```

The exact meaning of priority numbers depends on the system.

Some systems may use larger values for higher priority.

Therefore, never assume:

```text
1 always means highest
```

without checking the convention.

---

# 13. Preemptive Priority Scheduling

Suppose:

```text
A = currently running
A priority = 5
```

Then a new process arrives:

```text
B priority = 1
```

where 1 means higher priority.

The scheduler may preempt A:

```text
A ─────────┐
           |
           | B arrives
           v
B ─────────────>
               |
               v
A resumes
```

This is **preemptive priority scheduling**.

---

# 14. Non-Preemptive Priority Scheduling

In a non-preemptive implementation, if A is already running:

```text
A ─────────────────>
```

a newly arrived higher-priority process B may have to wait until A:

* finishes, or
* blocks.

```text
A ───────────────> finishes
                         |
                         v
                         B
```

So the same priority policy can behave differently depending on whether it is preemptive.

---

# 15. Advantages of Priority Scheduling

### 1. Important Tasks Can Run Earlier

Suppose a system has:

```text
High priority   → critical task
Medium priority → normal task
Low priority    → background task
```

The scheduler can give CPU preference to the important task.

This is useful when tasks have different scheduling importance.

---

### 2. Useful for Different Workload Requirements

Not every process has the same urgency.

For example:

```text
Interactive task → higher priority
Background backup → lower priority
```

The scheduling policy can reflect these differences.

---

# 16. Disadvantages of Priority Scheduling

## 1. Starvation

If high-priority tasks continuously arrive:

```text
High → High → High → High → ...
```

a low-priority process may keep waiting:

```text
Low-priority process
        |
        v
     waiting...
```

This is **starvation**.

---

## 2. Priority Assignment Can Be Difficult

Choosing the correct priority can be complicated.

For example:

```text
Task A = priority 5
Task B = priority 10
```

What exactly should determine these values?

Possible considerations include:

* Task importance
* Responsiveness requirements
* System policy
* User interaction
* Real-time constraints
* Resource behavior

The exact mechanism depends on the OS.

---

## 3. Preemptive Priority Scheduling Can Cause More Context Switching

If higher-priority tasks frequently become runnable:

```text
A → B → A → C → A → B → ...
```

the scheduler may perform frequent preemptions and context switches.

That introduces overhead.

---

# 17. Aging — Solution to Priority Starvation

A common solution to starvation is **aging**.

Aging gradually increases the effective priority of a process that has been waiting for a long time.

For example:

```text
Initial priority
      ↓
P = 10

Waits
      ↓
P = 9

Waits longer
      ↓
P = 8

Waits longer
      ↓
P = 7
```

If smaller values represent higher priority, the process gradually becomes more likely to run.

The exact aging mechanism varies by system.

The main idea is:

> **The longer a process waits, the more its priority can be adjusted to prevent indefinite starvation.**

---

# 18. Comparison of the Four Algorithms

| Algorithm       | Preemptive? | Main Idea                         | Major Issue                                          |
| --------------- | ----------- | --------------------------------- | ---------------------------------------------------- |
| **FCFS**        | Usually No  | First arrival runs first          | Convoy effect                                        |
| **SJF**         | No          | Shortest expected CPU burst first | Burst time is difficult to know; starvation possible |
| **Round Robin** | Yes         | Fixed time quantum                | Quantum selection and context-switch overhead        |
| **Priority**    | Either      | Highest-priority process first    | Starvation                                           |

---

# 19. Quick Comparison by Goal

| Goal                                                   | Commonly Associated Algorithm |
| ------------------------------------------------------ | ----------------------------- |
| Simplicity                                             | FCFS                          |
| Short average waiting time under ideal burst estimates | SJF                           |
| Interactive responsiveness                             | Round Robin                   |
| Fair time sharing                                      | Round Robin                   |
| Task importance                                        | Priority Scheduling           |
| Avoiding long-task blocking of short tasks             | SJF / SRTF                    |
| Preventing priority starvation                         | Priority + Aging              |

These are general associations, not guarantees. Actual performance depends on workload and implementation.

---

# 20. Quick Example

Suppose all processes arrive at the same time:

```text
A = 6 ms
B = 2 ms
C = 4 ms
```

---

## FCFS

Assuming arrival order is:

```text
A → B → C
```

Execution:

```text
A → B → C
```

Gantt chart:

```text
0       6    8        12
|-------|----|---------|
    A     B      C
```

---

## SJF

Shortest CPU burst first:

```text
B = 2
C = 4
A = 6
```

Therefore:

```text
B → C → A
```

Gantt chart:

```text
0    2       6            12
|----|-------|-------------|
 B       C          A
```

---

## Round Robin

Suppose:

```text
Quantum = 2 ms
```

Execution:

```text
A → B → C → A → C → A
```

Gantt chart:

```text
0    2    4    6    8    10   12
|----|----|----|----|----|----|
 A    B    C    A    C    A
```

Explanation:

```text
A: 6 → 4 → 2 → 0
B: 2 → 0
C: 4 → 2 → 0
```

So B finishes first, C finishes next, and A finishes last.

---

## Priority Scheduling

For the same processes:

```text
A → Priority 3
B → Priority 1
C → Priority 2
```

Assuming lower number = higher priority:

```text
B → C → A
```

The exact execution can differ if processes arrive at different times or if the implementation is preemptive.

---

# 21. Example Where Algorithms Behave Differently

Consider:

```text
A = 10 ms
B = 2 ms
C = 2 ms
```

If A arrives first:

### FCFS

```text
A → B → C
```

Short tasks B and C wait behind A.

### SJF

If all are ready:

```text
B → C → A
```

Short tasks complete earlier.

### Round Robin

With quantum = 2:

```text
A → B → C → A → A → A → A → A
```

B and C get CPU time quickly even though A arrived first.

### Priority

The order depends on priority:

```text
Highest priority
       ↓
       ?
```

This demonstrates why different algorithms produce different waiting and response behavior.

---

# 22. Important Interview Distinction

Do not confuse **SJF** with **SRTF**.

```text
SJF
↓
Non-preemptive
↓
Choose shortest CPU burst
```

Whereas:

```text
SRTF
↓
Preemptive
↓
Choose shortest remaining CPU time
```

Example:

```text
A is running
A remaining = 7 ms

B arrives
B = 3 ms
```

SRTF can do:

```text
A ─────┐
       |
       v
B ─────>
       |
       v
A resumes
```

Basic SJF would not preempt A merely because B is shorter.

---

# 23. Important Interview Distinction: Round Robin vs FCFS

Both can use a queue-like arrival order, but they behave differently.

### FCFS

```text
A ───────────────────>
B                     waiting
C                     waiting
```

A normally runs until completion/blocking.

### Round Robin

```text
A → B → C → A → B → C
```

Each gets a limited time quantum.

Therefore:

> **FCFS is generally non-preemptive, while Round Robin is preemptive and time-sliced.**

---

# 24. Important Interview Distinction: Priority vs SJF

SJF can be viewed as a special kind of priority-based idea where the priority is derived from expected CPU burst length.

Conceptually:

```text
SJF:

Shorter CPU burst
       ↓
Higher scheduling preference
```

But in general priority scheduling, priority can come from other system-specific factors rather than CPU burst length.

---

# 25. Real-World Example

Imagine a computer running:

```text
Browser
Code Editor
Video Encoder
Background Backup
Terminal
```

Different scheduling policies can produce different behavior.

A time-sharing scheduler may want interactive applications such as the editor and terminal to remain responsive.

A background backup may be less urgent.

A CPU-intensive video encoder may consume substantial CPU time but should not necessarily prevent other runnable tasks from making progress.

Conceptually:

```text
                  CPU Scheduler
                       |
        +--------------+--------------+
        |              |              |
   Interactive      CPU-heavy     Background
      tasks           task           tasks
        |              |              |
        +--------------+--------------+
                       |
                      CPU
```

Modern general-purpose operating systems generally use sophisticated scheduling mechanisms rather than implementing these textbook algorithms exactly as described.

# 27. Interview Takeaway

> **FCFS prioritizes arrival order, SJF prioritizes the shortest expected CPU burst, Round Robin gives each runnable process a fixed time quantum, and Priority Scheduling chooses according to scheduling priority.**

### Memory Trick

```text
FCFS
= First Come → First Served

SJF
= Shortest Job → First

RR
= Time Quantum → Take Turns

Priority
= Highest Priority → First
```

The choice of scheduling strategy depends on what the system needs to optimize:

```text
Simplicity
   ↓
FCFS

Short average waiting time
   ↓
SJF

Responsiveness + time sharing
   ↓
Round Robin

Task importance
   ↓
Priority Scheduling
```

But in real operating systems, scheduling is usually much more sophisticated than these textbook algorithms and may combine multiple ideas to balance **fairness, responsiveness, throughput, CPU utilization, priority, and scheduling overhead**.
