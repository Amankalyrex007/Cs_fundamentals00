11.Explain FCFS, SJF, Round Robin, and Priority Scheduling.
These are common CPU scheduling algorithms used by an operating system to decide which ready process gets the CPU.

1. FCFS — First-Come, First-Served

Idea: The process that arrives first gets the CPU first.

It is generally non-preemptive.

Example:

Processes:
A → 5 ms
B → 3 ms
C → 2 ms

Execution:
A ───── B ─── C ──>

If A arrives before B and C, A runs to completion before B starts.

Advantages

Very simple
Easy to implement
No starvation in the basic algorithm

Disadvantages

Can produce high waiting time
Poor response time for interactive workloads
Suffers from the convoy effect: a long process can make many short processes wait behind it
2. SJF — Shortest Job First

Idea: Choose the process with the shortest expected CPU burst.

Basic SJF is non-preemptive.

Example:

A = 8 ms
B = 3 ms
C = 2 ms

Execution:

C ── B ─── A ────────>

The shortest job runs first.

Advantages

Can minimize average waiting time when CPU burst lengths are known/estimated accurately
Good for batch workloads

Disadvantages

Actual future CPU burst length is generally not known exactly
Long processes can experience starvation if short jobs continuously arrive
Requires estimating CPU burst duration
SRTF

The preemptive counterpart is commonly called Shortest Remaining Time First (SRTF).

If a new process arrives with a shorter remaining CPU burst than the currently running process, the current process can be preempted.

3. Round Robin (RR)

Idea: Each process gets a fixed amount of CPU time called a time quantum.

It is preemptive.

Suppose:

Time quantum = 2 ms
Processes = A, B, C

The scheduler might execute:

A → B → C → A → B → C

until the processes finish.

Example:

A = 5 ms
B = 3 ms
C = 2 ms
Quantum = 2 ms

A A | B B | C C | A A | B | A

Advantages

Good responsiveness for interactive systems
Prevents one process from monopolizing the CPU
Generally provides fair CPU sharing

Disadvantages

Too small a quantum → many context switches
Too large a quantum → behavior approaches FCFS
Performance depends heavily on the chosen quantum
4. Priority Scheduling

Idea: The scheduler chooses the process with the highest priority.

It can be either preemptive or non-preemptive.

Example:

A → Priority 3
B → Priority 1
C → Priority 2

If a lower numerical value means higher priority:

B → C → A

The exact priority convention depends on the system.

Advantages

Important/urgent tasks can receive CPU time earlier
Useful when different tasks have different importance

Disadvantages

Low-priority processes can experience starvation
Priority assignment can be difficult
Preemptive priority scheduling can cause additional context switches

A common solution to starvation is aging: gradually increasing the priority of a process that has been waiting for a long time.

Comparison
Algorithm	Preemptive?	Main idea	Major issue
FCFS	Usually no	First arrival runs first	Convoy effect
SJF	No	Shortest job first	Burst time is difficult to know; starvation possible
Round Robin	Yes	Fixed time quantum	Quantum selection and context-switch overhead
Priority	Either	Highest-priority process first	Starvation
Quick example

Suppose all processes arrive at the same time:

A = 6 ms
B = 2 ms
C = 4 ms

For FCFS:

A → B → C

For SJF:

B → C → A

For Round Robin, with quantum = 2 ms:

A → B → C → A → C → A

For Priority Scheduling, the order depends on the assigned priorities.

Interview takeaway

FCFS prioritizes arrival order, SJF prioritizes the shortest CPU burst, Round Robin gives each process a fixed time quantum, and Priority Scheduling chooses according to priority. The right choice depends on whether the system prioritizes simplicity, throughput, responsiveness, fairness, or task importance.
