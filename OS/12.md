12.Preemptive vs non-preemptive scheduling?
The key difference is whether the operating system can forcibly take the CPU away from a running process.

1. Preemptive scheduling

In preemptive scheduling, the OS can interrupt a running process and assign the CPU to another ready process.

Example:

Process A is running
        ↓
Process B becomes ready
        ↓
Scheduler preempts A
        ↓
CPU → Process B
        ↓
A can resume later

This is useful for interactive and time-sharing systems because one process cannot normally keep the CPU indefinitely.

Examples:

Round Robin
Shortest Remaining Time First (SRTF)
Preemptive Priority Scheduling

Advantages

Better responsiveness
Better sharing of CPU time
A high-priority task can run sooner
Suitable for interactive systems

Disadvantages

More context switches
Context-switch overhead
Requires synchronization when processes/threads share resources
Scheduling is more complex
2. Non-preemptive scheduling

In non-preemptive scheduling, once a process gets the CPU, it generally keeps it until it:

finishes, or
voluntarily blocks/waits, such as for I/O.

Example:

Process A gets CPU
        ↓
A continues running
        ↓
A finishes or blocks
        ↓
Scheduler selects B

Examples:

FCFS
Basic SJF
Non-preemptive Priority Scheduling

Advantages

Simpler scheduling
Fewer context switches
Lower scheduling overhead

Disadvantages

Poorer response time for interactive workloads
A long-running process can delay other processes
Can cause the convoy effect in FCFS
Comparison
Feature	Preemptive	Non-preemptive
Can OS interrupt running process?	Yes	Generally no
Responsiveness	Usually better	Usually lower
Context switches	Potentially more	Usually fewer
Complexity	Higher	Simpler
Overhead	Higher	Lower
Example	Round Robin	FCFS
Suitable for	Interactive/time-sharing systems	Simpler or batch-oriented workloads
Simple example

Suppose:

A starts running
B arrives later

Preemptive:

A ──────┐
        ↓
        B ─────
              ↓
              A resumes

The scheduler can interrupt A.

Non-preemptive:

A ──────────────────
                    ↓
                    B ─────

B waits until A finishes or blocks.

Interview takeaway

Preemptive scheduling allows the OS to interrupt a running process and give the CPU to another process, improving responsiveness but adding context-switch overhead. Non-preemptive scheduling lets a process retain the CPU until it finishes or blocks, making scheduling simpler but potentially increasing waiting and response times.
