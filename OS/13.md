13.What is starvation?
Definition

Starvation is a scheduling problem in which a process or thread waits for an indefinitely long time because other processes continuously get the resources or CPU time it needs.

The process is ready to run, but the scheduler repeatedly chooses other processes instead.

Example: Priority Scheduling

Suppose we have:

P1 → Low priority
P2 → High priority
P3 → High priority
P4 → High priority

If high-priority processes keep arriving:

P2 → P3 → P4 → P2 → P3 → P4 → ...

P1 may continue waiting:

P1 → waiting → waiting → waiting → ...

This is starvation.

Why does starvation occur?

Common causes include:

Priority scheduling where low-priority processes are repeatedly bypassed
Poor scheduling policies
Continuous arrival of higher-priority tasks
Resource allocation policies that repeatedly favor certain processes
How can starvation be prevented?

A common solution is aging.

With aging, the priority of a waiting process is gradually increased over time.

Initial:
P1 → Priority 10

After waiting:
P1 → Priority 8

After more waiting:
P1 → Priority 5

Eventually:
P1 → gets CPU

The exact direction of priority values depends on the scheduling system.

Other scheduling strategies can also reduce starvation by ensuring some degree of fairness.

Starvation vs deadlock
Starvation	Deadlock
A process waits for an excessively long/indefinite time	Processes are stuck waiting for each other
Other processes may continue running	A group of processes cannot make progress
Often caused by unfair scheduling/resource allocation	Often caused by circular resource dependencies
Aging can help with scheduling starvation	Deadlock prevention/detection/recovery is used
Interview takeaway

Starvation occurs when a process waits indefinitely because the scheduling or resource-allocation policy repeatedly favors other processes. Aging is a common technique used to prevent starvation in priority scheduling.
