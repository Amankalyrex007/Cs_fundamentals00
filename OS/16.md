16.What is a race condition?
A race condition occurs when multiple threads or processes access shared data concurrently, and the final result depends on the timing/order of their execution.

In simple terms:

Two or more threads “race” to read or modify the same shared resource, and the program may produce an incorrect or unpredictable result.

Example

Suppose two threads increment the same variable:

counter = 0

# Thread 1
counter = counter + 1

# Thread 2
counter = counter + 1

We expect:

counter = 2

But counter = counter + 1 is not necessarily one indivisible operation. Conceptually, it can be:

Read counter
Add 1
Write counter

A possible execution:

Thread 1: Read 0
Thread 2: Read 0
Thread 1: Add 1 → 1
Thread 2: Add 1 → 1
Thread 1: Write 1
Thread 2: Write 1

Final result:

counter = 1

instead of 2.

Why does it happen?

A race condition typically requires:

Shared mutable data/resource
Concurrent execution
At least one operation that modifies the shared resource
Insufficient synchronization
How can we prevent it?

Use synchronization mechanisms that make the critical section safe, such as:

Mutex/lock
Semaphore
Monitor
Atomic operations
Thread-safe data structures
Message passing, where appropriate

For example:

lock.acquire()
try:
    counter += 1
finally:
    lock.release()

Only one thread can execute the protected section at a time.

Race condition vs deadlock
Race Condition	Deadlock
Result depends on execution timing	Threads/processes wait indefinitely
Can produce incorrect/unpredictable results	Can cause the program to stop making progress
Usually caused by unsynchronized shared data	Usually caused by circular resource/lock dependencies
Locks/atomic operations can help prevent it	Lock ordering, timeouts, detection, etc. can help prevent/handle it
Interview takeaway

A race condition is a concurrency bug where the outcome depends on the timing of concurrent operations on shared resources. Synchronization or atomic operations are used to ensure predictable behavior.

Common interview follow-up: What is a critical section?
A critical section is the part of a program where shared resources are accessed or modified and therefore may need synchronization.
