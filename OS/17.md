17.What is a critical section? 
Ans:critical section is a part of a program where a shared resource is accessed or modified, and therefore it must be protected so that multiple threads or processes do not execute it unsafely at the same time.

The goal is to ensure mutual exclusion when required.

Example

Suppose multiple threads update a shared counter:

counter += 1

The code that reads, modifies, and writes counter can be treated as a critical section.

Without synchronization:

Thread 1 ──┐
           ├── access shared counter → race condition
Thread 2 ──┘

With a lock:

lock.acquire()

# Critical section
counter += 1

lock.release()

Only one thread at a time can execute the protected section.

Critical Section Requirements

A good solution to the critical-section problem generally aims for:

Mutual exclusion — only one process/thread enters the critical section at a time.
Progress — if no one is inside the critical section, a waiting process should not be blocked unnecessarily.
Bounded waiting — a process should not wait indefinitely to enter.
Critical section vs race condition
Critical Section	Race Condition
A section of code accessing shared resources	A concurrency bug caused by unsafe concurrent access
It identifies where protection may be needed	It describes the problem that can occur
Can be protected using locks/other synchronization	Can be prevented/reduced through proper synchronization
Interview takeaway

A critical section is the portion of code that accesses shared resources and must be properly synchronized to prevent race conditions and maintain data consistency.
