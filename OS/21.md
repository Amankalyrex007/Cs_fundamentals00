21.What is a monitor?
A monitor is a high-level synchronization mechanism that combines:

Shared data
Methods that access that data
Automatic mutual exclusion
Condition variables for waiting and signaling

The main idea is to provide a safe way for multiple threads to access shared resources without manually managing locks everywhere.

Intuition

Think of a monitor as a protected room:

             Monitor
┌──────────────────────────────┐
│ Shared data                  │
│                              │
│  method A()                  │
│  method B()                  │
│  method C()                  │
│                              │
│  Only one thread executes    │
│  monitor methods at a time   │
└──────────────────────────────┘
       ↑       ↑       ↑
     Thread 1 Thread 2 Thread 3

When one thread enters the monitor, other threads trying to execute its synchronized methods must wait.

Example

Conceptually:

monitor BankAccount:

    balance = 1000

    withdraw(amount):
        if balance >= amount:
            balance -= amount

    deposit(amount):
        balance += amount

The monitor ensures that operations on balance are properly synchronized.

Monitors and condition variables

A monitor can also allow a thread to wait until a condition becomes true.

For example, in a producer-consumer system:

Producer:
    add item
    signal consumer

Consumer:
    if buffer is empty:
        wait
    remove item

Condition variables commonly provide operations such as:

wait() — temporarily releases the monitor's lock and waits.
signal()/notify() — wakes a waiting thread.
broadcast()/notifyAll() — wakes multiple waiting threads.

The exact API and semantics depend on the programming language/runtime.

Monitor vs mutex
Monitor	Mutex
Higher-level synchronization construct	Lower-level synchronization primitive
Combines shared data + methods + synchronization	Primarily provides mutual exclusion
Usually provides automatic locking around monitor methods	Programmer explicitly acquires/releases it
Can include condition variables	May be used together with condition variables
Helps encapsulate synchronization	Provides the basic locking mechanism
Real-world examples

Languages provide monitor-like constructs in different forms:

Java — every object can act as a monitor; synchronized methods/blocks provide monitor-style synchronization.
C# — lock provides monitor-based synchronization through the runtime.
Other languages may provide similar abstractions using locks and condition variables.
Interview takeaway

A monitor is a high-level synchronization construct that encapsulates shared data and the operations on it, ensuring controlled access by concurrent threads and typically providing condition variables for coordination.

Common follow-up: How is a monitor different from a mutex?
A mutex is primarily a locking primitive, while a monitor is a higher-level abstraction that combines synchronization with the shared state and operations being protected.
