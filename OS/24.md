24.Deadlock prevention vs avoidance vs detection?
These are three different strategies for dealing with deadlocks.

Aspect	Deadlock Prevention	Deadlock Avoidance	Deadlock Detection
Basic idea	Prevent deadlock conditions from occurring	Make resource-allocation decisions carefully to stay safe	Allow deadlock, then detect it
When decision is made	Before/during resource allocation	Before granting a resource request	After allocation
Main goal	Guarantee deadlock cannot occur	Avoid entering an unsafe state	Find deadlocks and recover
Knowledge required	Resource/lock rules	Often requires knowledge of future resource needs	Current allocation/waiting state
Example	Enforce fixed lock ordering	Banker's algorithm	Wait-for graph / cycle detection
Recovery needed?	Usually no deadlock to recover from	Usually no	Yes, after detection
1. Deadlock Prevention

Prevention deliberately breaks at least one of the four necessary conditions for deadlock.

Examples:

Prevent hold and wait by requiring a process to request all required resources at once.
Prevent circular wait by imposing a fixed ordering on resource acquisition.
Allow preemption where appropriate.
Make resources shareable where possible to reduce mutual exclusion.

Key idea:

Don't allow the system to reach a state where deadlock is possible.

2. Deadlock Avoidance

Avoidance is more dynamic. The system checks whether granting a resource request could put the system into an unsafe state.

A classic example is the Banker's Algorithm.

Conceptually:

Resource request
       ↓
Would granting it keep the system in a safe state?
       ↓
   Yes → Grant
   No  → Make process wait

A safe state means the system can still find some order in which all processes can eventually complete.

Important distinction:

Unsafe state ≠ deadlock necessarily, but an unsafe state means the system can no longer guarantee deadlock avoidance.

3. Deadlock Detection

With detection, the system does not try to prevent every possible deadlock.

Instead:

Allow resource allocation
        ↓
Monitor system state
        ↓
Detect deadlock
        ↓
Recover

Detection can involve looking for cycles in a resource-allocation graph or wait-for graph, depending on the resource model.

After detecting a deadlock, the system may:

Terminate one or more processes
Preempt resources where possible
Roll back work
Release resources and retry
Easy way to remember

Prevention: Don't let deadlock conditions form.
Avoidance: Check before granting resources so the system remains safe.
Detection: Let deadlock happen, detect it, then recover.

Interview takeaway

The key distinction an interviewer usually wants is:

Prevention → break a necessary condition
Avoidance → stay in a safe state
Detection → find deadlock after it occurs and recover
