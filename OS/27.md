26.What is segmentation?
Segmentation is a memory-management technique in which a process's logical memory is divided into variable-sized segments, where each segment represents a meaningful logical part of the program.

Examples of segments include:

Code segment → program instructions
Data segment → global/static variables
Stack segment → function calls and local variables
Heap segment → dynamically allocated memory

Unlike paging, segmentation uses variable-sized blocks.

How segmentation works

A logical address is represented as:

Logical Address
┌─────────────────┬────────────┐
│ Segment Number  │   Offset   │
└─────────────────┴────────────┘

The segment number identifies the segment, while the offset identifies the location within that segment.

The OS maintains a segment table containing information such as:

Base → starting physical address of the segment
Limit → size of the segment

The physical address is conceptually:

Physical Address = Base + Offset

The OS also checks:

Offset < Limit

If the offset exceeds the segment's limit, a memory-access exception occurs.

Example

Suppose a process has:

Code  → 20 KB
Data  → 10 KB
Stack → 8 KB

These are separate logical segments and can be placed at different locations in physical memory.

Paging vs Segmentation
Feature	Paging	Segmentation
Division	Fixed-size pages	Variable-size segments
Based on	Physical memory management	Logical program structure
Address	Page number + offset	Segment number + offset
Fragmentation	Internal fragmentation possible	External fragmentation possible
Programmer view	Mostly transparent	Reflects logical program structure
Table	Page table	Segment table
Key disadvantage

Because segments have variable sizes, segmentation can suffer from external fragmentation—free memory may exist but be split into small, non-contiguous regions.

Interview takeaway

Paging divides memory into fixed-size pages, while segmentation divides a process into variable-sized logical segments such as code, data, stack, and heap.
