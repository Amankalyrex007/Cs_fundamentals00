# Q28. What is a Page Fault?

A **page fault** occurs when a process tries to access a virtual-memory page that is **not currently present in the physical memory (RAM) in the required state**.

The CPU works with **virtual addresses**, while the actual data may or may not currently be available in RAM.

When the required page is missing, the hardware detects the condition and transfers control to the **operating system**, which determines how to resolve it.

> **A page fault does not necessarily mean an error.** In virtual-memory systems, page faults are a normal mechanism for bringing required pages into RAM.

---

# Basic Idea

Suppose a process has the following pages:

```text id="y5x5wq"
Process Virtual Pages

Page 0 → RAM
Page 1 → RAM
Page 2 → Disk / Backing Store
Page 3 → RAM
```

If the process accesses Page 2:

```text id="2g8r8p"
CPU
 │
 ▼
Virtual Address
 │
 ▼
Page Table
 │
 ▼
Is Page 2 Present?
 │
 ├── YES ──→ Access RAM
 │
 └── NO
       │
       ▼
   Page Fault
       │
       ▼
   OS handles fault
       │
       ▼
  Load/resolve page
       │
       ▼
  Update page table
       │
       ▼
 Resume execution
```

---

# Why Does a Page Fault Occur?

Virtual memory allows a process to have a virtual address space larger than the amount of physical RAM currently assigned to it.

The OS does not necessarily keep every page of every process in RAM at the same time.

For example:

```text id="4y2c3x"
Process needs:

Page 0
Page 1
Page 2
Page 3
Page 4
Page 5

But currently RAM contains:

Page 0
Page 1
Page 3
Page 5
```

If the process accesses:

```text id="a0x0a1"
Page 2
```

the page is not currently present, so the access causes a **page fault**.

The general flow is:

# Steps in Handling a Page Fault

When a page fault occurs, the OS generally follows these steps.

## Step 1: CPU Generates a Virtual Address

The CPU executes an instruction that needs some memory location.

For example:

```text id="i9v9bw"
LOAD R1, [Virtual Address]
```

The address is a **virtual address**.

---

## Step 2: MMU Performs Address Translation

The **MMU (Memory Management Unit)** uses the relevant translation structures, often with help from the **TLB**, to determine the physical location.

Conceptually:

```text id="6gcvzh"
Virtual Address
      │
      ▼
     MMU
      │
      ▼
Translation Information
      │
      ▼
Page Table Entry
```

---

## Step 3: Page Table Indicates Page Is Not Present

The relevant page-table entry contains information indicating that the required page is not currently present in the expected physical memory.

Conceptually:

```text id="b5o5ms"
Page 2
  │
  ▼
Page Table Entry

Present = 0
```

The hardware detects this condition.

---

## Step 4: Hardware Traps into the OS

The processor generates a **page-fault exception/trap**.

Control transfers from the currently running program to the operating system's page-fault handler.

```text id="c1j0as"
User Program
     │
     ▼
Memory Access
     │
     ▼
Page Fault
     │
     ▼
OS Page-Fault Handler
```

The CPU also preserves enough execution state for the OS to handle the exception and later continue the interrupted execution.

---

## Step 5: OS Determines How to Resolve the Fault

The OS determines where the required page should come from.

It may be backed by:

* swap/backing storage,
* a memory-mapped file,
* executable file contents,
* a newly allocated zero-filled page,
* or another mechanism.

A common textbook example is loading the page from secondary storage.

---

## Step 6: Find a Free Frame

If RAM has a suitable free frame:

```text id="1j8c3u"
Free Frame 15
      │
      ▼
Required Page → Frame 15
```

The page can be loaded there.

---

## Step 7: Select a Victim Page if Necessary

If no suitable free frame is available, the OS may select another page to remove.

For example:

```text id="9x1r2f"
RAM

Frame 4 → Page A
Frame 5 → Page B
Frame 6 → Page C  ← Victim
Frame 7 → Page D
```

If Page E is required:

```text id="3s5p5g"
Page E required
      │
      ▼
Choose Page C as victim
      │
      ▼
Remove/evict Page C
      │
      ▼
Load Page E into Frame 6
```

The page-replacement policy determines which page should be selected.

Examples include:

* FIFO
* LRU
* Clock / Second-Chance
* Other OS-specific policies

If the victim page has been modified, the OS may need to write it back to its backing store before reusing the frame.

---

# Step 8: Load the Required Page

The required page is brought into the selected physical frame.

For example:

```text id="a9x8wq"
Before:

Frame 6 → Page C


After:

Frame 6 → Page E
```

---

# Step 9: Update the Page Table

The OS updates the relevant page-table entry.

Before:

```text id="qj0d5y"
Page E → Not Present
```

After:

```text id="s7r4rj"
Page E → Frame 6
Present = 1
```

Other relevant metadata may also be updated.

---

# Step 10: Resume / Restart the Interrupted Instruction

The instruction that caused the page fault is generally **restarted or retried** after the fault has been successfully handled.

For example:

```text id="jv0r9z"
Instruction
    │
    ▼
Memory Access
    │
    ▼
Page Fault
    │
    ▼
OS handles fault
    │
    ▼
Page becomes available
    │
    ▼
Instruction retried
    │
    ▼
Execution continues
```

The program does not normally need to know that this happened.

---

# Complete Example

Suppose a process has:

```text id="3j79l3"
Page 0 → RAM
Page 1 → RAM
Page 2 → Disk
Page 3 → RAM
```

Now the CPU executes:

```text id="7o9bve"
Access Page 2
```

The sequence is:

```text id="g0w9g5"
CPU
 │
 ▼
Requests Page 2
 │
 ▼
Page Table
 │
 ▼
Page 2 = Not Present
 │
 ▼
Page Fault
 │
 ▼
OS Handler
 │

 │

```

The process can continue executing normally.

# Page Fault vs Normal Page Access

A normal memory access might look like:

```text id="l9c5ye"
CPU
 ↓
Virtual Address
 ↓
TLB / Page Table
 ↓
Page Present
 ↓
Physical Address
 ↓
RAM
```

A page fault looks like:

```text id="7d9t1y"
CPU
 ↓
Virtual Address
 ↓
TLB / Page Table
 ↓
Page Not Present
 ↓
Page Fault
 ↓
OS
 ↓
Resolve Page
 ↓
Update Mapping
 ↓
Retry
 ↓
RAM
```

The second path is much more expensive.

---

# Why Are Page Faults Expensive?

The main reason is that **RAM is much faster than secondary storage**.

A normal memory access can often be served directly from memory after address translation.

A page fault that requires storage I/O may involve:

```text id="1stn77"
CPU
 ↓
Page Fault
 ↓
OS
 ↓
Storage I/O
 ↓
Wait
 ↓
Page Loaded
 ↓
Update Mapping
 ↓
Resume
```

Storage access can be dramatically slower than RAM access.

Therefore:

> **A page fault can be much more expensive than a normal memory access.**

The exact cost depends on the hardware, storage device, OS, memory pressure, and whether actual I/O is required.

---

# Important: Not Every Page Fault Requires Disk I/O

This is an important interview nuance.

A page fault means the required memory page is not currently present in the expected physical mapping.

It does **not necessarily mean**:

```text
Page Fault → Read from Disk
```

Every time.

For example, a fault can occur when the OS needs to establish a mapping for:

* a newly allocated zero-filled page,
* a memory-mapped file,
* a shared page,
* or other memory-management cases.

Therefore, a more accurate statement is:

> **A page fault is an exception caused by a missing or otherwise unresolved page mapping; resolving it may or may not require storage I/O.**

---

# Page Fault and Demand Paging

**Demand paging** is a technique where pages are loaded into RAM **when they are actually needed**, rather than loading every page in advance.

For example:

```text id="vqv0f7"
Program has:

Page 0
Page 1
Page 2
Page 3
Page 4
Page 5

Initially RAM contains:

Page 0
Page 1

Program accesses Page 4
        ↓
Page Fault
        ↓
Load Page 4
        ↓
Continue execution
```

This saves RAM because unused pages do not have to be loaded immediately.

---

# Page Fault and Page Replacement

If RAM has no free frame, the OS must potentially replace an existing page.

```text id="1g9m9u"
Required Page
     │
     ▼
No free frame
     │
     ▼
Choose victim page
     │
     ▼
Evict victim
     │
     ▼
Load required page
     │
     ▼
Update page table
```

This is where **page replacement algorithms** become important.

Common examples:

| Algorithm   | Basic Idea                                                                              |
| ----------- | --------------------------------------------------------------------------------------- |
| **FIFO**    | Replace the page that has been in memory the longest                                    |
| **LRU**     | Replace the page that has not been used for the longest time                            |
| **Clock**   | Approximate LRU using reference information                                             |
| **Optimal** | Replace the page whose next use is farthest in the future; mainly theoretical benchmark |

---

# Dirty Pages During Page Replacement

Suppose the OS wants to evict a page:

```text id="zshgpp"
Frame 8 → Page A
```

If Page A has not been modified since it was loaded, it may be possible to discard it without writing its contents back.

But if Page A is **dirty/modified**:

```text id="q9q4cm"
Page A
  ↓
Modified
  ↓
Must preserve changes
  ↓
May need write-back
```

This can make page replacement even more expensive.

---

# Page Fault and TLB

A **TLB miss** and a **page fault** are different events.

### TLB Miss

The required translation is not currently in the TLB.

```text id="zv0l9p"
TLB
 │
 └── Translation not found
        ↓
   Check page table
```

The page may still be completely present in RAM.

### Page Fault

The required page is not currently present/mapped as required.

```text id="6g6v5q"
Page Table
 │
 └── Page not present
        ↓
    Page Fault
```

Therefore:

> **TLB miss ≠ page fault.**

A TLB miss can happen even when there is no page fault.

---

# Page Fault vs Segmentation Fault

These two terms are frequently confused because both involve memory access.

| Page Fault                                              | Segmentation Fault                                                                             |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Required page is not currently present/mapped as needed | Process makes an invalid or prohibited memory access                                           |
| Normally handled by the OS                              | Typically results in an access-violation signal/exception and process termination if unhandled |
| Normal part of virtual memory                           | Usually indicates a programming/access violation                                               |
| Can happen during normal execution                      | Often caused by bugs such as invalid pointers                                                  |
| OS may load or establish the required page              | OS generally cannot legitimately provide the requested access                                  |

### Example of a Page Fault

```text id="s4g3ty"
Program accesses valid virtual page
             ↓
Page is currently not in RAM
             ↓
Page Fault
             ↓
OS loads/resolves page
             ↓
Program continues
```

### Example of a Segmentation Fault

```text id="r7o0m8"
Program accesses invalid memory
             ↓
Access violates protection
             ↓
Memory-access exception
             ↓
Process is typically terminated
```

---

# Why Is It Called a "Page Fault"?

The word **fault** does not necessarily mean that the program contains a bug.

It means that the processor encountered a condition that requires operating-system handling before the requested memory access can proceed.

Therefore:

```text id="7p0j7x"
Page Fault
     ≠
Program Error
```

A page fault can be completely normal in a demand-paged virtual-memory system.

---

# Page Fault vs Segmentation Fault: Important Nuance

The terminology can be confusing because **segmentation fault** has "segmentation" in its name, but on modern systems a segmentation fault generally refers to an **invalid/prohibited memory access**, not simply an access to a classic segmentation-based memory segment.

For example, on Unix-like systems, an invalid memory access may result in **SIGSEGV**.

So:

```text id="v8x6gk"
Page Fault
→ Virtual-memory mechanism
→ May be normal
→ OS resolves it when possible


Segmentation Fault
→ Invalid/prohibited memory access
→ Usually a program bug or illegal access
→ Process normally cannot continue from that access
```

---

# Page Fault and Thrashing

A small number of page faults can be completely normal.

The problem occurs when page faults become excessive.

For example:

```text id="z0n9p8"
Too many active pages
        ↓
RAM pressure
        ↓
Frequent page faults
        ↓
Frequent page replacement
        ↓
More storage I/O
        ↓
Less useful CPU work
        ↓
Thrashing
```

**Thrashing** occurs when the system spends a significant amount of time handling memory paging rather than doing useful application work.

---

# Simple Real-World Analogy

Imagine a student working at a desk.

The student has:

```text id="o0a4p2"
Desk = RAM
Cupboard = Storage
```

The student keeps only the currently needed books on the desk.

Suppose the student needs a book that is in the cupboard:

```text id="w9q5o8"
Need Book
   ↓
Book not on desk
   ↓
Go to cupboard
   ↓
Bring book to desk
   ↓
Continue studying
```

This is similar to a page fault:

```text id="q8x0qm"
Need Page
   ↓
Page not in RAM
   ↓
OS obtains page
   ↓
Page placed in RAM
   ↓
Program continues
```

If the desk is full, the student may first have to remove a book that is currently less useful.

That resembles **page replacement**.

If the student constantly moves books between the desk and cupboard, that resembles **thrashing**.

---

# Advantages of Page Fault Mechanism

Page faults are an essential part of virtual-memory systems because they allow:

### 1. Demand Paging

Pages can be loaded only when needed.

### 2. Better RAM Utilization

Unused pages do not always need to occupy physical memory.

### 3. Large Virtual Address Spaces

Processes can have virtual address spaces that are not fully resident in RAM at the same time.

### 4. Memory Protection

The page-table mechanism can enforce access permissions and process isolation.

---

# Disadvantages

### 1. High Latency

Resolving a fault that requires storage I/O can be very slow compared with RAM access.

### 2. CPU Stall

The thread that caused the fault cannot complete that memory access until the fault is resolved.

### 3. Storage I/O

Frequent faults can generate substantial storage traffic.

### 4. Thrashing

Excessive page faults can severely reduce overall system performance.

---

# Common Interview Mistakes

### ❌ Mistake 1: Page fault means program crashed

Not necessarily.

Page faults are normal in virtual-memory systems.

---

### ❌ Mistake 2: Every page fault reads from disk

Not necessarily.

Some faults can be resolved without ordinary storage I/O.

---

### ❌ Mistake 3: Page fault and segmentation fault are the same

They are not.

```text id="q2f5vv"
Page Fault
→ Missing/unresolved page mapping

Segmentation Fault
→ Invalid/prohibited memory access
```

---

### ❌ Mistake 4: TLB miss means page fault

False.

A TLB miss only means the translation was not found in the TLB.

The page can still be in RAM.

---

### ❌ Mistake 5: Page fault happens only because RAM is full

False.

A page can be absent from RAM even when there are free frames.

For example, demand paging may intentionally leave pages non-resident until they are needed.

---

### ❌ Mistake 6: Page fault is always extremely slow

The expensive case is generally when resolving the fault requires storage I/O.

Some page faults can be resolved without reading from secondary storage.

### Key Terms

| Term                   | Meaning                                                                         |
| ---------------------- | ------------------------------------------------------------------------------- |
| **Page Fault**         | Exception caused when a required page is not currently present/mapped as needed |
| **Demand Paging**      | Loading pages when they are actually needed                                     |
| **Victim Page**        | Page selected for eviction when a frame is needed                               |
| **Page Replacement**   | Process of choosing a page to evict                                             |
| **TLB Miss**           | Translation not found in the TLB                                                |
| **Dirty Page**         | Page modified since it was loaded or last written back                          |
| **Thrashing**          | Excessive paging that severely reduces useful work                              |
| **Segmentation Fault** | Invalid or prohibited memory access                                             |

# Interview Takeaway

> **A page fault happens when a process accesses a virtual-memory page that is not currently present or otherwise not immediately resolvable in physical memory. The hardware transfers control to the OS, which resolves the fault—possibly by obtaining the page, finding or creating a suitable frame, updating the page table, and retrying the interrupted instruction. Page faults are a normal part of virtual memory, but faults requiring storage I/O are expensive, and excessive faults can lead to thrashing.**

### Memory Trick

```text
Page Missing
     ↓
Page Fault
     ↓
OS Handles
     ↓
Find/Load Page
     ↓
Update Mapping
     ↓
Retry
```

**One-line interview answer:**

> **A page fault occurs when a required virtual-memory page is not currently present or resolvable in RAM, causing the OS to handle the exception and make the page available before execution continues.**
