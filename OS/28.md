28.What is a page fault?
A page fault occurs when a process tries to access a virtual memory page that is not currently present in physical RAM.

It does not necessarily mean an error. In virtual memory systems, page faults are a normal mechanism for bringing required pages into RAM.

How it works

Suppose a process accesses a page:

CPU
 ↓
Virtual Address
 ↓
Page Table
 ↓
Is page in RAM?
 ├── Yes → Access RAM
 └── No  → Page Fault
              ↓
        OS handles fault
              ↓
      Load page from disk
              ↓
        Update page table
              ↓
        Resume execution
Steps in a page fault
CPU generates a virtual address.
The MMU checks the page table.
The page-table entry indicates that the page is not present in RAM.
Hardware traps into the OS.
The OS locates the required page in secondary storage.
It finds a free frame or selects a victim page for replacement.
The required page is loaded into RAM.
The page table is updated.
The interrupted instruction is restarted.
Example

Suppose a process has pages:

Page 0 → RAM
Page 1 → RAM
Page 2 → Disk
Page 3 → RAM

If the process accesses Page 2, a page fault occurs because Page 2 isn't currently in RAM. The OS loads Page 2 into a suitable frame.

Why are page faults expensive?

RAM access is much faster than storage access. Therefore, handling a page fault can be significantly slower than a normal memory access.

If page faults happen excessively, the system may experience thrashing, where the OS spends much of its time moving pages between RAM and storage instead of executing useful work.

Page fault vs segmentation fault
Page Fault	Segmentation Fault
Page is not currently in RAM	Process makes an invalid/prohibited memory access
Usually handled by the OS	Usually results in process termination
Normal part of virtual memory	Typically indicates a programming/access violation
Can happen during normal execution	Often caused by bugs such as invalid pointers

Interview takeaway:

A page fault happens when a required virtual-memory page is not present in RAM. The OS handles it by loading the page into memory and updating the page table.
