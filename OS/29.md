# Q29. What is Page Replacement?

**Page replacement** is the process of selecting a page currently present in **physical memory (RAM)** to remove when a **page fault occurs** and there is **no free frame** available for the required page.

The OS replaces an existing page with the required page so that execution can continue.

The page selected for removal is called the **victim page**.

---

# Why is Page Replacement Needed?

Physical RAM is limited.

Suppose all available frames are already occupied:

```text id="x2n4q7"
Physical Memory

Frame 1 → Page 2
Frame 2 → Page 5
Frame 3 → Page 7
```

Now the process requests:

```text id="p9f4o2"
Page 3
```

But there is no free frame.

Therefore:

```text id="4x1m4u"
Page 3 is required
       ↓
Page Fault
       ↓
No free frame
       ↓
Choose a victim page
       ↓
Remove victim
       ↓
Load Page 3
```

This decision is the job of a **page replacement algorithm**.

---

# How Page Replacement Works

The overall process is:

```text id="x0v2r9"
              Page Fault
                  │
                  ▼
          Is there a free frame?
             /           \
           YES            NO
            │              │
            ▼              ▼
     Load required     Select victim
         page              page
            │              │
            │       Is victim modified?
            │          /          \
            │        YES           NO
            │         │             │
            │         ▼             │
            │    Write victim       │
            │    back if needed     │
            │         │             │
            └─────────┴─────────────┘
                      │
                      ▼
             Load required page
                      │
                      ▼
              Update page table
                      │
                      ▼
              Resume execution
```

---

# Step-by-Step Explanation

## Step 1: Page Fault Occurs

The CPU requests a page that is not currently present in RAM.

```text id="6n5z5j"
CPU
 ↓
Virtual Address
 ↓
Page Table
 ↓
Page Not Present
 ↓
Page Fault
```

A page fault itself does not necessarily mean there is a problem with the program.

---

## Step 2: Check for a Free Frame

The OS checks whether there is an unused physical frame.

### If a free frame exists

There is no need for replacement.

```text id="2q3r0k"
Page Fault
    ↓
Free Frame Available
    ↓
Load Required Page
    ↓
Update Page Table
    ↓
Resume
```

### If no free frame exists

The OS must select a page to remove.

```text id="w0j9f6"
Page Fault
    ↓
No Free Frame
    ↓
Page Replacement Required
```

---

# Step 3: Select a Victim Page

The OS uses a **page replacement algorithm** to decide which page should be removed.

For example:

```text id="4w2r8h"
Frame 1 → Page 2
Frame 2 → Page 5
Frame 3 → Page 7

Required → Page 3
```

Suppose the replacement algorithm selects Page 5.

```text id="u7j6j7"
Page 5 → Victim Page
```

---

# Step 4: Check Whether the Victim Page Is Modified

The OS may maintain a **dirty/modified bit** for pages.

If the victim page has been modified since it was loaded:

```text id="2j5h4k"
Victim Page
     ↓
Modified?
     ↓
YES
     ↓
Write updated contents
to backing storage
```

If it has not been modified, the OS may be able to discard it without writing its contents back.

### Why?

Suppose:

```text id="c3r8v2"
Page 5 loaded from storage
        ↓
Process never changed Page 5
        ↓
RAM copy = backing-store copy
```

There is no new data that needs to be preserved.

But:

```text id="v5j2p1"
Page 5 loaded
        ↓
Process modifies Page 5
        ↓
RAM copy differs from backing copy
        ↓
Must preserve modified data
```

This can make replacement more expensive.

---

# Step 5: Load the Required Page

After the victim frame is available:

```text id="8v8j6f"
Before:

Frame 2 → Page 5
```

After eviction:

```text id="5z8j4g"
Frame 2 → Available
```

Then the required page is loaded:

```text id="9c4m6r"
Frame 2 → Page 3
```

---

# Step 6: Update the Page Table

The OS updates the page-table entries.

Before:

```text id="3x1v7g"
Page 5 → Frame 2
Page 3 → Not Present
```

After:

```text id="8n4v6t"
Page 5 → Not Present
Page 3 → Frame 2
```

The relevant presence/valid and other metadata are also updated.

---

# Step 7: Resume Execution

The instruction that caused the page fault can now be retried.

```text id="5c7y4v"
Page Fault
    ↓
Replacement
    ↓
Page Loaded
    ↓
Page Table Updated
    ↓
Instruction Retried
    ↓
Execution Continues
```

---

# Complete Example

Suppose RAM has **3 frames**:

```text id="d2q0k9"
Frame 1 → Page 2
Frame 2 → Page 5
Frame 3 → Page 7
```

Now the process requests:

```text id="f8g3x7"
Page 3
```

All frames are occupied.

Suppose the selected victim is Page 5.

### Before

```text id="a4d6m8"
Frame 1 → Page 2
Frame 2 → Page 5  ← Victim
Frame 3 → Page 7
```

The OS removes Page 5.

### After replacement

```text id="m6s2r9"
Frame 1 → Page 2
Frame 2 → Page 3  ← Required Page
Frame 3 → Page 7
```

The page chosen for removal is called the **victim page**.

---

# Why Does the Choice of Victim Matter?

Suppose the system has:

```text id="f3n8q1"
Page 2 → frequently used
Page 5 → rarely used
Page 7 → frequently used
```

If the OS removes Page 2:

```text id="3x6w5d"
Page 2 removed
     ↓
Program needs Page 2 again
     ↓
Another page fault
```

The system may have to perform another replacement soon.

But if the OS removes a page that is unlikely to be needed soon:

```text id="m2p7v5"
Rarely used page
      ↓
Replace it
      ↓
More useful pages remain in RAM
```

Therefore, a good replacement algorithm attempts to keep useful pages in memory and reduce future page faults.

---

# Common Page Replacement Algorithms

Several algorithms can be used to choose the victim page.

| Algorithm                 | Basic Idea                                                                |
| ------------------------- | ------------------------------------------------------------------------- |
| **FIFO**                  | Replace the page that has been in memory the longest                      |
| **Optimal**               | Replace the page that will not be used for the longest time in the future |
| **LRU**                   | Replace the page that has not been used for the longest time              |
| **Clock / Second Chance** | Give recently referenced pages another chance before replacement          |

---

# 1. FIFO Page Replacement

**FIFO (First-In, First-Out)** replaces the page that has been in memory for the longest time.

Think of it as a queue:

```text id="0f8w3k"
Oldest                         Newest
  ↓                               ↓
Page 2 → Page 5 → Page 7 → Page 9
  ↑
Victim
```

Page 2 is removed first because it entered memory first.

### Advantages

* Simple to understand.
* Easy to implement.
* Low bookkeeping overhead.

### Disadvantage

FIFO does not consider how frequently or recently a page is being used.

A very frequently used page could still be removed simply because it is old.

---

# FIFO Example

Suppose there are 3 frames:

```text id="q9s4x6"
Reference String:

1, 2, 3, 4
```

Initially:

```text id="e8f3j0"
1 → Frame 1
2 → Frame 2
3 → Frame 3
```

Now Page 4 is required.

FIFO chooses the oldest page:

```text id="8f5w2a"
Remove Page 1

Frame 1 → Page 4
Frame 2 → Page 2
Frame 3 → Page 3
```

---

# Belady's Anomaly

An interesting property of FIFO is **Belady's anomaly**.

In some reference patterns, increasing the number of available frames can unexpectedly result in **more page faults** under FIFO.

Conceptually:

```text id="r8c2k6"
More Frames
     ↓
Expected: fewer page faults
     ↓
FIFO
     ↓
Certain reference patterns
     ↓
Can produce MORE page faults
```

This is one reason FIFO is not generally considered an ideal replacement strategy.

---

# 2. Optimal Page Replacement

The **Optimal page replacement algorithm** replaces the page that will **not be used for the longest time in the future**.

For example:

```text id="m7c2v9"
Current pages:

Page 1
Page 2
Page 3

Future accesses:

Page 1 → soon
Page 3 → later
Page 2 → far in future
```

The optimal algorithm would choose:

```text id="s2f7k5"
Page 2
```

because it will be needed farthest in the future.

---

## Why Is Optimal Mostly Theoretical?

The OS cannot generally know exactly which page the program will access in the future.

Therefore:

> **Optimal replacement is mainly used as a theoretical benchmark for comparing practical algorithms.**

It tells us the minimum possible number of page faults for a given reference string and number of frames.

---

# 3. LRU Page Replacement

**LRU (Least Recently Used)** replaces the page that has not been used for the longest time.

The idea is:

> A page that has not been used recently may be less likely to be needed immediately than pages that were just accessed.

Example:

```text id="6f7r2x"
Recent usage:

Page 2 → used 1 step ago
Page 5 → used 3 steps ago
Page 7 → used 10 steps ago
```

LRU chooses:

```text id="v6j8c4"
Page 7
```

because it was used least recently.

---

# LRU Example

Suppose:

```text id="8p3d1m"
Frames = 3

Current pages:

Page 1
Page 2
Page 3
```

Suppose the recent access history is:

```text id="y1x8k5"
Page 1 → recently used
Page 2 → used earlier
Page 3 → least recently used
```

If Page 4 is required:

```text id="2z4q7r"
Page 3 → Victim

Page 1
Page 2
Page 4
```

LRU attempts to use recent access history to make a better replacement decision.

---

# 4. Clock / Second-Chance Algorithm

The **Clock** algorithm is a practical approximation of LRU.

Instead of maintaining exact usage order, pages are given a **reference/use bit**.

Conceptually:

```text id="8d6p4z"
             Page 1
               ↓
          ┌─────────┐
          │         │
     Page 4 ←       → Page 2
          │         │
          └── Page 3
```

The algorithm moves around the pages like a clock hand.

If a page has recently been referenced:

```text id="0r7f6q"
Reference Bit = 1
```

the algorithm may give it another chance:

```text id="p4x1w8"
Reference Bit = 1
       ↓
Set bit to 0
       ↓
Move to next page
```

If a page has not been referenced:

```text id="j6m2c5"
Reference Bit = 0
       ↓
Candidate for replacement
```

This can approximate the behavior of LRU with less bookkeeping than maintaining exact recency ordering.

---

# Comparison of Replacement Algorithms

| Algorithm   | Victim Selection       | Main Advantage              | Main Disadvantage                     |
| ----------- | ---------------------- | --------------------------- | ------------------------------------- |
| **FIFO**    | Oldest page            | Very simple                 | May remove frequently used pages      |
| **Optimal** | Farthest future use    | Minimum theoretical faults  | Future is unknown                     |
| **LRU**     | Least recently used    | Good practical principle    | Exact implementation can be expensive |
| **Clock**   | Based on reference bit | Efficient LRU approximation | Not exact LRU                         |

---

# Page Replacement and Page Faults

These two concepts are closely related but are **not the same**.

### Page Fault

A page fault occurs when:

```text id="b6v8y4"
Required Page
      ↓
Not currently present
      ↓
Page Fault
```

### Page Replacement

Page replacement is needed when:

```text id="a5h7k2"
Page Fault
     ↓
No free frame
     ↓
Choose existing page
     ↓
Remove victim
     ↓
Load required page
```

Therefore:

> **A page fault does not always require page replacement.**

If a free frame exists:

```text id="f4q8x2"
Page Fault
    ↓
Free Frame Available
    ↓
Load Page
```

No existing page needs to be removed.

Page replacement is required only when there is **no suitable free frame** and an existing resident page must be evicted.

---

# Page Fault vs Page Replacement

| Page Fault                                               | Page Replacement                                                     |
| -------------------------------------------------------- | -------------------------------------------------------------------- |
| Required page is not currently present/resolvable in RAM | Existing page is selected for removal                                |
| Triggered by a memory access                             | Usually occurs while handling a page fault when no free frame exists |
| OS must resolve the missing page                         | OS chooses a victim page                                             |
| May occur when a free frame exists                       | Requires lack of a suitable free frame                               |
| May not require eviction                                 | Involves eviction of a resident page                                 |

### Simple Relationship

```text id="c4y7x2"
Page Fault
    │
    ▼
Free Frame?
 ┌──┴───┐
 │      │
YES     NO
 │      │
 ▼      ▼
Load   Page Replacement
Page        │
            ▼
       Choose Victim
            │
            ▼
       Load Required Page
```

---

# Page Replacement and Dirty Pages

A useful interview concept is the **dirty bit**.

Suppose:

```text id="j5s8p1"
Page A
  ↓
Modified by process
  ↓
Dirty = 1
```

If Page A becomes the victim:

```text id="k3d7q9"
Victim Page
     ↓
Dirty = 1
     ↓
Write back if required
     ↓
Reuse frame
```

But if:

```text id="n4m6z8"
Dirty = 0
```

the page may be discarded without writing its unchanged contents back, depending on how it is backed.

This is important because writing a dirty page to storage adds additional I/O cost.

---

# Page Replacement and Performance

A major goal of page replacement is to reduce the number of expensive page faults.

A simplified relationship is:

```text id="y7x4c3"
Better Replacement
       ↓
Fewer Page Faults
       ↓
Less Storage I/O
       ↓
Better Performance
```

However, minimizing page faults is not the only consideration.

A real system also cares about:

* CPU overhead,
* memory usage,
* fairness,
* working-set behavior,
* I/O cost,
* cache/TLB behavior,
* and overall system responsiveness.

---

# Local vs Global Page Replacement

In systems with multiple processes, replacement can also be discussed in terms of **local** and **global** policies.

### Local Replacement

A process chooses a victim only from its own allocated frames.

```text id="x4q2j8"
Process A
Frames: A1 A2 A3
             ↓
Victim must come from A's frames
```

This provides stronger isolation of one process's frame allocation.

### Global Replacement

A process may potentially select a victim from frames belonging to other processes, subject to the OS's memory-management policy.

```text id="z7m5p1"
Process A ─┐
Process B ─┼──→ System-wide frame pool
Process C ─┘
```

This can allow more flexible memory allocation but can also make one process's memory demand affect another.

Actual policies vary significantly between operating systems.

---

# Working Set and Page Replacement

A process often has a set of pages it is actively using at a given time.

This is related to its **working set**.

For example:

```text id="c6v9k4"
Process has 100 pages

Currently active:

Page 2
Page 5
Page 7
Page 9
Page 12
```

If these frequently used pages fit in RAM:

```text id="s5j3h8"
Working Set fits in RAM
       ↓
Fewer page faults
       ↓
Better performance
```

If the working set does not fit:

```text id="h4k8z2"
Working Set > Available RAM
       ↓
Frequent page faults
       ↓
Page replacement
       ↓
Possible thrashing
```

Therefore, effective page replacement works together with broader memory-management policies.

---

# Real-World Analogy

Imagine a small desk with only three spaces:

```text id="e5r8m2"
Desk:

[Book A] [Book B] [Book C]
```

You suddenly need Book D.

There is no free space.

You must decide which book to remove:

```text id="j8c4v6"
Book A → rarely used
Book B → currently being used
Book C → recently used

Need Book D

Remove Book A
```

This is similar to page replacement.

```text id="9v2x7p"
Desk       → RAM
Book       → Page
Desk slot  → Frame
Needed book → Required page
Removed book → Victim page
```

A good strategy tries to remove a page that is unlikely to be needed soon.

# Common Interview Mistakes

### ❌ Mistake 1: Every page fault causes page replacement

False.

If a free frame exists:

```text id="3m8q6w"
Page Fault
    ↓
Free Frame
    ↓
Load Page
```

No replacement is required.

---

### ❌ Mistake 2: Page replacement means replacing a virtual page permanently

Not exactly.

The OS usually replaces the **physical frame contents** by evicting one resident page and loading another.

The evicted page may later be brought back if needed.

---

### ❌ Mistake 3: Optimal is used directly by normal OS scheduling

Not generally.

Optimal replacement requires knowledge of future references, which the OS does not have exactly.

It is mainly a theoretical benchmark.

---

### ❌ Mistake 4: LRU means least frequently used

False.

LRU means:

> **Least Recently Used**

It considers **recency**, not total frequency.

LFU, Least Frequently Used, is a different policy.

---

### ❌ Mistake 5: FIFO always gives fewer faults with more frames

False.

FIFO can suffer from **Belady's anomaly**, where increasing the number of frames can sometimes increase page faults.

---

### ❌ Mistake 6: Victim page is always written to disk

Not necessarily.

If the victim is clean and its backing copy is already up to date, it may be discarded without a write-back.

### Key Terms

| Term                 | Meaning                                                             |
| -------------------- | ------------------------------------------------------------------- |
| **Page Replacement** | Selecting a resident page to remove when no free frame is available |
| **Victim Page**      | Page selected for eviction                                          |
| **Page Fault**       | Required page is not currently present/resolvable in RAM            |
| **Free Frame**       | Physical frame available for a new page                             |
| **Dirty Page**       | Page modified since its backing copy was last synchronized          |
| **FIFO**             | Replace oldest resident page                                        |
| **Optimal**          | Replace page whose next use is farthest in the future               |
| **LRU**              | Replace least recently used page                                    |
| **Clock**            | Practical approximation using reference information                 |
| **Thrashing**        | Excessive paging that severely reduces useful work                  |

---

# Interview Takeaway

> **Page replacement is the mechanism used by the OS to select and remove a page from physical memory when a page fault occurs and no suitable free frame is available. The OS selects a victim page using a replacement policy such as FIFO, Optimal, LRU, or Clock, writes it back if necessary, loads the required page into the freed frame, updates the page table, and resumes execution.**

### Memory Trick

```text id="5q8v3n"
PAGE FAULT
    ↓
NO FREE FRAME
    ↓
SELECT VICTIM
    ↓
EVICT
    ↓
LOAD REQUIRED PAGE
    ↓
UPDATE TABLE
    ↓
RESUME
```

**One-line interview answer:**

> **Page replacement is the process of choosing a victim page to evict from RAM so that a required page can be loaded when a page fault occurs and no free frame is available.**
