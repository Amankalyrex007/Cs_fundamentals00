30.What is thrashing?
Thrashing is a condition in a virtual-memory system where the OS spends most of its time handling page faults and swapping pages between RAM and disk, leaving very little time for actual process execution.

Why does thrashing happen?

The main reason is that processes require more memory than the available physical RAM can effectively hold.

For example:

Too many active processes
        ↓
Not enough RAM for their working sets
        ↓
Frequent page faults
        ↓
Pages constantly replaced
        ↓
More disk I/O
        ↓
CPU spends less time doing useful work
        ↓
Performance collapses
Example

Suppose RAM can effectively hold the frequently used pages of only 3 processes, but 8 processes are actively competing for memory.

The OS may repeatedly:

Load Page A → remove Page B
Need Page B → remove Page C
Need Page C → remove Page A
Need Page A → ...

This causes a very high page-fault rate and excessive disk I/O.

Symptoms of thrashing
Very high page-fault rate
Heavy disk/SSD activity
Low useful CPU utilization
Applications become extremely slow
System may appear almost frozen
How can thrashing be reduced?
Reduce the number of simultaneously active processes.
Give processes enough frames to hold their working sets.
Use effective page-replacement strategies.
Increase physical RAM when memory capacity is genuinely insufficient.
Monitor page-fault rate and memory pressure.
Important distinction

Page fault is an individual event where a required page isn't in RAM.
Thrashing is a system-level condition where page faults occur so frequently that most system time is spent managing memory rather than executing useful work.

Interview Takeaway

Thrashing occurs when excessive paging/page faults cause the system to spend most of its time moving pages between RAM and secondary storage, resulting in severe performance degradation.
