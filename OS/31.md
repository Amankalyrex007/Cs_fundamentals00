31.Stack vs heap memory?
Stack and heap are two different memory areas used by a program during execution, but they serve different purposes.

Aspect	Stack	Heap
Main use	Function calls, local variables, call frames	Dynamically allocated objects/data
Allocation	Usually automatic	Usually dynamic
Deallocation	Automatically when scope/function ends	Depends on language/runtime
Access	Typically fast	Typically more overhead
Size	Usually more limited	Typically larger
Organization	LIFO-like	Dynamic allocation
Common issue	Stack overflow	Memory leak / fragmentation
1. Stack memory

The stack stores information associated with active function calls, such as:

Local variables
Function parameters
Return addresses
Call-frame information

Example:

def calculate():
    x = 10
    y = 20
    return x + y

The function's execution state is associated with a stack frame. When the function returns, that frame can be removed automatically.

Deep or infinite recursion can exhaust stack space:

Stack
┌──────────────┐
│ calculate()  │
├──────────────┤
│ calculate()  │
├──────────────┤
│ calculate()  │
├──────────────┤
│ ...          │
└──────────────┘
       ↓
Stack overflow
2. Heap memory

The heap is used for dynamically allocated data whose lifetime isn't tied simply to one function call.

For example, creating a large object or dynamically sized data structure may involve heap allocation.

In garbage-collected languages such as Java, Python, and C#, objects are generally allocated in managed heap memory and later reclaimed by the garbage collector when no longer reachable.

In C/C++, dynamically allocated memory is typically managed explicitly:

int* p = new int(10);

// use p

delete p;

Failing to release dynamically allocated memory when required can cause a memory leak.

Simple intuition

Think of:

Stack → Temporary workspace for active function calls

Heap  → Dynamic storage for objects/data whose lifetime
        is managed separately from the current call
Important interview nuance

The exact stack/heap behavior is language- and runtime-dependent. For example, saying “all local variables are always on the stack” is too simplistic. Compilers and runtimes can optimize how values are stored.

Interview Takeaway

Stack memory primarily manages function-call execution and local state, while heap memory supports dynamic allocation and longer-lived data. Stack allocation/deallocation is generally automatic, whereas heap lifetime depends on the language's memory-management model.
